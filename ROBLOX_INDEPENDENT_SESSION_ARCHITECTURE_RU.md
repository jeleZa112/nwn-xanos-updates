# ROBLOX_BG_AI — независимый игровой сеанс, 09.11.2026

## Установленный факт
V3.6.9 (реальный пользовательский лог): PostMessage WM_KEYDOWN W вызывался три раза без изменения сцены (SPAWN_MOTION NO_MOTION 0.0, 379/423/339 features), остановка. Таким образом, фоновые WM-сообщения НЕ пригодны для управления данным Roblox-клиентом. Нельзя объявлять их «рабочим фоновым вводом» и продолжать бессмысленные подборы таймеров.

## Целевая архитектура
Фоновая автономность достигается не отправкой синтетических событий в неактивное окно, а запуском Roblox в **отдельном полноценном интерактивном игровом сеансе**. Контроллер игры работает ВНУТРИ этого сеанса, где Roblox остаётся активным окном; основной пользовательский компьютер/сеанс не получает чужих клавиш и кликов.

Вариант А, предпочтителен при наличии второго компьютера Windows: официальный Roblox + наш `ROBLOX_UPDATE.cmd` / `roblox_monitor.py` на отдельном ПК с действующим игровым GUI. Сеанс предназначен только для игры. Все input-вызовы остаются локальными на том ПК. Диагностические логи/статус передаются через обычный согласованный файловый канал, не пересылая аккаунт-пароли.

Вариант B, условный: GPU-passthrough виртуальная машина с выделенным физическим GPU, когда оборудование и официальная совместимость это позволяют. Поддержка GPU passthrough обязательна согласно Roblox Anti-cheat Messages, обычная VirtualBox/Hyper-V VM без passthrough не считается пригодной. **Нельзя обходить античит, подменять сведения VM, менять Roblox-клиент или отключать защиту.**

Вариант C: исходный Windows foreground режим без оборудования; это НЕ фоновая игра при использовании других окон. Отдельно сохранить как рабочее по механизму ввода, но весь цикл ещё не проверен.

## Состояние кода V3.7.0
`ROBLOX_BG_INPUT=0` (по умолчанию) — проверенный тип Windows SendInput, требует активный Roblox и останавливает действия при переключении. `ROBLOX_BG_INPUT=1` — экспериментальный прошлый PostMessage с предупреждением о реальном провале, **не рекомендуется**. Изменение лишь предотвращает запуск заведомо нерабочего бэкенда по умолчанию, НЕ подтверждает готовый автопилот.

## Интеграционные задачи без очередных микротестов пользователя
1. В отдельном сеансе использовать тот же main controller, WGC capture и локальные input-команды, без изменения Roblox.
2. Выделить файловый статус `CURRENT/STATUS.json` с версией, фазой LOBBY/MENU/MATCH/RETURN, последним визуальным доказательством, ошибкой, временем и alive/stop. Не писать персональные данные и картинки игроков в публичный GitHub.
3. Встроить ограниченный health-check и автоматический fail-closed при потере настоящего game HWND, 3 NO_MOTION, отсутствии стабильного READY; F10.
4. Проверять весь цикл, а не запускать отдельный тест после каждого небольшого исправления.
5. Если нет отдельного ПК или GPU-passthrough, не обещать независимую работу «в фоне» на одном рабочем столе.

## Пользовательские требования
- Без OBS-видео, бесконечных 40-секундных ожиданий и микротестов.
- Один обновлятор, один скрипт/файл логов в эксплуатации.
- Автоматическая карта City Landscape, 1, Hard, создание, угол, турели, повтор только после реального подтверждения каждого этапа.
- Управление фоново, при возможности использовать основной ПК для другой работы.
- Не объявлять виртуальную машину гарантированно совместимой: официальный Roblox требует GPU passthrough: https://en.help.roblox.com/hc/en-us/articles/24275616578708-Anti-cheat-Messages

## Не подтверждено
Фактическая доступность отдельного ПК, passthrough GPU, работа Roblox в VM и полный игровой цикл. Никакая из этих возможностей не должна объявляться выполненной заранее.
