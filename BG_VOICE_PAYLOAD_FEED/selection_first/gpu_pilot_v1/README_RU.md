# BG Voice RU — независимая GPU-проверка голоса Stable / Per_line

**Версия:** `BGVOICE_WAVLM_SELECTION_FIRST_PILOT_V1`  (23.11.2026)

Это **один автономный отборщик**, не обновлятор игры и не замена `BG_VOICE_UPDATE.cmd`.
Ничего не изменяет в Baldur's Gate EET, BGXAI, BG_EET_RU, главном обновляторе и 14 412 исходных русских WAV.
**Никаких исправлений ударений, новых TTS, перегенерации или установки в игру.**

## Один запуск

1. Распаковать ZIP полностью в любую отдельную папку.
2. Дважды открыть **`BG_VOICE_GPU_SELECT.cmd`**.
3. Не требуется выбирать 7 206 записей вручную. Программа проверит, есть ли доступный Python с CUDA, затем сама продолжит работу.
4. Итоговый файл для анализа: `%USERPROFILE%\Documents\BG_VOICE_RU\VOICE_SELECTION_GPU\BG_VOICE_GPU_SELECTION_REPORT.zip`. При ошибке запуска также смотреть `BOOTSTRAP_STATUS.json`.

## Что принципиально меняется

Старый автоматический отборщик фактически выбирал Per_line во всех **20** ранее оценённых пользователем случаях, то есть совпадение **13/20** было равно константному правилу «всегда Per_line». Переписывать вес ECAPA бесполезно.

Здесь используется **новая независимая модель WavLM-Base-Plus-SV Microsoft** — заранее обученная сеть векторного сравнения голосов (XVector), а не тот же ECAPA с другим коэффициентом. Она получает 16-кГц звуковые данные и сравнивает RU Stable и Per_line с 3–5 английскими образцами **того же персонажа**. До массового анализа выполняется ретроспективная калибровка на прежних пользовательских выборах: 7 Stable + 13 Per_line. Эти решения не заменяются и не используются для обучения модели.

**Автоматический барьер (важно):** массовое сравнение запускается **только если** не менее 12 из 20 человекоразмеченных примеров поддаются оценке, включая не менее 4 Stable и 6 Per_line; далее требуются отзыв Stable >=60%, Per_line >=70%, balanced accuracy >=70%. Если этот тест не пройден или нет английских источников — результат `HOLD_CALIBRATION`, тысячи GPU-проходов не запускаются. Проверка маленькая и не доказывает качество для всей библиотеки; даже после PASS результаты остаются только предложениями.

Источники: полный реестр V55/V70/R2 (7206 строк, 14412 старых SHA), **реальный Windows SHA-отчёт от 23 ноября**, 58 его исторических защит, 20 старых человеческих предпочтений. **Повторной начальной проверки всех 14412 WAV нет**: SHA сверяется при новом фактическом чтении выбранного файла моделью, затем результат кешируется по файлу/модели/размеру/времени.

## Где английские образцы

Используется **без изменений** прежний `V58_EN_RECOVERY.py` (V58.2), а не новый угадывающий поиск голосов. Он сперва читает точные EN-файлы из уже существующих кэшей. При нехватке пробует получить WAV по точному Sound ID из ресурсов EET через существующий WeiDU, **только чтение** игры. Все декодированные EN-файлы сохраняются в собственной папке отчёта. Если исходный EN не найден, один ID не заменяется чужим по аналогии. Требуется не менее **трёх** пригодных английских образцов персонажа; в противном случае HOLD. Даже найденные по имени EN остаются `LANGUAGE_AND_SPEAKER_UNVERIFIED`: без человеческой проверки это предварительные, а не сертифицированные опоры.

## Про CPU и GPU

- **GPU** (при доступности CUDA, рекомендуемая RTX 4060): WavLM XVector для сравнения реальных звуков; модель ~405 МБ, при первом запуске может быть скачана из Hugging Face.
- **CPU:** WAV-декодирование, ресемплинг 48/44,1→16 кГц, SHA256, организация кеша, формирование отчётов.
- В Python окружениях проекта ищется **уже установленный GPU Torch**. Если отсутствуют библиотеки WavLM/Transformers, необходимые небольшие Python-компоненты устанавливаются в **отдельную приватную папку отчётов**, не изменяя основной venv. Глобальную установку или переустановку CUDA/Torch программа не делает. Если GPU Torch нет — HOLD, а не многочасовой скрытый CPU-проход.
- Новые нейромодели *эмоций/актёрского мастерства* пока не проходят. Этот этап проверяет **узнаваемость/принадлежность голоса**, не художественную выразительность. Предыдущие V9/SER на данных проекта имели смещение; им нельзя назначать победителя по названию эмоции.

## Файлы результата

- `PILOT_HUMAN_20_WAVLM.csv`: **оба класса отдельно** (7 Stable / 13 Per_line), разница модели и причины HOLD.
- `WAVLM_PROPOSALS_READONLY.csv`: до 7206 новых предложений при успешной калибровке. **Все 58 исторических решений защищены и явно сохранены в полях `human_lock` / `protected_human_choice`.**
- `EN_REFERENCE_ISSUES.json`, `RUN_STATUS.json`, один `BG_VOICE_GPU_SELECTION_REPORT.zip`.
- `SHA_BOUND_WAVLM_CACHE.sqlite`: кеш нейросетевых embedding, продолжение после прерывания.
- `BOOTSTRAP_STATUS.json`: поиск Torch/CUDA, проблемы зависимостей; при первом запуске для WavLM нужен интернет, после загрузки модель кешируется.

Ошибка одного WAV не останавливает другие; повреждённый SHA → HOLD. Исходники открываются только на чтение. Программа не заменяет чей-либо ручной выбор машинным.

## Статус проверки

- Подготовлен настоящий код вызова WavLM через официальные `WavLMForXVector` и `Wav2Vec2FeatureExtractor`, модель закреплена по ревизии HF (`feb593a6c23c1cc3d9510425c29b0a14d2b07b1e`).
- READ-ONLY реестр 7206, 14412 ожидаемых SHA, 58 защищённых записей: PASS.
- Все ветки выбора на **синтетических** WAV, cache/resume, SHA mismatch/corruption, полный 7206-проход с HOLD, ZIP CRC: PASS.
- Отрицательный тест на машине без CUDA: корректный `HOLD_NO_CUDA`, без запуска синтеза и GPU-прогона.
- **Реального WavLM inference на Windows + RTX 4060 пока не было, и новую точность на 20 реальных оценках мы не утверждаем**. Качество следующего этапа определяется только после получения настоящего отчёта.

Изменять что-либо в игре этим пакетом **невозможно**: он не содержит игровой установки/WeiDU-модификаций.
