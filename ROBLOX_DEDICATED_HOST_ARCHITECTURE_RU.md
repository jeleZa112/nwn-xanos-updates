# Roblox: изолированный игровой компьютер — 09.11.2026

## Результат исследований

Последний живой лог V3.6.9: три `SPAWN_APPROACH W`, три `SPAWN_MOTION NO_MOTION shift=0`; `SPAWN_NO_BACKGROUND_MOTION_AFTER_3_KEYS`. Ветка PostMessage на этой игровой конфигурации не приводит к движению. Не повторять эксперименты с прежним `ROBLOX_BG_INPUT=1` под видом нового исправления.

Win32 `SendInput` отправляет события в общий поток пользовательского ввода, а не в конкретное неактивное окно. Два монитора или виртуальные рабочие столы Windows не изолируют ввод. Обычная виртуальная машина Windows/облачный компьютер для игры не считается поддерживаемой Roblox; Roblox отдельно упоминает GPU passthrough, но не обещает, что любая конкретная ВМ заработает.

## Выбранная схема

На **отдельном физическом Windows-компьютере** запускаются Roblox Player, `roblox_monitor.py`, Windows Graphics Capture и проверенный foreground backend. На основном рабочем ПК остаются браузер/ChatGPT/другие приложения. У каждого компьютера собственный активный рабочий стол и аппаратный ввод. Можно наблюдать через обычный удалённый просмотр, но запуск с RDP/заблокированной сессией может прервать игровой ввод; не считать RDP гарантированным решением.

## Файлы и запуск

- `ROBLOX_DEDICATED_HOST.cmd --dedicated-host` (положить рядом с `ROBLOX_UPDATE.cmd`) — безопасный отдельный запуск: задаёт `ROBLOX_BG_INPUT=0`, запускает прежний обновлятор; режим `15`, затем явный `YES`.
- Не меняет исходный пользовательский `ROBLOX_UPDATE.cmd`, не создаёт новый автоматический цикл поверх неизвестного клиента.
- `F10` остановит бот, когда Roblox активно на игровом ПК; журналы остаются в `Documents\RobloxBGDiagnostics\AUTOPILOT`.
- Никакой установки драйверов, виртуализации, выключения античита или обхода защит Roblox.

## Что подтверждено и что нет

- Доказано живым логом: PostMessage не вызвал движения; независимо от WGC-картинка оставалась неподвижной.
- Проверено по GitHub: проект на версии V3.7.0 отключил прежний PostMessage по умолчанию; стартовый файл выделенного игрового ПК явно использует foreground.
- НЕ подтверждено: полный цикл City/1/Hard -> match -> safe corner -> turrets -> return. Также нет подтверждения работы Roblox на виртуальной машине.
- **Один физический ПК:** независимая фоновая игра и одновременная работа в других окнах не обеспечиваются текущими Windows/Roblox механизмами. Это ограничение архитектуры, а не задержки кода.
- **Без второго физического ПК** возможен только foreground режим на текущем ПК с остановкой ввода при смене фокуса. Не утверждать обратного.
