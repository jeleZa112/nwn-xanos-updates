# BG Voice RU — R3: совместимый слой отчётов + безопасная диагностика Windows

**Дата:** 2026-11-23. **Статус:** `SOURCE_ONLY / LOCAL_TEST_PASS / REAL_ARCHIVE_COPY_PASS / WINDOWS_NOT_RUN / LIVE_NOT_INTEGRATED / TTS_HOLD`.

Основание: главный ЭТАЛОН BG Voice RU v1.7, действующий GitHub runtime manifest (Voice Core 4.9.9; Movie Core 1.11.0; V70 Core 1.2.0) и R2 safeguards. Существующий пользовательский CMD **не изменён**. R3 — не второй обновлятор, его не нужно запускать отдельно.

## Реальный результат

1. `bgvoice_report_bridge_r3.py`: адаптер с сигнатурами прежних `Movie._merge_main_report(replacements, root, remove_names)` и `V70._replace_atomic(report, replacements)` (для V70 дополнительно указывается существующий `RESULT_PREFIX`). В одном общем ZIP корректно заменяет записи, удаляет прежние записи по whitelist/prefix, защищает архив O_EXCL-блокировкой, выполняет CRC/проверку имён, атомарную замену. При неизменных данных не переписывает отчёт. Никакой синтез или игра не используются.
2. `bgvoice_windows_probe_r3.py`: read-only инвентаризация точных байтов действующего Windows CMD и Python из venv, существующего общего ZIP, размеров и имён файлов Shtorm. Дополнительно можно включить полные SHA модели, но по умолчанию **4.5 ГБ весов не хешируются**, чтобы не создавать затрат на штатный запуск. Подсчитывает SHA локальных `.py` модулей `voxcpm` в выбранном venv **без импорта и исполнения модели**. Не заявляет, что Style Control работает: только `NOT_VERIFIED`. Сам не пишет файл отчёта. Запуск будет доступен после включения хука в существующий один обновлятор.
3. `test_report_bridge_r3.py`, `test_windows_probe_r3.py`: 9 тестов R3; выполнены совместно с 9 тестами R2.

## Проверки

- Локально в этом контейнере **18/18 PASS** (R3: 9, R2: 9). Сюда входят 2 параллельных процесса, проверка повторного запуска, проверка `remove_names` Movie, замена prefix V70, провал при невалидных ZIP путях, сохранение утверждённого голосового образца, имитация папок Windows и отсутствие файловых изменений в read-only probe.
- ПЕРЕПРОВЕРЕННАЯ КОПИЯ реального пользовательского Windows архива `SOURCE_WINDOWS_VIDEO_REPORT_20261123.zip` (81 entry; оригинальный SHA256 `9ea9089666061a3b29a9d8fb9a1bb0822958438af28e45acc2faee12fb447b19`). После добавления одной тестовой записи в **копию** архива все 81 исходных записи совпали побайтово. Исходный архив НЕ изменился.
- Этот результат не доказывает Windows PASS: RTX 4060 не использовалась, исходные тексты 37 видеореплик не утверждались, Style Control установленного Shtorm не проверялся.

## Интеграционная граница

**Не публиковать R3 в рабочем `bg-voice-ru/BG_VOICE_RUNTIME_MANIFEST.json` до Windows read-only preflight, аудита точного установленного CMD и полного присоединения ZIP-writers к общему lock.** Подключение частичного lock недостаточно: старые процессы могут обходить протокол. Host writer и встроенный Python runtime остаются вне этого R3 в текущем варианте.

Для будущего внедрения нужно:
- При загрузке реальных модулей сверить их pinned SHA, версии `1.11.0` и `1.2.0`, сохранение `HOLD_LITERARY_TEXT_FIRST_37_NO_GPU`.
- Вызовы Movie `_merge_main_report` заменить на `movie_merge_main_report`; V70 `_replace_atomic` на `v70_replace_atomic(..., result_prefix=RESULT_PREFIX)`; остальные фактические writers и host `write/run_local` должны применять ту же блокировку **в том же процессе и всех параллельных процессах**.
- Диагностику `probe_local_environment(...)` вызвать в READ ONLY через **существующий** CMD; результат помещать только в обычный общий ZIP и только через транзакционный writer.
- Результат `READONLY_EVIDENCE_COLLECTED_STILL_TTS_HOLD` не повышать до `MODEL_TRUSTED`, `STYLE_SUPPORTED` или `GAME_APPROVED`.
- Отдельная доверенная публикация подписи Ed25519 и release key provisioning ещё не реализована; тестовые ключи категорически не использовать в живом релизе.

**Ограничения и безопасность:** модуль R3 является исходником для интеграции, не внедрён в живой обновлятор; SRC-only код никакой игры/озвучки не меняет. Продолжать работу над сохранением полного контекста и источниковой редактурой без генерации черновиков. Новые WAV запрещены до human-approved текста и реальных EN оригиналов.
