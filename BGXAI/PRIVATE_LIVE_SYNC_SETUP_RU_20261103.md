# BGXAI — приватная передача коротких сводок, подготовка пилота 0.4.0

**Статус 03.11.2026:** Код прототипа создан и сохранён в `BGXAI/live/BGXAI_LIVE_MONITOR_0.4.0_DEV.ps1` (commit `9eb72ef42ad7428c3c56ab289382c020e46db562`). Он **не активирован** в `BGXAI/live/latest.json` и не передаёт данные пользователя. Монитор 0.3.2 продолжает работать.

## Краткая схема
- EEex пишет начала наблюдаемых действий в `BGXAI_COMBAT.log` (сейчас только Халид, Джахейра, волк).
- Локальная Ollama продолжает анализировать инциденты, без OpenAI API.
- В прототипе 0.4.0: `LIVE_SUMMARY.json` (только типы инцидентов, имена наблюдаемых персонажей, счётчики и UTC-время), `SYNC_STATUS.txt`. Полные логи, путь компьютера, сейвы и ответы модели **не загружаются**.
- Никакая сеть не включается сама. При настройке в окне монитора клавиша **S**, ввод приватного репозитория и fine-grained токена `Contents: Read and write` через `Read-Host -AsSecureString`. Пароль/токен не отправлять в чат. Токен хранится в `%LOCALAPPDATA%\BGXAI_LIVE\private_token.dpapi` в формате Windows DPAPI. Репозиторий проверяется как `private=true` перед записью и при каждой отправке. Публичный `nwn-xanos-updates` запрещён.
- Фоновое сетевое действие через PowerShell Start-Job, частота не выше 1 раза за 120 секунд после появления событий. Целевой путь `live/latest.json` — перезаписываемая сводка, но GitHub хранит историю коммитов; для полного удаления нужна очистка репозитория.
- Код ещё **не проверялся Windows PowerShell 5.1/на машине игрока**, и его нельзя выдавать за работающий релиз. В GitHub не хранить пользовательский PAT или реальные отчёты.

## Единственный необходимый внешний шаг пользователя
1. Открыть `https://github.com/new`. Владелец `jeleZa112`, имя **`BGXAI-private-telemetry`**, видимость **Private**, `Add a README`, `Create repository`. GitHub-репозиторий создаёт пользователь; через установленный GitHub-коннектор создание репозитория недоступно.
2. Добавить новый репозиторий к доступу уже подключённого GitHub App в Settings → Applications → Installed GitHub Apps → Configure → Repository access (Only selected repositories); это необходимо, чтобы ассистент видел приватные сводки по запросу. После создания проверить доступ, не выдавать его за подключённый автоматически.
3. Создать fine-grained personal access token только для одного приватного репозитория с правами Contents read/write (через `https://github.com/settings/personal-access-tokens/new`); никуда не отправлять, позже вводить только в локальное скрытое поле монитора. Важно выбрать дату истечения и продление либо ротацию. Токен **не** даёт ChatGPT права читать его; для ChatGPT отдельное разрешение GitHub App в п.2.
4. Только после подтверждения приватности репозитория и статической/Windows-проверки пилота публиковать 0.4.0 в `BGXAI/live/latest.json` с размером SHA256, проверенным локально, и одним обновлением постоянного CMD (без замены самого CMD).

## Принципиальные ограничения
- Приватный GitHub не равен сквозному шифрованию, а коммиты оставляют историю; минимизировать состав данных.
- Чат ChatGPT сам не подписывается на push и не принимает поток в реальном времени; ассистент читает GitHub **по пользовательскому запросу**, либо через отдельно настроенную периодическую задачу, не в секунды. В реальном времени локально анализирует Ollama.
- Игровая сложность текущего теста: Legacy of Bhaal (GameDifficulty=6). Продолжать анализ отдельно от факта гибели героя.
