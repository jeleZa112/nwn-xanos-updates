# BGXAI 0.7 — переход от BAF-правил к проверяемому командному AI
Дата: 2026-11-03. **Статус: проект плана, НЕ выпущенный боевой релиз.**

## Факты на момент планирования
- Игровая сборка EET v2.6.6.0, последняя опубликованная боевая BGXAI `0.6.26-squad-two-tank-pilot`, установка и корректность активных compiled BCS на ПК не полностью подтверждены. Не путать её с **BGXAI LIVE 0.4.1** — версией монитора (read-only).
- Последний реальный тест на **Legacy of Bhaal (GameDifficulty=6)**; смерть спутника при LoB сама по себе не доказывает дефект AI.
- Из реального EEex-журнала: 221 action, Джахейра `355 RunAwayFromNoLeaveArea` → `3 Attack`, волк многократно `22 MoveToObject` с одной позиции; нельзя объяснять причины, не имея HP, таймстампов, конечных состояний и меток происхождения команд. Локальный монитор зарегистрировал три инцидента, Ollama ошибочно трактовала коды — её промпт исправлялся в 0.3.2.
- `BGXAI/knowledge/observed_enemy_memory_v1.js`, `tactical_priority_planner_v2.js`, `team_combo_planner_v3_offline.js` — **офлайн-модели, не игровые скрипты**. Обнаружено конкретное несоответствие в v2: в начале файла вместо определения `clamp` написано отдельное выражение `(v,a,b)=>Math.min(b,Math.max(a,v))`, после чего идёт обращение к `clamp(...)`; исправить и перезапустить тесты ДО интеграции. Результаты модельных тестов не выдавать за реальную тактическую эффективность.

## Целевое устройство 0.7 (поэтапно)
```
EEex read-only 6 party slots + visible threats
   -> timestamped observation/validation (what was really seen, vs guessed)
   -> state machine for each actor and shared team state
   -> deterministic urgent safety rules (always local BAF fallback)
   -> tactical scorer / role coordinator (initially SHADOW, no orders)
   -> constrained command adapter ONLY after acceptance tests
   -> outcome check: did action start, finish, or get cancelled?
   -> brief reports + offline evidence-based knowledge
```
AI-LLM (локальная Ollama) обобщает подозрительные эпизоды; **не имеет права** напрямую отдавать непрерывные боевые команды без детерминированного фильтра/приоритета человека. GitHub private telemetry 0.4.1 — только краткая передача по мере событий; работоспособность синхронизации с ПК ещё требует подтверждения. Не путать с постоянным GPT-потоком.

## Milestones и критерии
**0.7.0 — наблюдение + доказательство установки**
- Сначала проверить рабочую установку `BGXVER26` для `BGXGRP` и `BGXTANK`, иначе benchmark 0.6.26 недостоверен.
- Подключить read-only `EEex_Sprite_GetInPortrait(0..5)` с резервной копией `M_BGXAI.lua`, определить активных членов партии независимо от имён. Собирать только доступные игровой телеметрии факты: actionId, target, start/end если API допускает, игровую паузу/время, координаты, наблюдаемый HP/состояния. Перед выгрузкой в приватный GitHub псевдонимизировать идентификаторы, исключить системные пути/сырые полные логи.
- Проверить безопасно на одном сохранении, EEex hook/performance, отсутствие вмешательства в ручные команды. Несовместимый API — не активировать.

**0.7.1 — координация отряда (SHADOW)**
- Роли: tank, melee striker, ranged, healer/support, mage/controller, scout. Учитывать мультиклассы/дуалы и способность действовать в нескольких ролях.
- Выбор по `threat score`, расстоянию, текущему действию/очереди, риску получения урона, имеющимся ресурсам; оценивать без точных данных с пометкой `unknown`, не выдумывать иммунитеты/HP врага.
- План `target reservation`: не переключать танка из-за случайного удара; два танка избегают одновременного перехвата одного малозначимого противника; ближайший свободный защищает реально уязвимого.
- Пока выводить `would_do` и сравнивать с фактом, **НЕ исполнять**.

**0.7.2 — survival/recovery LoB**
- Исправить дефекты: `retreat -> attack -> retreat` с гистерезисом, cooldown, запретом сбрасывать очереди вне экстренной ситуации; различать массовую атаку/контроль/урон от единичного слабого попадания.
- Не считать LoB HP-модификаторы основанием изменить проценты без фактов; мерить отменённые действия, урон в бою, расстояние отхода и фактическое спасение.
- Ручной приказ игрока и продолжающееся чтение заклинания приоритетнее плановой смены цели.

**0.7.3 — умные способности и комбинации**
- Реестр доступных заклинаний/умений на текущем уровне с проверкой слотов, дистанции, целей, возможных иммунитетов и защиты.
- Координация исцеления (один закрепляет цель, другие не дублируют), контроль толпы, снятие магической защиты перед DPS, песни/бафы/призыв; избегать конфликтов AoE с союзниками.
- Учитывать SCS/EET/моды и 3E Sneak Attack: только melee. Любая программа должна проверять актуальные правила/признаки предмета, а не жёсткие списки из другой сборки.

**0.7.4 — gated executor**
- Только после минимум 1) tests 2) WeiDU compile/activation 3) одного реального контрольного боя разрешить отдельные ограниченные команды. Один управляющий слой, очередь/арбитраж, защита от повторных actions/lockouts, мгновенный локальный fallback на проверенный 0.6.26.
- Ограничить частоту автокоманд; не выполнять команды из удалённых GitHub-отчётов; пользователь может отключить executor в любой момент.

**0.7.5 — объективная оценка и память**
- Сравнение LoB/Insane отдельно: deaths, cancelled-actions per minute, non-damaging chase loops, heal competition, target switches, useful spells, elapsed time; не утверждать рост DPS без метрик попаданий/реального урона.
- Память о врагах строить только на подтверждённых попаданиях/иммунитетах. Разделять варианты CRE, fingerprint сборки, уровень персонажа, сложность, а также ограничения скрытых атак по уникальному противнику.
- Автоматический краткий `before/after` отчёт и журнал выводов, без автоматического самоизменения боевых BAF/BCS.

## Важные ограничения и release policy
- **Сейчас ничего не устанавливать** под номером 0.7: начнём с пакета 0.7.0 SHADOW. Отдельные версии `BGXAI_UPDATE.cmd` (боевые BAF/WeiDU) и `BGXAI_LIVE.cmd` (наблюдение) не менять молча. `main` NWN не трогать.
- Для всех game-side updates: GitHub SHA256, уникальная компиляция BAF, проверка compiled marker, backup/rollback, отказ без подтверждения Windows/игры.
- Прогнозы/статистику LLM никогда не выдавать за подтверждённый факт движка. Нет гарантии автоматического масштабирования до всех классов в первом 0.7 релизе.
- В любой момент по умолчанию безопасность/ручной контроль выше эффектных комбинаций.
