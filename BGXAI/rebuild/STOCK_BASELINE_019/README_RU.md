# BGXAI: этап 019 — возврат к штатной базе без очередного боя

**Дата:** 05.11.2026. **Статус:** готов набор офлайн-анализа и защитный стоп новой установки; **нового автономного игрового ИИ пока нет**. Не выдавать результаты анализа за проверенную тактику.

## Решение после реальных поражений

Последний журнал `BGXAI_COMBAT(20261105-093310).log` — Имоен A1, 5 запущенных `AttackOneRound` и 4 `RunAwayFromNoLeaveArea`; среди действий по второй цели есть повторяющиеся последовательности `105 → 355 → 105 → 355 → 105 → 355 → 355`. Игрок сообщил, что встроенный Advanced AI управляет лучше. Это достаточно, чтобы **приостановить установку BGXUN1 v0.1.8**, вместо просьбы ещё раз сражаться с теми же хобгоблинами.

## Проверена реальная структура игровых ресурсов

Анализ выполнялся на собственном архиве EET пользователя `BG_EET_AUDIT_02_QUESTS_AI.zip` без доступа к его компьютеру. Итоговые числа:

| Ресурс | Число IF-блоков | Число действий | Вывод |
|---|---:|---:|---|
| `BDDEFAI.BCS` | 322 | 700 | 277 Spell, 221 SetGlobalTimer, 144 SetInterrupt; **нет** зарегистрированного `AttackOneRound`/`AttackReevaluate` внутри именно этого ресурса |
| `BDFTHI01.BCS` | 30 | 75 | 2 AttackReevaluate, проверки переменных `bd_no_retreat`/`bd_retreat` |
| `BDFIGH01.BCS` | 32 | 79 | 2 AttackReevaluate, похожая классовая логика |
| `BDFMAG01.BCS` | 141 | 203 | 2 AttackReevaluate плюс магические правила |
| `BDFCLE01.BCS` | 97 | 147 | классовая ветка жреца |
| `BDAI0020.BCS` | 1 | 4 | переключатель старого режима `bd_ai_no_retreat` |

**Критически важное следствие:** копирование только `BDDEFAI.BCS` не гарантирует работу всех компонентов штатного ИИ. Отдельные классовые BCS имеют собственное поведение; до создания новой установки нужно проверить фактические script slots/роль модов и динамические правила в текущей игре. Нельзя заявлять, что скопировали полностью «Улучшенный ИИ», пока это не доказано.

## Что выполнено реально

1. `src/stock_parity_audit.py`: разбирает сериализованные `.BCS` из архива пользователя, выводит хеши, число блоков/действий/ссылок на переменные **без распространения защищённых игровых ресурсов**.
2. `src/action_replay_gate.py`: читает старые логи EEex, отделяет игровые сессии и обнаруживает известную плохую осцилляцию `105/355`. **Не** приписывает неизвестные команды игроку или ИИ и не подменяет отсутствие HP/агро выдуманными фактами.
3. `src/setup-BGXUNI-STOCK-EXPERIMENT.tp2.txt`: заготовка для будущей изолированной проверки: создать отдельное имя `BGXUN1` копированием *установленного пользовательского* `BDDEFAI.BCS`. Никаких игровых бинарников не включено. **Не запускать**: полноценный набор script slots, ресурсы и WeiDU-контекст пока не проверены.
4. `tests/test_baseline.py`: перепроверяет структуру игровых файлов, остановку при побайтово изменённой «копии», обнаружение старой плохой последовательности в четырёх журналах; результаты в `tests/results.json`. Офлайн-проверка прошла.
5. GitHub `bg-eet-ai`: прежний **один** `BGXAI_UPDATE.cmd` остался побайтно неизменным. Изменено лишь удалённое меню `BGXAI_SYNC.ps1`: **пункт 1 (экспериментальный BGXUN1) временно остановлен**, пункт 2 сохранил прежнюю реализацию, пункт 3/Enter выход без записи. Штатные BDDEFAI / классовые скрипты на компьютере пользователя **не изменены**.

## Ограничения: чего пока не доказали

- Не проверено, какие именно слоты `Override/Class/General/Default` активны у Имоен в сохранении при штатном Advanced AI.
- Не воспроизведены цели агрессии, HP на конкретном тике, безопасность пути, точка за танком или PLAYER/AI происхождение команд.
- Структурные офлайн-тесты не являются симуляцией движка EET/SCS. Нет оснований обещать новый AI, превосходящий штатный, без полноценного baseline.
- Копия `BDDEFAI.BCS` отдельно сама по себе не доказывает равенства комплексному штатному поведению (классовые скрипты работают отдельно).

## Требования до следующей версии

- Сначала восстановить фактическую цепочку Advanced AI по текущим game-side script slots / классовым скриптам.
- Запускать установку отдельного `BGXUN1` только если автоматическая проверка показывает сохранение необходимого набора штатных поведенческих модулей; нужен явный rollback.
- Только затем отдельно подключать read-only EEex сенсоры `HP`, вражеская цель, расположение защитника, path validity, confirmed/manual command source (или `UNKNOWN`).
- Реализовать координацию с защитником и приоритет ручного приказа; валидировать 105/355 регрессии и ситуации на безопасных файлах до приглашения пользователя к тесту.
- Никаких новых CMD; действующий `BGXAI_UPDATE.cmd` неизменен.

**Для игры сейчас:** назначить Имоен ранее работавший штатный Advanced AI через её меню. Сохранять/удалять созданный BGXUN1 не требуется. Новые тесты на хобгоблинах не нужны.
