# BGXAI 0.2.3 — EEex SHADOW telemetry + readiness for Foxx/SCS

**Статус:** исходники и офлайн-проверки. Не установлен в EET. Не является боевым ИИ и не управляет персонажами. Существующий `BGXAI_UPDATE.cmd` и действующий `BGXAI_LIVE.cmd` не менялись.

## Зачем

Пользователь перенесёт игру на новую сборку Foxx и затем установит SCS. Старый пилот BGXUN1 v0.1.8 плохо чередовал `105 AttackOneRound`/`355 RunAwayFromNoLeaveArea`; повторять смерть Имоен ради диагностики нельзя. Оставляем обычный **Advanced AI / «Улучшенный ИИ»**, который сохраняет необходимое пользователю поведение песни барда при магии. **При установке SCS не выбирать компонент `#5000 Ease-of-use party AI`**; прочие компоненты SCS согласовать с новой сборкой и своим порядком модов.

## Что написано

- `src/M_BGX23.lua`: отдельный **пассивный** модуль EEex, использующий официальный `EEex_Action_AddSpriteStartedActionListener`, `EEex_Sprite_GetInPortrait`, `getLocalInt`. Печатает `[BGX23] OBS ...` в тот же лог EEex, что и BGX71, если текущая версия InfinityLoader зеркалирует `print()` в `BGXAI_COMBAT.log`. Ловит коды 3/105/134/355/296, HP, класс, игровую позицию и точку назначения, переключатели `BDAI_SKILL_MODE`, `BDAI_ATTACK_MODE`, численность видимых в LOS врагов. Часто повторяющиеся второстепенные события прореживаются, лимит 4500 строк за сессию.
- `src/BGX23_PARSER.js`: строгий анализатор формата и короткая сводка атак, уходов и песни. Он не преобразует данные в команды игре.
- `src/BGX23_MONITOR_FRAGMENT.ps1`: **неактивная** кандидатная функция для существующего `BGXAI_LIVE_MONITOR.ps1`. При дальнейшем переносе в LIVE 0.4.5 данные останутся в общей системе без дополнительного фонового монитора. Прямо сейчас не подключена и не прошла PowerShell-проверку на Windows.
- `src/BGXAI_FOXX_SCS_PRECHECK_023.ps1`: будущая **только читающая** проверка `WeiDU.log` **новой** EET: SCS, EEex, наличие `EET_END`, присутствие SCS компонента `#5000`. Не изменяет настройки и не устанавливает моды. Это анализ журнала, не проверка фактических BCS/CRE ресурсов.
- `tests`: реальные Lua mock-тесты, JS-тесты парсера, сверка структуры после сборки.

## Строгие ограничения

- Только члены партии из проверенных слотов портретов. Никаких «всевидящих» NPC. Не определять врага по `NONPARTY_UNVERIFIED`: это может быть фамильяр, нейтрал или предмет.
- `manual=UNKNOWN`, `enemyTarget=UNKNOWN`, `weapon=UNKNOWN`, `maxHP=UNKNOWN`, `path=UNKNOWN`, `sessionEpoch=UNKNOWN`. Движок не доказывает эти факты данным подписчиком. В частности, выбранный персонаж ≠ ручной приказ.
- Радар **опционален**. В проекте уже существуют `BGXRADAR_EVIDENCE_GATE_V02.js`, `BGXRADAR_FUSION_V01.js`, но у штатного BG Radar нет подтверждённого локального экспорта данных. Скрипт не подменяет их фиктивными фактами и не подключается к памяти Radar.
- Никаких `Attack`, `RunAway`, `MoveToPoint`, `BattleSong`, `SetGlobal` или переключения оружия; не трогает SCS, EET, классовые скрипты или ручное управление.
- **Не считать офлайн-прохождение тестов доказательством работы в Windows EEex 1.1.7 / InfinityLoader.** Не включать автоматически на новую сборку без проверки версий и безопасного способа установки.

## После установки новой Foxx + SCS

1. Подтвердить новую конфигурацию по `WeiDU.log`; использовать `BGXAI_FOXX_SCS_PRECHECK_023.ps1` только после установки. Сверить наличие/отсутствие #5000 и остальные изменения по сравнению со старой конфигурацией.
2. Сверить в новой EET API EEex, целостность `BDDEFAI.BCS`, песню барда и фактический состав скриптов/слотов.
3. Проверить *только наблюдение* от BGX23 в штатной игре, затем осторожно включить парсер единого `BGXAI_LIVE_MONITOR` — без боевых экспериментов на выживание.
4. Точный источник ручных команд, текущая цель противника, безопасный маршрут и связь с Radar — отдельные задачи с требованием реальных доказательств.

Документация: EEex v1.1.7 `EEex_Action.lua`, `EEex_Sprite.lua` и существующий проект `BGXAI/eeex/M_BGX73.lua`. Исходники SCS v35.21 использованы как справочные, **не для замены партийного AI**.
