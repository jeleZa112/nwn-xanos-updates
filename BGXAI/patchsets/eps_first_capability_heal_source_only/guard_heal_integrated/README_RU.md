# BGXAI — единый патч к действующей 066S: выбор защитника и лекаря по возможностям

**Состояние на 14.11.2026: SOURCE ONLY, НЕ УСТАНАВЛИВАТЬ В ИГРУ.** Это **доработка текущего Lua 066S**, не самостоятельный бот и не ещё одна устанавливаемая номерная версия. EPS 18.4 остаётся основным исполнителем атаки, бафов, лечения, песен барда и предметов.

## Что изменено **только в кандидате**

В Lua уже имелись обработчик попадания, выбор F-защитника, запросы `BGX52_REQ_SLOT` и лечение/Shield `BGX66_*` через BCS. Они сохранены.

1. **Лечение и Shield:** прежний подготовленный патч допускает будущую проверку конкретного реально доступного заклинания (`S.capabilityVerifier`), вместо неизменяемого списка class ID. По умолчанию `nil`, точное старое поведение 066S.
2. **Охрана:** в том же самом файле добавлен опциональный `T.capabilityVerifier`; **по умолчанию он `nil` и `T.capabilitySourceVerified=false`**, в таком режиме старая ветвь 066S с классами `[2,6,12]` ведёт себя как раньше. Это не ограничение будущей модели, а только сохранённый fallback реально установленного скрипта.
3. **Если в будущей версии отдельно подтверждён источник достоверных данных:** перечень классов не используется для выбора охранника. Ему необходима подтверждённая боеспособность сейчас: подходящее оружие/форма, возможность пробить атакующего, активный kit/dual, настоящий свободный action state, пустая очередь EPS, отсутствие ручного приказа, ожидающего лечения, каста, песни барда и ловушек. Требуются точные совпадения IDs охранника, атакующего, защищаемого и номера события. Любое поле отсутствует, `nil`, неверно, исключение в provider или metatable-сгенерированное значение => отказ.
4. **Текущие ограничения не ослабляются:** F=ON, те же AREA, HP>50% и HP>3, modal NONE, reservation/TTL, выбор по расстоянию, тот же BCS `ActionListEmpty`, приоритет жизненно необходимого лечения. Прямые Lua `Attack`/`Spell`/`ClearActions` не добавлены.

**Важное ограничение архитектуры:** Lua-обработчик попадания владеет ID врага, однако прежний BCS 061 использует `LastAttackerOf(PlayerN)` и другие движковые селекторы. Точный выбор **того же** атакующего BCS не доказан, даже если модельный provider возвращает все требуемые флаги. Включать новую ветвь до отдельной проверки этого контракта и реальной provenance/queue нельзя. В коде **не устанавливается** `T.capabilitySourceVerified=true`.

## Проверки, реально выполненные офлайн

- Полный исходный Lua 066S на нативной Lua 5.4 с моками EEex: **18/18** исторических тестов PASS.
- Тот же исторический набор без проверки byte-exact старого файла на новом кандидате: **17/17** поведенческих тестов PASS.
- Добавочные **27/27** Python unittest (каждый выполняет Lua 5.4 либо проверяет файлы): проверка всех `CLASS.IDS 1..21` при выключенном новом коде; 14 примеров гибридов/китов/ресспека при явной модельной проверке; вызов второго защитника при занятой очереди первого; блокировка при ручном приказе, лечении, касте, песне и ловушках, неверных актёре/атакующем/цели/номере события, недоказанных полях, ошибках provider, F=OFF, другом ARE, слабом HP и modal; совместимость с прежними тестами лечения шамана и Shield.
- `texlua` проверка синтаксиса; BAF был побайтно сохранён, не компилирован и не установлен.
- После архивации требуется чистый повтор `python verify_release.py` и `python run_regression.py` на извлечённом содержимом.

**Честная граница:** все новые сведения о способностях в тестах передаются симулятором. `manual_order_absent_verified`, `eps_queue_empty_verified`, текущая боеспособность/формы/умения через EEex v1.1.7 в живой игре **не подтверждены**. Никакого улучшения в реальной игре это ещё не принесло. Не переключать боевые режимы самостоятельно, не выдавать тесты за реальную работу в EET.

## Запуск только на независимой копии исходников, не в игре

В каталоге пакета на ПК с установленным Python и библиотекой Lua 5.4 (или аналогичной проверочной средой):

```powershell
py -3 verify_release.py
py -3 run_regression.py
```

Это **не действия, которые пользователь обязан сейчас выполнять**: результаты уже проверены в изолированной среде. Пакет не содержит установщика. Работа продолжается от сохранённой 066S, пока нет доказанных причин её менять. Любая установка потребует отдельного подтверждения, точных SHA, резервной копии и обратимого теста.
