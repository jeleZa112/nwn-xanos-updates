## Обнаруженная, воспроизведённая ошибка предыдущего кандидата

Новая модель защитника по подтверждённым способностям позволяет воину/жрецу или другому гибриду быть одновременно кандидатом на охрану и на лечение. Предыдущий скрипт сначала резервировал охрану, потом лечение, а два BCS-запроса могли адресоваться ОДНОМУ актёру. Дополнительно проверялись разные Lua-аренды по 45 тиков, но не активный BCS-запрос, живущий до 300 тиков. Создали три изолированных теста, которые **достоверно провалились на предыдущем V2**, затем исправили.

## Точное изменение

Пять строго проверенных участков в ТОМ ЖЕ `M_BX43_066S_CAPABILITY_CANDIDATE.lua`:

1. В **неактивном по умолчанию** новом режиме `T.capabilitySourceVerified==true` сначала вызывается старый `S.onHit`, затем старый `T.prepare`: лечению предоставлен первый запрос.
2. Если для актёра уже есть Lua-резерв лечения или BCS-переменные `BGX66_S_HEAL_SLOT`/`BGX66_S_WARD` ненулевые, он исключается из выбора охранника.
3. Если для актёра уже есть Lua-резерв охраны или BCS-переменная `BGX52_REQ_SLOT` ненулевая, он исключается из выбора лекаря.
4. При ошибке чтения указанных LOCALS кандидат **не** даёт новый конфликтующий запрос.
5. При `T.capabilitySourceVerified~=true` — прежний 066S порядок и выбор, строго сохранённый тестом и обратным точным патчем.

**Никаких новых действий Spell/Attack/ProtectObject/ClearActions, регистрации EEex хуков и изменений BAF.** Перехватчик по действительным способностям и проверяющий наличие заклинаний остаются отключёнными до подтверждения live EEex / происхождения ручных приказов / пустоты очереди EPS.

## Честные результаты проверок

- RED before fix: **3/3 целевых теста проваливались** на предыдущем V2, доказав отсутствие согласования двух каналов.
- GREEN after fix: **5/5 точечных тестов**, исходная 066S **18/18**, прежнее поведение кандидата **17/17**, полный новый набор **32/32**.
- `arbiter_exact_diff.py` возвращает новый код к предыдущему проверенному V2 побайтно, отклоняя любые правки за пределами пяти разрешённых участков.
- `verify_release.py` проверяет контрольные суммы всех файлов, историю исходников, точность diff и отсутствие установщиков/скомпилированного BCS. `run_regression.py` заново запускает тесты. Отдельно `texlua parse.lua M_BX43_066S_CAPABILITY_CANDIDATE.lua` подтверждает синтаксис.
- Эти тесты исполнялись с модельными EEex объектами и не доказывают улучшение в живом бою. Новый режим по умолчанию OFF.
