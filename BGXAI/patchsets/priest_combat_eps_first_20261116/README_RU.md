# BGXAI BGXP2 — боевой священник / поддержка / авто, EPS-first

**Устанавливается ПОВЕРХ уже работающего BGXPR Priest Modes**, отдельным компонентом WeiDU `BGXP2` через привычный `BGXAI_UPDATE.cmd`. Не меняет `M_BX43.lua`, режим HEALER или предыдущие 1130 BCS-блоков. Добавляет 28 блоков **в конец** `BDDEFAI.BCS`; 1158 блоков после установки. Не заменяет EPS, не переключает `bddefai` и не управляет зельями/свитками. Это реальная игровая функциональность, но компиляцию на конкретной EET и поведение в бою необходимо проверить через предусмотренный preflight и игру.

## Режимы

Для выделенного жреца с включённой F-охраной и общим ИИ: `Ctrl+Shift+J` циклически выбирает старые режимы (`EPS OFF` → `HEALER` → `SUPPORT` → `BATTLE CLERIC` → `AUTO`). Роли хранятся в `BGXR_ROLE` для каждого спутника отдельно. Эта версия **не меняет горячую клавишу**, используемую установленным BGXPR.

- **HEALER (1):** полностью неизменён: проверенная на Jade и Jagan самостоятельная попытка приблизиться и лечить.
- **SUPPORT (2):** дополнительно к старым проверкам лечения при свободном исполнителе применяет запомненное `CLERIC_REMOVE_FEAR` на союзника в панике или `CLERIC_SLOW_POISON` на отравленного, если цель видна в радиусе 10. При отсутствии таких доступных заклинаний остаётся EPS.
- **BATTLE (3):** после старой экстренной проверки лечения, когда жрец здоров, незанят и видит близкого противника (12 Range), может применить запомненное `CLERIC_COMMAND` к врагу, затем в следующей возможности атакует один раунд посредством `AttackOneRound`. Не гонится за врагами на другой край карты.
- **AUTO (4):** лечит по уже установленным в BGXPR порогам. При панике/отравлении союзника подключает поддержку; если никому из шести портретных слотов не требуется экстренное лечение (<45% HP), свободен и достаточно здоров, применяет `Command` и ограниченно атакует близкого врага.
- **EPS OFF (0):** новая логика не выполняется.

Каждый новый блок требует `Global("BGX38_GUARD","LOCALS",1)`, `ActionListEmpty()`, `ModalState(NONE)`, отсутствие старой лечебной заявки и правильный режим. Исключены `ClearActions`, `ForceSpell`, `ActionOverride` и команды движения. Во время текущего лечения/заказа EPS новая логика не должна перебивать очередь. Оставшееся ограничение: `ActionListEmpty()` не доказывает происхождение завершённого ручного приказа. Это сохраняется как риск при полностью автономном управлении.

## Через единственный BGXAI_UPDATE.cmd

Сохрани оригинальный CMD. После обновления GitHub PIN появляется новая группа меню **105–108**: проверка статуса, read-only компиляция с IDS установленной EET, устанавливаемое обновление с **отдельным точным подтверждением `INSTALL_BGXP2_COMBAT_PRIEST`**, откат с `ROLLBACK_BGXP2_COMBAT_PRIEST`.

1. Для проверки **без изменений игры**: `105`, затем `106` — только если нужен запуск реальной компиляции на ПК.
2. Закрой Baldur/InfinityLoader/WeiDU; выбери `107`, введи точное подтверждение. Установщик самостоятельно проверяет, что последняя запись WeiDU — `BGXPRIEST`, а Lua и BCS совпадают с двумя **известными установленными SHA**. Создаёт проверенную внешнюю резервную копию в `Документы/BGXAI_PRIEST2_SAFE_BACKUPS`, выполняет WeiDU и сверяет постинсталляционные SHA.
3. **Откат `108`** допускается только если BGXP2 — последний WeiDU-мод, создаёт отдельный бэкап и возвращает прежнюю BGXPR, не трогая Lua, EPS, предыдущие файлы.

Нельзя использовать старые пункты `84`, `94`, `96`, `99`, `100` для управления этим обновлением. Они относятся к другим слоям. Если префлайт FAIL — **не устанавливай** и не повторяй автоматически.

## Что НЕ доказано офлайн

- Реальное поведение нового блока на твоих IDS, в игре, при сложных заклинаниях и глобальных эффектах EPS.
- Полная стратегическая автономность шести персонажей (согласованная магия, ловушки, предметы, HLA и т. д.).

Заявлять полноценного бота готовым до игрового испытания нельзя. Вся работа над текущим модулем аддитивна, без удаления уже успешного HEALER.
