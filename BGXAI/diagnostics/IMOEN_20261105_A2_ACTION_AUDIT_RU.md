# BGXAI — диагностика Имоен (A2), 05.11.2026

**Источник:** присланный игроком `BGXAI_COMBAT(20261105-022204).log` (без публичной публикации исходного лога).
**Контекст пользователя:** игрок сам перемещал Имоен к врагу; только Имоен имела новый сценарий BGXUN1; по зрительному наблюдению она пыталась биться, не отступала и погибла.

## Достоверно из журнала EEex BGX71

- Внутри одного исходного файла: 296 запусков действий четырех членов партии, 92 запуска для `A2 slot=2` (Имоен по положению в партии), регистрация смерти `SPRITE_IS_DEADIMOEN2` ближе к концу.
- Для A2: `23 MoveToPoint` ×48, `83 SmallWait` ×28, `84 Face` ×7, `200 RandomWalkContinuous` ×7, `24 Panic` ×2. Кодировка проверена по настоящему `ACTION.IDS` из сохраненной пользователем EET.
- `105 AttackOneRound` ×0; `3 Attack` ×0; `355 RunAwayFromNoLeaveArea` ×0 **среди зарегистрированных начал действий A2**. Ноль в неполном журнале НЕ означает отсутствие реальных ударов: в логе нет исчерпывающих попаданий, исходящего урона или всех engine действий.
- Лог содержит стартовый `BGX71 READ_ONLY_DYNAMIC_PARTY_REGISTERED` и `FILTERED ACTION HOOK REGISTERED v5`, но НЕТ `origin=PLAYER/AI`, маркеров фактического активного сценария на каждом тике, полных HP snapshots и привязки к инпут-событиям игрока.

## Обнаруженные ошибки дизайна, а не игрока

1. В установленном `BGXUN1.BAF` (v0.1.3) действительно **нет аварийной ветки отступления**. Есть лечение и защиты по `HaveSpell`, но Воин/Вор Имоен не обязана иметь эти заклинания. Следовательно, на сценарий нельзя было рассчитывать как на AI самосохранения в ближнем бою.
2. Система `BGX71` и LIVE 0.4.4 распознаёт паттерны `MoveToPoint`, `Attack`, `Panic`, но **не источник приказа**. В более новом offline-only `M_BGX73.lua` явно `manual=?`. Ранее заявленную задачу player-vs-AI attribution завершённой считать нельзя.
3. `ActionListEmpty()` помогает не перебивать занятую очередь команд, но **не различает** её происхождение. При ручном ведении персонажа действие MoveToPoint может доминировать в журнале; нельзя классифицировать эти события как ошибку BGXUN1.

## Требования следующего исправления

- Установленный старый Advanced AI сохранить; менять только отдельный BGXUN1 через **существующий** `BGXAI_UPDATE.cmd`, без новых CMD.
- Добавить ограниченное аварийное отступление низкоуровневому не-кастеру с лимитом/таймером, без бесконечного бегства и без перехвата ручной очереди. Сначала проверить компиляцию/поведение в EET; offline-модель не доказывает in-game.
- Реализовать отдельный **engine/UI manual-order probe** (на момент аудита не установлен) и привязывать его к party action observer по epoch+actor+queue+time. Пока источник неизвестен, маркировать только `UNKNOWN`; по одному `MoveToPoint` не приписывать AI.
- Включить read-only HP, weapon/mode, ability availability, current target; без этих сенсоров не утверждать причину смерти или успешность атаки.
