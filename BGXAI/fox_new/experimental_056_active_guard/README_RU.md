# BGXAI 056 — активная охрана по подтверждённому попаданию (кандидат)

Дата разработки: 10.11.2026. Статус: **кандидат для безопасной интеграции, НЕ установлен**.

Исходная установленная конфигурация: `BGXAI 042B + 043P + 044 + 045 + 046 + 047 + 048 + 049`, EET Foxx `C:\Games\BG_EET_FOXX_NEW`, EPS 18.4, SCS 35.21, EEex v1.1.7. До установки **обязательны** внешние резервные копии и успешные офлайн-проверки. Не копировать файлы вручную в override.

## Что меняет кандидат 056

При подтверждённом EEex попадании чужого персонажа по отряду **Lua выбирает единственного защитника** с включённой локальной `BGX38_GUARD=1` (клавиша F, исключая главного героя), пропускает песню барда / ловушки / скрытность по `m_nModalState`, проверяет ID, координаты, время и сохраняет ограниченный запрос `BGX52_REQ_SLOT` и срок истечения `BGX52_EXPIRE` в LOCALS выбранного защитника. Lua **не вызывает Attack/ClearActions/ProtectObject**.

**BCS** реагирует на запрос только при `BGX38_GUARD=1`, `ActionListEmpty()`, `ModalState(NONE)`, `See(PlayerN)`, `Range(PlayerN,10)`, `See(NearestEnemyOf(PlayerN))`, `Range(...,7)`, активном TTL и отсутствии кулдауна. Команда — существующая `ProtectObject(PlayerN,6)`. Исходные 1057 блоков BCS остаются байт-в-байт и в прежнем порядке. Восемь новых блоков вставляются **перед первым блоком охраны (оригинальный 1032), после обработчика F**. Никакой `EXTEND_TOP` перед обработчиком F.

## Особые ограничения

- `ActionListEmpty()` запрещает прерывать текущий ручной приказ, лечение, заклинание, передвижение и песню. Защита может задержаться до окончания `AttackOneRound` в EPS; немедленное реагирование без отмены действий не гарантируется.
- Главный герой не назначается командным защитником. Срабатывание требует включённой F-охраны у хотя бы одного спутника и наличия врага рядом с атакованным.
- Подтверждённое попадание — НЕ гарантированная враждебность по игровому `EA.IDS`; конечный скрипт дополнительно проверяет наличие `NearestEnemyOf`.
- `BGX52Bridge.prepare` **не выводит** реальную команду (ее отправляет только BCS после самостоятельного пересмотра условий).
- Это кандидат на изменение двух живых файлов: `override/BDDEFAI.BCS` и `override/M_BX43.lua` — нужны WeiDU backup, SHA pin, статус и откат. Нельзя утверждать, что песня/магия/охранное поведение реально протестированы в игре.

## Доказательства до установки

Проводятся офлайн проверки с настоящим WeiDU 251 на Windows и Linux: синтаксис и компиляция актуального BAF версии 056 с публичным набором IDS. Отдельно проверяется вставка восьми реальных блоков между 1031-м и 1032-м блоками искусственного BCS из 1057 блоков. Локальные тесты установщика используют модель игры и подтверждают запрет изменений при неудачной компиляции, SHA и полный цикл отката. Тесты Lua используют настоящий интерпретатор Lua (`lupa`) с макетами EEex. **Это всё ещё не подтверждение работы с настоящими файлами EET и внутри боевого движка.**

Все изменения 056 отключаются при штатном откате WeiDU. Текущая версия 049 остаётся нетронутой до отдельного подтверждения пользователя.
