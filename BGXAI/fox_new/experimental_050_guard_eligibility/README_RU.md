# BGXAI 050 — исследование охраны F / достоверные кандидаты на защиту

**Дата:** 10 ноября 2026 г.  **Статус:** ПРОТОТИП ИСХОДНИКОВ, только офлайн; в игру не установлен. **Текущая рабочая версия пользователя:** BGXAI 049, успешно проверен в EET (HITS=1 GUARD=1 QUEUE=1 ERR=0 DISPATCH=false).

## Проверенные источники

- В `BGXAI/fox_new/release_040/BGX40/toggle_feedback.baf` и `release_041/BGX41/toggle_icon.baf` режим F переключает `Global("BGX38_GUARD","LOCALS",0/1)` для каждого персонажа.
- В EEex `v1.1.7`, файл `EEex/copy/EEex_scripts/EEex_Sprite.lua`, `EEex_Sprite_GetLocalInt(sprite, name)` выполняет `sprite.m_pLocalVariables:getInt(name)`, экспортируется как `CGameSprite.getLocalInt`.
- В `BGXAI/fox_new/release_039/BGX39/team_guard_fallback.baf` командная охрана разрешена только при `InParty(Myself)`, `!InPartySlot(Myself,0)`, `Global("BGX38_GUARD","LOCALS",1)`, `ActionListEmpty()`, наличии видимого союзника/угрозы, расстоянии и кулдауне. `release_042b/guard_source_042a.py` переставляет 11 блоков `ProtectObject` перед автоатакой EPS, **не отменяет текущие действия**.
- `BGXAI 049`: при реальном попадании EEex передаёт объекты атакующего и пострадавшего; guard advisory фиксирует событие, но не меняет боевые действия.

## Что добавлено в прототип 050

Файл `M_BX43_050_PREVIEW.lua` — расширение исходника 049. Только при подтверждённом попадании он читает у остальных членов отряда `sprite:getLocalInt('BGX38_GUARD')` через `EEex_GameObject_Get` и подразделяет кандидатов:

- `guard_on_candidate_ids`: командные защитники с **подтверждённым** состоянием F=1;
- `guard_off_candidate_ids`: F=0;
- `guard_unknown_candidate_ids`: переменная недоступна/не удалось прочитать;
- `excluded_protagonist_ids`: слот Player1, поскольку командные защитные блоки 042B его исключают.

Старые `guard_signals`, `weapon_hit_calls`, `events`, журнал атак и защитные проверки 049 сохранены. В снимке добавлены диагностические `guard_eligibility_passes`, `guard_eligibility_errors`, `guard_local_reader_available`.

**Это только проверка F.** Никаких предположений о LOS, расстоянии, текущей ручной команде, касте, песне барда или возможности перехвата. `guardDispatchEnabled=false`, никаких действий, `QueueResponse`, `ClearActions`, `SetGlobal`, `ActionOverride` и записи в игровой движок. На попадание всегда возвращается `false`, чтобы не блокировать урон.

## Проведённый тест

Тест `test_guard_050.lua` исполняется интерпретатором `texlua` (Lua 5.3) с моделями EEex 1.1.7. Команда:

```
texlua test_guard_050.lua M_BX43_050_PREVIEW.lua
```

**PASS: 106 BGXAI 050 Lua runtime checks.** Смоделированы смена флага F, отсутствие/ошибка чтения, своя атака, чужая цель, копирование снимка, сохранение кольцевого буфера в 64 события, невозможность отдать приказ и не блокировать попадание. Это тест логики; интеграция с живым EEex не доказана.

## Почему пока НЕ выпускаем установщик

- Для настоящих боевых приказов нет верифицированного способа отличать вручную выданные действия, заклинания, песни и самостоятельные действия EPS. Нельзя бездумно прерывать их.
- `ActionListEmpty()` в 042B препятствует вмешательству в незавершённый каст/ручную команду, но задерживает перехват до освобождения очереди. <https://iesdp.bgforge.net/scripting/triggers/bg2triggers>
- `ProtectObject()` уже присутствует в 042B; ненужная повторная отправка может отменить полезные действия или вызвать бесконечную переоценку. <https://iesdp.bgforge.net/scripting/actions/bgeeactions>

**Следующий этап:** составить защищённую политику для использования одного события `attacker_id/protected_id` с проверенной ролью F, текущими действиями, дальностью и приоритетами EPS, выбрать минимальный вариант без `ClearActions` и без повторной установки пассивных модов. До этого 049 остаётся штатной работоспособной версией.

**Не копировать этот модуль в `override` вручную.** Для будущей установки — только установленный `BGXAI_UPDATE.cmd`, pinned SHA256, отдельный WeiDU компонент, резервная копия, явный `YES` и откат.
