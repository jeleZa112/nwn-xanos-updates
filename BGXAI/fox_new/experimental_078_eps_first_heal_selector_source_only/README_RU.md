# BGXAI 078 — автоматический отбор доступного лекаря (SOURCE ONLY)

**Дата:** 14.11.2026. Установленная в Baldur's Gate EET версия — **066S**, проверенная пользователем реальными read-only проверками 075 и 076R1. **078 НЕ УСТАНОВЛЕНА**, игрового патча или подключения к EEex нет. F-охрана — наша BGXAI, НЕ штатная кнопка EPS. Не устанавливать 067.

## Зачем

Аудит 077 закрепил исходники 061/066S с SHA256. В старом Lua выбирался *ближайший* жрец по классу и дистанции **до** проверки фактического CLW, BCS `Range(PlayerN,10)` и свободной очереди EPS. Если ближайший не умеет/не может лечить, другой потенциально доступный лекарь не отбирался автоматически. Роли бойцов ограничены тремя base CLASS.IDS; шаман и активные дуалы не поддерживаются надёжно.

## Что сделано в 078

- `BGXAI078_HEAL_SELECTOR.lua` — *самостоятельный чистый Lua-алгоритм* выбора из всех представленных кандидатов (до шести), с отказами по понятным кодам и переходом к следующему пригодному. НЕТ вручную перечисленных имён или запрета мультиклассам/китам/шаманам по ID: доступность лечения доказывается текущей подтверждённой способностью.
- Требует `F=ON`, фактически доступное `CLERIC_CURE_LIGHT_WOUNDS` (точно для текущего BCS 066S), подтверждённую видимость, **результат эквивалентной проверки BCS Range 10**, жизнеспособность и свободную очередь EPS, отсутствие ручных приказов, текущего каста, песни, обнаружения ловушек, ожидающего лечения и уже существующего запроса.
- Режим opt-in по умолчанию **OFF**, всё неизвестное — отказ, существующее лечение EPS получает приоритет. При равной дистанции выбирается меньший слот портрета; длительность, HP и класс не выдумываются. Расстояние применяется лишь для сортировки; координаты EEex нельзя просто считать футами BCS `Range`.
- Шаман (`21`), жрец/мультикласс и восстановленный дуал **могут быть кандидатами только при подтверждённом подходящем заклинании и действующих способностях**. Для обычного друида/оборотня без лечения кандидатом не становится. Скрипт **не генерирует игровые команды** и не вызывает `setLocalInt`, `Spell`, `AttackReevaluate` или EEex hooks.
- Это *алгоритм принятия решения*, а не пока работающий мод: реальный источник `spell.usable_now`, `target.in_bcs_range_10`, `eps.queue_empty`, `eps.manual_command` и доказанный статус способности на пользовательском EEex пока **не подключён и не доказан**. Подмена `verified=true` по предположению запрещена.

- **14/14 проверок Python PASS**, включая исходники 061/066S из сохранённого приватного каталога (если он доступен). Пакет сам эти исходники не распространяет.
- Четыре подлинных файла 077 ещё раз SHA-сверены на рабочем контейнере; ни одного файла установленной игры не меняли.
- `verify_release_078.py`: SHA-контроль исходников + запрет опасных игровым вызовов.

## Следующее содержательное действие

Разрабатывать безопасный **read-only EEex provider**, который способен доказать факты доступного именно сейчас `CLERIC_CURE_LIGHT_WOUNDS`, `Range(PlayerN,10)` и пустоты очереди EPS. При невозможности доказать — отказ, а не гадание. *Не подключать активную часть к игре*, пока не пройдут подтверждение реальных API EEex 1.1.7 и отдельное разрешение на установку с точным SHA/бэкапом. Настоящая 066S — неизменна. Не просить повторять Шанка/архивы/075/076R1.
