# BGXAI 063 — native Lua 5.4 regression suite (SOURCE ONLY)

Дата: 2026-11-12. Установленная на ПК BGXAI 061 не изменена; 063 не установлен и не подключён к загрузке EEex.

**Отличие от прежних прототипов:** тестируем два реальных источника Lua в настоящей локальной Lua VM через ctypes/liblua5.4, без вызовов движка игры:

1. `BGX62E_CLASS_ACTION_PROBE.lua` — точная копия 062E. Проверяется выполнение snapshot() на mock EEex: отсутствие API, корректные 2 персонажа, 0..5 портреты, повторы ID, ошибки доступа, неверные значения класса/action, отсутствие попыток послать боевые команды.
2. `BGX59_ELIGIBILITY_059_HISTORICAL.lua` — из исходного ZIP проекта 059, **это исторический неустановленный прототип**, а не установленная версия M_BX43.lua. Проверяется ближайший кандидат, равная дистанция/slot, другая AREA, отсутствие видимости, ошибки API и отсутствие боевых команд. Не содержит моста записи Q.
3. В комплект добавлены все Python-модули и тесты 062E, 062D, 062C, 062B для регрессии.

**Команда в среде разработчика:** `python -m unittest discover -s . -p 'test_*.py' -v`.
**Факт:** 103/103 PASS. Первоначально было 1 ERROR из-за забытого `BGX62D_BASELINE_SNAPSHOT.lua`; файл добавлен, весь набор перепроверен, 103/103 PASS.

**Строгие ограничения:** 063 не использует установленную EEex, не утверждает реальную работоспособность Lua в EET и не разрешает автоматический перехват на основании класса или actionID. Историческая 059 была нужна для независимой динамической проверки уже реализованного алгоритма одиночного выбора, не как точный бинарный эквивалент 061.

## Вывод о вооружении
Старый пример чтения активного launcher может вернуть ammunition resref. Не следует использовать x86 memory offsets для x64 EEex. Описание публичного мода использует `GT_Sprite_GetSelectedWeapon`, но нет подтверждения, что эта глобальная функция присутствует в пользовательской сборке; поэтому реальную экипировку/рукопашную роль по-прежнему считаем UNKNOWN.
