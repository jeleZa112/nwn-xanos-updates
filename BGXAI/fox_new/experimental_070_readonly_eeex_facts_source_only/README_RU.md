# BGXAI 070 — проверяемый пассивный адаптер данных EEex

Дата: **14.11.2026**. Статус: **SOURCE ONLY / НЕ УСТАНАВЛИВАТЬ**. Текущая установленная BGXAI в EET: **066S**. 067 — заморожена, 068/069 — модели и исходники, 070 — новый отдельный read-only Lua-модуль. Никакого обновления установленной игры, EPS, `M_BX43.lua`, `BDDEFAI.BCS`, `WeiDU.log`, автообновлятора или меню.

## Что теперь действительно реализовано

- `BGXAI070_EEEX_FACTS_READONLY.lua`: функция `snapshot(sprite)` пассивно читает `m_typeAI.m_Class`, `m_baseStats.m_hitPoints`, `m_derivedStats.m_nMaxHitPoints`, `m_derivedStats.m_nKit`, `m_derivedStats.m_nLevel1/2/3`, `m_derivedStats.m_bPolymorphed`, `m_nModalState`, `getLocalInt('BGX38_GUARD')`. Каждый read защищён `pcall`; нет игры / объекта — значения `nil` / `UNKNOWN`.
- `facts_for_069(snapshot)` передаёт **только неподтверждённые** kit/form/actions/combat/healing в прежний 069. Отсутствие достоверных сведений о дуале передаётся как `nil`, а не как *подтверждённый дуал*. Это предотвращает ошибочную потерю способности базового воина в классификаторе, но **не даёт ни одного нового боевого разрешения**: actions/combat остаются не проверены.
- `inspect(sprite, role_observer_069)` объединяет read-only snapshot с read-only рекомендацией. Нет команд движку, событийных подписок, логирования в игру, timers, записи LOCALS, управления F или EPS.
- Нативные офлайн-тесты `test_070.lua`: **230/230 проверок PASS** на эмуляции, включая 21 CLASS.IDS, дуал Воин→Маг, оборотня, шамана, неправильные IDs, ошибочные/отсутствующие поля, неверные уровни, HP, KIT, провал чтения EEex и запрет нового перехвата при неизвестной очереди EPS.

## Чего это НЕ доказывает

- Документация EEex предоставляет **названия полей**, но их безопасное чтение именно у пользователя с EEex 1.1.7 не проверено в живой игре. Код никогда не автоматически загружается в игру.
- `m_nKit` — **сырое числовое значение**, НЕ гарантированно расшифрованный кит из реального EET `KIT.IDS`/`KITLIST.2DA`; модовые значения не угаданы.
- `m_bPolymorphed` = «движок отметил превращение»; это НЕ доказательство, что персонаж именно Werewolf / Greater Werewolf, что ему доступна эффективная атака или что он может танковать.
- `m_nLevel1/2/3` — уровни; сами по себе **не подтверждают** тип дуала, его восстановление или активность способности предыдущего класса. Варианты мультиклассов/кастомизации SCS нуждаются в отдельных проверках.
- `m_nModalState` — сырое поле; `0` НЕ означает отсутствие ручного приказа, кастинга, песни или намерения лечить. `ActionListEmpty()` в BCS недостаточно для гарантии безопасного прерывания атаки. Совместимость с очередью EPS в реальной игре остаётся **открытой задачей**; эта версия по построению не вмешивается в EPS.
- Ни WeiDU/EET компиляция, ни реальный бой не проводились. **Никакой полноценной автоматической охраны классов 070 сейчас не добавляет**.

## Подтверждение внешних структур

- Автор EEex объясняет, что в новом EEex нужно читать **именованные поля**, а не сырые указатели: https://forums.beamdog.com/discussion/71798/mod-eeex-v1-3-0/p41 (пример `sprite.m_typeAI.m_Class`, при доступности).
- В справочнике EEex `CDerivedStatsTemplate`: `m_nKit`, `m_nLevel1`, `m_nLevel2`, `m_nLevel3`, `m_bPolymorphed` — https://eeex-docs.readthedocs.io/en/latest/EE%20Game%20Structures%20%28x64%29/CD/
- ID классов 1–21 — https://gibberlings3.github.io/iesdp/files/ids/bgee/class.htm

## Как проверить исходники, не трогая игру

В папке пакета, при установленном `texlua` и Python:

```sh
texlua test_070.lua
python verify_070.py
```

`BGXAI069_ROLE_OBSERVER.lua` — неизменная копия предыдущей 069 (SHA256 `4e65f1bb9ddbc3501d593199442decf5fed2525fb2373b3ed7f7ad0dff068efd`). `verify_070.py` проверяет каждый манифестный SHA и отсутствие исполняемых вредных/боевых вызовов в **новом исходном коде**.
