# BGXAI 042B — опытный *ограниченный по времени* контроллер охраны

**SOURCE ONLY. НЕ УСТАНАВЛИВАТЬ ВРУЧНУЮ. В игре пользователя по-прежнему работает BGXAI 041.**

## Почему создан второй вариант

В действующем EPS 18.4 две ветки обычного autoattack вызывают `Attack()` (compiled ID 3), который по IESDP продолжает атаку до смерти цели и может удерживать очередь непустой, из-за чего отложенная охрана (`ActionListEmpty + ProtectObject`) не получает управление. Одной перестановки приоритетов 042A недостаточно для уже действующей атаки.

## Что делает офлайн-прототип 042B

Сначала безопасно применяет 042A: перемещает ровно 11 защитных блоков из конца `BDDEFAI.BCS` на позиции **1032–1042**. Затем **только в двух конкретных** блоках EPS, ставших №1043 и №1056, заменяет один compiled action ID `Attack(3)` → `AttackOneRound(105)`. Все остальные 1055 CR-блоков не меняются по содержимому (а перенесённые защитные блоки не изменяются вообще). Оригинальный SHA256 проверяется строго до любой трансформации.

Стандартная документация IESDP: `AttackOneRound()` в отличие от `Attack()` и `AttackReevaluate()` имеет условие прекращения после одного раунда и позволяет `ActionListEmpty()` стать истинным, после чего следующий проход скрипта может выбрать Guard. Новый приоритет — Guard → AttackOneRound, но *только когда очередь свободна*.

## Точность и ограничения

- В исходном BCS 2 229 760 байт и 1057 блоков. SHA256 `86d80953be464a3f10da8e1dc031b907801860b7f1f15b3ea6fb9d25e485f3f5`.
- Офлайн-preview 042B: 2 229 764 байта и 1057 блоков; SHA256 `8602e8853a9c0e8b1bd5733021e6dd9c9ac73e03beb6c9900ef6ebd09dacb9a0`.
- Ручную очередь скрипт никогда не очищает, команды не прерывает, а две автоматические атаки становятся короче: это меняет игровую тактику *EPS* и требует реального теста перед выпуском.
- Текущая исполняемая при загрузке сохранения старая команда `Attack()` может остаться активной до смерти цели. Скрипты иных слотов и EEex-заказы могут также назначать непрерывные действия — они не охвачены.
- Офлайн-регрессии НЕ доказывают действительное выполнение в EET, корректное взаимодействие с бардовской песней или локальным WeiDU 25100. Для боевого релиза нужны резервная копия BCS и надёжный WeiDU rollback с проверкой установки 041 и строгой проверкой хеша. Никакого автообновления в играемую сборку 042B пока нет.

## Проверки

`python -m unittest discover -s tests -v`: 50/50 офлайн-тестов, проверяют старую 042A и новую 042B, неизменность всех блоков, строго только два изменённых action ID и поведение очереди лишь в условной модели.

Публичный GitHub содержит **исходники**, не сам игровой BCS: нельзя публиковать пользовательский compiled script. Постоянный `BGXAI_UPDATE.cmd` не менялся. Сами исходники и манифест доступны в постоянной библиотеке проекта.
