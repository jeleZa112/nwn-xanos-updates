# BGXAI 065 — Live API gate R1 (SOURCE ONLY, игра не изменяется)

Дата: 12 ноября 2026. Основание: реальный скриншот EET v2.6.6.0 после `BGXAI65_CLASS_HP_CONSOLE.lua`.
В четырёх занятых портретах P0–P3 класс/ОЗ прочитались успешно:
P0 `2:14/14`; P1 `1:14/14`; P2 `5:6/6`; P3 `3:8/8`.
P4–P5 `API_ERROR` при фактически пустых слотах. У исходной команды проверка только `if not id`, что не отбрасывает truthy sentinel вроде `-1` или `4294967295`. Такое значение — вероятная, но не доказанная по одному скриншоту причина. На чтение класса/ОЗ действующих персонажей это не влияет.

## Добавлено

- `BGXAI65_CLASS_HP_CONSOLE_R1.lua` — разграничивает empty-ID sentinel (`absent`), валидный идентификатор без объекта (`OBJECT_MISSING`) и сломанные поля (`API_ERROR`). Это новый исходник: старая команда и неизменяемый пакет 065 не перезаписываются.
- `BGXAI65_POLICY_SNAPSHOT_GATE.lua` — следующий *только читающий* тест дополнительных полей, которые использует пассивный `BGX65Policy.partySnapshot`: `m_id`, `m_pos.x`, `m_pos.y`, `BGX38_GUARD` посредством `getLocalInt`, `m_nModalState`, наличие `m_pArea`. Для пустых слотов вывод `absent`; при исключениях `FIELD_ERROR`. Не вызывает игрового ИИ и не меняет файл/LOCALS/WeiDU.
- `test_065_live_gate.py` — 10 unit-тестов в нативной Lua 5.4, моделирует 4 занятых слота, пустые sentinel, ошибки API, несоответствия объекта, запрет команд.

## Что реально подтверждено

Данные класса/ОЗ работают в пользовательском EEex x64 для четырёх персонажей. Нет оснований считать **065 установленной**: в EET продолжает работать 064, с подтверждённым одиночным F-охранником. Распределение нескольких охранников, ранний перехват до удара, режимы магов и EPS — всё ещё только разработка.

## Следующее необходимое живое доказательство

В игровой Lua-консоли при существующей партии и обычной паузе выполнить **одну строку** `BGXAI65_POLICY_SNAPSHOT_GATE.lua` (скопировать содержимое, не имя). Это необязательный диагностический этап, не запуск обновления. Прислать строки `BGX65G P0...P5`; так будет ясно, читаются ли все дополнительные поля, прежде чем выдавать реальный план распределения охраны. До этого можно продолжать офлайн-планирование, но НЕ активировать 065 в игре.

Все файлы только для исходного аудита, не применять к `override`. Не запускать BGXAI_UPDATE.cmd для этих файлов; действующий pinned updater и установленный BCS/Lua сохраняются.
