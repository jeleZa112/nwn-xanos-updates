# Проект BGXAI 042 — согласование охраны с EPS

## Доказанные результаты

- Тарана и гном при `F`=ВКЛ, **личной автоатаке EPS=ВЫКЛ** и общей кнопке ИИ=ВКЛ вмешались, когда Шанк атаковал Джейд. Пользователь подтвердил в игре.
- При автоатаке=ВКЛ оба тоже атаковали Шанка, но источник атаки не различим. Это **не подтверждение** работы охраны одновременно с автоатакой.
- Блоки охраны BGX38/39 расположены в конце `BDDEFAI.BCS` и требуют `ActionListEmpty()`; голова EPS может выдавать долгосрочную `AttackReevaluate`, которая не освобождает очередь.
- В прежнем архиве EPS `BDDEFAI.BCS` есть строка `BDAI_ATTACK_MODE` (локальное состояние автоатаки). Она может не совпадать по версии с живой EET (2026), поэтому обязательно проверить скрипт живой игры.

## Выбранный безопасный алгоритм (ПОКА НЕ УСТАНОВЛЕН)

1. При `BGX38_GUARD=0`: EPS действует без изменений, включая автоматическую атаку.
2. При `BGX38_GUARD=1` и прямой угрозе союзнику: защитный маршрут имеет приоритет над **только автоатакующими** ветками EPS; оттуда переход к существующему `ProtectObject` из BGX38/39.
3. При включённой охране, но отсутствии угрозы: не спамить `ProtectObject`, не сбивать ручные команды, лечение и касты. Отдельно определить нужность самостоятельной атаки без угрозы — действующая охрана этого не гарантирует.
4. **Не** использовать повсеместно `ClearActions()`, `ActionOverride(Myself,...)`, `!ActionListEmpty` и постоянный `ProtectObject` без доказанной защиты ручных действий/модальных состояний (песня барда, обнаружение ловушек).
5. Кандидат патча для конкретного установленного EPS: только в доказанных ветках *автоматической атаки* добавить `!Global("BGX38_GUARD","LOCALS",1)`; не трогать остальные ветки, сохранить настройку EPS и одиночное переключение `F`. Однако пока не известен локальный BAF/BCS контекст, нельзя безошибочно заменить целевые блоки через WeiDU.
6. Если оказывается, что `BDAI_ATTACK_MODE` управляет скриптом, чей `AttackReevaluate` уже не выходит, одной защиты веток недостаточно: понадобится аккуратный способ отменить **только** автоматический приказ, а не произвольный ручной. Без данных не включать его в релиз.

## Граница безопасного выпуска

Мод 042 будет публиковаться только после аудита актуального файла `override/BDDEFAI.BCS`, подготовки проверяемого патча по конкретным блокам, сохранения резервной копии и отдельного механизма отката. Текущие 0381/039/040/041 **не трогаем**. Ниже прилагается `scan_eps_bcs.py`, который считывает бинарный BCS и выдаёт индексы и типы блоков, ничего не меняя.
