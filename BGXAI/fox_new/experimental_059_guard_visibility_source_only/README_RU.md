# BGXAI 059 — безопасный фильтр доступности охранника (SOURCE ONLY)

Дата: 11 ноября 2026. Основа: BGXAI 056, источник `BGXAI/fox_new/experimental_056_active_guard/BGX56/M_BX43.lua`; 058 — отдельный ранее подготовленный фильтр одной ARE. **059 пока не установлен в EET и не имеет подтверждённого игрового результата.**

## Почему делаем

В живом тесте Шанк ударил Jade (P3) в помещении, а выбранный Lua защитник P4 находился снаружи; `H=1 HE=0 A=1 P=1`, `G=P4 V=P3 F=1 Q=3 MOD=0 TTL=82`. Передача LOCALS сработала, исполнение ProtectObject не доказано. По исходнику 056 выбор происходит только по F, MOD и относительному расстоянию и не проверяет, что защитник реально видит союзника.

## Изменение

Файл `BGX59_ELIGIBILITY.lua` — независимый исходник чистого выбора. Перед принятием защитника требует:

1. Ненулевых `guardian.m_pArea` и `victim.m_pArea`, подтверждённого `EEex_UDEqual(ga,va)` (сравнение реальных engine userdata областей, а не вычисление расстояния между координатами разных карт).
2. Доступного штатного EEex `EEex_Sprite_ForAllOfTypeStringInRange(guardian,"[ANYONE]",128,callback,true,false)`: наблюдения жертвы внутри 128-пиксельного ограниченного радиуса при включенной проверке LOS.
3. Если проверка невозможна/ошибочна, **нет запроса**; никакой телепортации, попытки пройти сквозь стену, отмены действий или изменения LOCALS.
4. При наличии нескольких допущенных защитников — ближайший, при равенстве портрет с меньшим индексом. Наличие допустимого кандидата **не гарантирует** выполнение BCS, который отдельно требует ActionListEmpty, видимого врага, TTL и Range(PlayerN,10).

В GitHub после проверки сохраняется интегрированный исходник `BGXAI/fox_new/experimental_059_guard_visibility_source_only/M_BX43.lua` на основе 058 и вставленного фильтра. Он **не предназначен для ручного копирования в override**. Нужны последующие сверки WeiDU/EEex 1.2.0, безопасный opt-in установщик с SHA и rollback и отдельное разрешение перед установкой.

## Проверка без доступа к игре

`python run_lua54.py` — 9/9 PASS, настоящий `liblua5.4` с моками engine EEex. Запускал на Linux. Это **не тест LuaJIT/EEex/BCS в игре**. Во время запуска ни один игровой файл не изменён.

`test_059.lua` покрывает разные ARE, альтернативного ближайшего допустимого охранника, стену/LOS, неполную ARE, отсутствие/ошибку EEex, равенство расстояния, пустой список и отсутствие команд изменения игры. Инвариант безопасности: источник фильтра не содержит `setLocalInt`, `ProtectObject`, `Attack`, `ClearActions`, `ActionOverride`.

Дальнейшая задача: проверить совместимость добавочного EEex запроса в синхронном обработчике ударов на установленной версии без принудительного боевого испытания; не объявлять ошибку BCS устранённой по успешным мокам.
