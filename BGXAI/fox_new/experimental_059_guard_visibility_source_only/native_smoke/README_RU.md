# BGXAI 059 — нативная проверка ARE/LOS на EEex 1.2.0 (только чтение)

**Дата:** 11 ноября 2026. **Установка:** НЕ требуется, НЕ выполнена. Установленной остаётся BGXAI 056.

## Подтверждённый игровой результат

Пользователь в EET v2.6.6.0 выполнил:

`C:DisplayText("AREAAPI="..tostring(type(EEex_UDEqual)).." SIGHTAPI="..tostring(type(EEex_Sprite_ForAllOfTypeStringInRange)))`

Скриншот показывает `AREAAPI=function SIGHTAPI=function`. Обе функции существуют в установленном EEex; фактическое выполнение native LOS ещё не проверялось.

## Следующий безопасный эксперимент (один раз, без боя)

Вставить **точное содержимое** `BGX59_NATIVE_SMOKE_READONLY.lua` в уже используемую Lua-консоль EET. Это один Lua-оператор, который сравнивает выбранных ранее охранников P2 и P4 (портреты с индексами 1 и 3) с Jade P3 (индекс 2). Число проверок LOS ограничено двумя, радиус 128 пикселей. Никаких боевых приказов, переменных LOCALS, установки, записи файлов или смены состояния игрового мира.

Поле `ARE` — сравнение текущих `m_pArea` через `EEex_UDEqual` (`true` означает одинаковый объект области). `LOS` — найден ли идентификатор Jade среди объектов `[ANYONE]` на расстоянии до 128 пикселей, с включённой проверкой линии зрения. `OK` — сработал ли API поиска видимых существ без Lua-ошибки. При `ARE=false` функция LOS не вызывается и `OK=false` **ожидаемо**, это не авария. `ARE=true LOS=false OK=true` означает, что поиск отработал, но Jade не найдена в малом радиусе (дистанция, стена, особенности выборки и т. п.). `ARE=true LOS=true OK=true` — положительное подтверждение выборки видимости в данной игровой ситуации.

Проверка не доказывает, что вызов API безопасен **внутри синхронного weapon-hit hook**. Поэтому это шаг до установки 059, а не разрешение на установку.

## Офлайн-регрессии

`python test_native_smoke.py` использует системную `liblua5.4` через ctypes (без `pip`). 10/10 проверок PASS:
- обе цели в одной зоне и видны;
- P4 в другой области;
- P2 не видит цель;
- API поиска отсутствует;
- API поиска бросает исключение;
- отсутствует объект охранника;
- отсутствует объект цели;
- сравнение областей возвращает false;
- сравнение областей бросает исключение;
- отсутствие вызовов изменения LOCALS/боевых команд.

Это мок EEex, не настоящий игровой runtime.
