## Выявленный проектный риск

Исходная пассивная политика 065 может назначить любого ближайшего F=ON в качестве primary guardian, включая мага/жреца, поскольку выбор не разделён на frontline и support. Это **не означает**, что 065 установлена в игре: в живой 064 выбранный F=ON может получить обычную реакцию после подтверждённого попадания.

По текущей живой партии F=ON у **мага P1** и **жреца P3**. Нельзя автоматически делать из них ближних перехватчиков только потому, что F=ON. Точный боевой профиль может изменяться китом/модовым переобучением и оснащением, поэтому предложена безопасная промежуточная классификация.

## Создано

`BGXAI65_ROLE_COORDINATION_R2.lua`:

- Берёт **только** проверенный список угроз из неизменного `BGX65Policy.plan`. Фальшивые атакующие из партии, неизвестные жертвы и непроверенный сигнал до удара отклоняются в базовой политике.
- Отделяет `frontlineAssignments` от `supportAssignments`. Фронтового кандидата без подтверждённой боевой способности назначает только при F=ON, modal=0, классе типа tank по текущему CLASS.IDS, ОЗ выше 50%, присутствии в той же ARE и наличии координат. Даже он отмечен **unverified_weapon**: это не приказ атаковать.
- Маг/жрец/бард с F=ON (если роль в текущей политике относится к caster) получает только **control / healing / protective кандидатство**, без доказанных заклинаний или выбора целей для каста. Если caster сам под ударом, критически ранен, находится в другой зоне, F=OFF или занят — не назначается.
- Если угроз две, сначала предлагает распределить разных свободных кандидатов поддержки на разные цели по срочности; при одной угрозе допускает несколько пассивных предложений поддержки. Никакого одновременного запуска магии/приказов нет.
- По непрочитанной AREA, плохому здоровью, ошибке сравнения, неизвестным данным действует fail-closed.
- Всегда `mode=ADVISORY_ONLY`, `ordersSent=0`, `isInstalled=false`, `dispatchEnabled=false`; **без LOCALS / атак / кастов / override / WeiDU**.

На моделируемых данных 4 персонажей со скриншота для одной угрозы P2: `frontlineAssignments=0`, `supportAssignments=2` — mage P1 кандидат контроля, cleric P3 кандидат поддержки. Это НЕ результат боевого теста и НЕ означает, что текущее игровое поведение 064 изменилось.

## Чего R2 пока НЕ делает

НЕТ активной координации в игре, нет определения до удара точного enemy target (EEex resolver), проверки memorized spells/active items/дальнобойного вооружения, проверенной совместимости с EPS при назначении приказов, управления bard songs, выученных способностей respec и врагов SCS. Не прошла реальная установка, нет нового BCS/TP2. Модельные тесты подтверждают логику рекомендации, а не работу настоящего EEex боевого сценария.
