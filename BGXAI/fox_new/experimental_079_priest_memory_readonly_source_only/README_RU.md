# BGXAI 079 — чтение фактических приготовленных жреческих заклинаний (read-only, SOURCE ONLY)

**Состояние:** EET + EPS 18.4 + SCS 35.21 + EEex 1.1.7, в игре подтверждённая 066S. 067 — HOLD, 078 и 079 — OFFLINE SOURCE ONLY; игра не изменена, ничего не установлено. Продолжение 078 выполнено в этом же обращении, без ожидания новой команды.

## Новый источник достоверных сведений

Обнаружен пример разработчика EEex **Bubb** на Beamdog Forums (апрель 2023): у современных sprite есть `m_memorizedSpellsPriest`, уровни получаются через `getReference(0..6)`, перебор `EEex_Utility_IterateCPtrList`, resref читается `EEex_CastUD(memorizedSpell.m_spellId,"CResRef"):get()`, а признак использованного слота — `EEex_IsBitUnset(memorizedSpell.m_flags,0)`. Источник: https://forums.beamdog.com/discussion/71798/mod-eeex-v0-10-2-alpha/p44 .

**Важное ограничение:** это пример разработчика, а не проверка API именно пользовательской EEex 1.1.7. Старые `EEex_GetMemorizedClericSpells(actorID)` в документации `engine-x86` НЕ подставляются без проверки совместимости с x64. Для экспериментального модуля применён инъецируемый read-only API-контракт, исполняемый на моках. Нельзя выдавать `m_flags` за полную проверку способности кастовать сейчас.

## Файлы и поведение

- `BGXAI079_PRIEST_MEMORY_READONLY.lua`: по явному проверяемому resref перебирает 7 списков жреческой памяти, считает запомненные и неиспользованные слоты, ловит ошибки и неизвестные структуры. **Не устанавливает `spell.usable_now=true`**: окаменение, немота, блокировка дуала, аура или занятый EPS могут не дать выполнить заклинание.
- `BGXAI078_HEAL_SELECTOR.lua`: исходник проверенной 078 скопирован **побайтно** только для независимого тестирования совместной безопасной логики.
- `test_079.lua`: **27/27 PASS**; проверены испорченные/недоступные указатели, отсутствие spell, использование слотов и передача 079→078 (проверка не выдаёт команду по одной только памяти).
- `test_079_contract.py`: **7/7 PASS**, статический no-engine-write и нативный Lua тест.
- `verify_release_079.py`, `manifest_sha256.json`: SHA256 источников.

## Следующая граница

Нужны достоверные runtime данные о текущем action/EPS queue, BCS `HaveSpell`, `Range(PlayerN,10)` и состоянии dual/формы, без доступа к которым 078/079 могут только **советовать**, но не должны инициировать cast. Следующее безопасное исследование — проверить API источника действия и сопоставления BCS-условий на реальной EEex; мод устанавливать можно только отдельно после guarded back-up и согласия пользователя. Не повторять 075, 076R1, Шанка и старые выгрузки.
