# BGXAI 085 — автоматический контроль защитных условий BCS

**SOURCE ONLY / READ ONLY.** Никаких изменений в EET, WeiDU, EPS или существующем скрипте. Последняя установленная 066S.

Проверены по исходникам на GitHub три существующих блока: `BGX61_RECEIVER.baf` — 20 IF блоков (2 служебных, **18 правил с игровыми действиями**), `BGX66_CASTER_RECEIVER_SOURCE_ONLY.baf` — 11 блоков (4 служебных, **7 игровых**), `BGX67_EARLY_GUARD.baf` — 8 блоков (2 служебных, **6 игровых**, версия 067 **не установлена**). Во всех 31 правилах с действиями присутствуют `ActionListEmpty()`, F guard ON и `ModalState(NONE)` в условной секции. У 061 игровой приказ `ProtectObject` встречается 6 раз — его обязательно считать полноценной командой, а не служебной очисткой.

`BGXAI085_BCS_GATE_AUDIT.py` проверяет произвольные BAF-файлы автоматически, без ручного подбора слов: парсит блоки IF/THEN/END, различает безопасную очистку и действия (включая `ProtectObject`), требует нативную проверку очереди, включённую F-охрану, отсутствие modal state и живой TTL запроса. Для заклинаний дополнительно требует `HaveSpell`. Неизвестные команды требуют отдельного разбора, а не получают автоматический PASS. При проблеме возвращает код ошибки 2 и JSON с номерами блоков.

Запуск только в безопасной отдельной папке с BAF-исходниками:

```sh
python BGXAI085_BCS_GATE_AUDIT.py path/to/BGX61_RECEIVER.baf path/to/BGX66_CASTER_RECEIVER_SOURCE_ONLY.baf
python -m unittest -q test_085.py
python verify_release_085.py
```

## Критический вывод

В 066S/061 **проверки занятости очереди уже присутствуют**, поэтому слепое добавление такой же проверки не исправит запаздывающую охрану. Следующее реальное улучшение связано с *моментом возникновения запроса* и *приоритетом охраны/лечения относительно EPS*: возможен порядок, когда 066S или 061 получает очередь раньше автобафа EPS. Это пока только архитектурный риск, а не доказанный конфликт в игре. Требуется отдельная модель расписания действий и тест на игровом стенде до любой новой установки. Достоверный ручной источник команды не установлен, поэтому 080/082 остаются HOLD.

Статический PASS — не разрешение на установку, не доказательство работы EEex или того, что пользовательские приказы не прерываются. Правило №7: после безопасного PASS следующий безопасный шаг выполнять самостоятельно в активном обращении. Для любой игры — только отдельное разрешение, exact SHA, preflight и backup.
