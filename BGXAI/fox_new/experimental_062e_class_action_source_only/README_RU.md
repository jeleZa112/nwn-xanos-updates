# BGXAI 062E — read-only class/action observer (source only)

Дата: 2026-11-12. **Не установлен и не включён в загрузчик EEex. Рабочий BGXAI 061 не изменялся.**

## Задача
Наблюдать за реальными идентификаторами класса и мгновенного действия игровых персонажей, **не утверждая**, что на их основе уже известны навыки и ручные приказы.

### Источники и статус доказательств
- EEex x64: `sprite.m_typeAI.m_Class` — документированный пример доступа к class ID (форум Beamdog, пост по переходу old-to-new EEex, версия v1.2.0/v1.3.1): https://forums.beamdog.com/discussion/71798/mod-eeex-v1-2-0/p41
- Используемое ранее поле `m_curAction.m_actionID` встречается в существующем исходнике моста BGXAI 059; означает сиюминутный action ID, **не** свободную очередь EPS или отсутствие пользовательской команды. Исторический 059 не приравнивать к установленной Lua 061.
- Точная сборка EEex пользователя, допустимые диапазоны id и корректность class/action при dual/respec в живой игре **пока не проверены**. Поэтому provenance `RUNTIME_UNVERIFIED`; нет назначения ролей.

## Реализация
- `BGX62E_CLASS_ACTION_PROBE.lua`: возвращает функцию `snapshot()` и **сам ничего не запускает**. В пределах шести portrait slots, через pcall: ID, F, modal, class_id и current_action_id. Нет API записи, переключения охраны или регистрации callbacks. Любые недоказанные способности, оружие, ручные приказы, очередь и stealth остаются `unknown`.
- `class_action_contract.py`: строгая валидация schema=2, provenance, слотов, идентификаторов, границ чисел; Boolean не принимается за игровое число. Любая попытка объявить возможности/ручной контроль подтверждёнными отклоняется. `intercept_authorized` **всегда False**.
- Ранее созданные 062B/C/D модули и проверки оставлены в комплекте для регрессии.

## Проверка
`python -m unittest discover -v`: **84/84 PASS**. Это синтетические Python тесты и текстовый аудит Lua. На пользовательском ПК реальный Lua/EEex не запускался; Lua VM компиляции в среде нет. Эти проверки **НЕ** доказывают работу кода в EET.
