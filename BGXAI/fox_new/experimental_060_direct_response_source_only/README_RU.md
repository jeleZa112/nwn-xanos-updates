# BGXAI 060 — исполнитель реакции на удар, поверх EPS 18.4

Состояние 11.11.2026: **отдельный экспериментальный исходник + защищённый кандидат установки, НЕ УСТАНОВЛЕН.** Существующие 056 Lua/BCS и все настройки EPS не затронуты.

## Что исправляем

В живом бою EEex подтвердил попадание по Jade, Lua выставил `BGX52_REQ_SLOT=3` у охранника P4 (`H=1 HE=0 A=1 P=1 Q=3 TTL=82`). Значит, механизм детекции и передачи **уже работает**. Следующий узкий элемент — BCS приёмник. В 056 он требует `See(NearestEnemyOf(PlayerN))` и `Range(NearestEnemyOf(PlayerN),7)`, причём *NearestEnemyOf* не обязательно является фактическим нападавшим. Реально исключивший запуск триггер всё ещё не доказан.

058/059 проверяли area/LOS. Живые результаты для P2/P4 относительно Jade `ARE=true LOS=true OK=true` указывают, что **059 не следует считать исправлением данного отказа**. Новый выпуск не опирается на 059.

## Новая схема 060

**Оставить EPS 18.4** для лечения, заклинаний, экипировки, песен, переключателей. Оставить **056 Lua** для регистрации подтверждённого попадания и записи Q/TTL. Заменить **только восемь собственных блоков BCS приёмника 056** на 14 адресных блоков:

1. Два исходных правила очистки просроченных и выключенных F запросов.
2. Шесть адресных блоков **прямого ответа**: если есть Q по пострадавшему PlayerN, охранник с F=ON свободен, видит союзника и реального последнего атакующего — выполнить `AttackReevaluate(LastAttackerOf(PlayerN),30)`. Не выбирать `NearestEnemyOf(PlayerN)` вслепую.
3. Шесть **резервных** блоков: если прямой ответ не подходит, но охранник видит и находится рядом с PlayerN — `ProtectObject(PlayerN,6)` без лишнего условия видимости какого-то «ближайшего врага».

Оба ответвления маркируют `BGX60_LAST_BRANCH=1/2` и `BGX60_LAST_VICTIM=N` в LOCALS. Это маркер **начала BCS ветви**, не гарантия попадания/победы. Не вызываются ClearActions, ActionOverride, принудительная магия. Проверка `ActionListEmpty` и `ModalState(NONE)` сохраняет приоритет ручного приказа / уже идущего каста. Прямая атака может занять очередь дольше, чем число `30` — IESDP предупреждает, что `AttackReevaluate` не обязательно завершится по истечении 30 тиков. Это пока экспериментальный компромисс.

## Содержимое

- `BGX60_RECEIVER.baf` — полный новый 14-блочный фрагмент.
- `generate_baf.py` — детерминированное создание исходника (не работа с игрой).
- `BGXAI60_BUILDER.py` — компиляция фрагмента с **штатным** WeiDU и IDS игры во временной папке; строго требует хеш установленного 056 и побайтно сохраняет остальные 1057 BCS-блоков.
- `BGXAI60_INSTALL.py` — кандидат установки **только BCS** через WeiDU и `BGX60` с внешней резервной копией; по умолчанию только статус. Установка/откат требуют двойного подтверждения; до инсталляции проверяются closed-game, WeiDU последняя запись 056, SHA Lua и BCS, источник BAF, отсутствие коллизий.
- `test_060.py`, `test_060_install.py` — всего 20 офлайн-тестов с искусственным BCS и WeiDU-моком. Тесты не подтверждают компиляцию с настоящими IDS/EEex на компьютере игрока.

## Следующий фактический шаг

Первый тест **не бой**: при закрытой игре выполнить из защищённого обновлятора read-only `preflight`, который скомпилирует BAF реальным WeiDU и сравнит подготовленный BCS с подлинным установленным 056. Если блок `LastAttackerOf(PlayerN)` не компилируется, выпуск останавливается без игры и отката. **Только после успешного preflight** можно предлагать отдельную подтверждённую установку BGX60. Сначала один короткий игровой тест, а не десятки проб.

Никаких повторных загрузок WeiDU.log, scripts.zip, EET-архивов или ресурсов не требуется. Не копировать BAF/BCS вручную в `override`; не менять `BGXAI_UPDATE.cmd` на непроверенную копию.

## Одна проверка на реальной Windows

Разархивировать `BGXAI_060_DIRECT_RESPONSE_SOURCE_ONLY.zip` **в отдельную папку вне `C:\Games\BG_EET_FOXX_NEW`**; закрыть игру и InfinityLoader; двойным щелчком запустить `BGXAI60_PRECHECK_READONLY.cmd`. Он выполняет `py -3 BGXAI60_INSTALL.py preflight` и печатает результат. **Только проверка и компиляция во временной папке, без установки**. Скопировать текст результата в чат. Пока не запускать `BGXAI60_INSTALL.py install` самостоятельно. Штатный `BGXAI_UPDATE.cmd` не заменять.
