# BGXAI 066S guarded upgrade — TWO-FILE CANDIDATE, NOT INSTALLED

Статус: **SOURCE ONLY / OFFLINE TESTED**. Пользовательская EET остаётся на **BGXAI 064**. Это независимый кандидат над именно 064, а НЕ над промежуточной 066.

## Что улучшено

- `BGX66_CASTER_SUPPORT.lua`: после подтверждённого попадания по союзнику может назначить жрецу F=ON запрос на лечение персонажа с ОЗ менее 45%; при критических ОЗ (≤25%) у мага F=ON может запросить `Shield` себе. Это запрос, а не непосредственная команда `Spell` из Lua.
- `M_BX43_066S_CASTER_CANDIDATE.lua` воспроизводимо собран из 066 multi-frontline Lua и 066S поддержки; один существующий EEex weapon-hit listener, без нового перехвата или изменений EPS-скрипта в Lua.
- `BGX66_CASTER_RECEIVER_SOURCE_ONLY.baf`: 11 BCS-правил, включая очистку устаревшего запроса, 6 вариантов лечения и самозащиту мага. Перед фактическим применением заклинания BCS проверяет `HaveSpell`, F=ON, `ActionListEmpty()`, `ModalState(NONE)`, HP, `See/Range`, TTL и cooldown. Выбор конкретного `Cure Light Wounds`/`Shield` по типу угрозы, уровню и слотам пока не реализован; нет общего SCS-анализа и полноценного ИИ.
- `BGXAI66S_BCS_PATCH.py`: сверяет точный хеш реального BCS 064, 1065 старых блоков и все 8 блоков старого охранного приёмника; компилирует 11 новых BAF-блоков через временную копию **локального WeiDU** и IDS установленной EET; вставляет новый фрагмент перед оригинальными правилами 042B/EPS. Сохраняет все старые блоки побайтно и доказывает обратное получение исходного BCS.
- `BGXAI66S_INSTALL.py`: предварительная **READ-ONLY** проверка, внешний SHA-верифицированный backup, установка ровно двух файлов через WeiDU, защищённый статус и откат к 064 при сохранении последней записи WeiDU. Никакой автозаписи в игру при распаковке архива.

## Проверки

- Тесты исходного Lua 066S: 18 из 18 на нативном Lua 5.4 с моделью EEex (не реальные игровые события).
- Новый установщик и внедрение BCS: 21 из 21 модельных тестов на временной синтетической установке — включая двухфайловый install/rollback, отсутствие записей при preflight, отказ при другом последнем WeiDU или изменении SHA, запрет ложного успеха и обнаружение одновременной подмены live/staged BCS.
- Итого **39/39** model/native tests PASS.
- Действующий source-only 066S BAF ранее проверен реальным WeiDU 251 с СИНТЕТИЧЕСКИМ набором IDS. Добавлен отдельный CI-прогон для проверки двухфайлового TP2; не утверждать, что уже выполнен, пока workflow не подтвердит.
- **Критическое ограничение**: реальную компиляцию новых BCS с текущими `IDS` **твоей** установки и игровые действия можно доказать только на пользовательском ПК. Пока такого подтверждения нет, новый пакет **не должен устанавливать игру** или заменять действующий обновлятор.

## Безопасные шаги

Для разработки/CI (не на основной игре):

```
python -m unittest -q test_066s_installer_mock.py test_066s_caster_native.py
python build_066s.py
python ci_weidu_066s.py
```

Для этапа интеграции на пользовательском ПК через привычный однофайловый BGXAI updater — только после проверки Windows updater и явно выбранного read-only preflight. Установку можно разрешить отдельно, написав `INSTALL_BGXAI_066S`; rollback — только с собственным подтверждением `ROLLBACK_BGXAI_066S`. Самовольных установок/обновлений нет.

## Проектное правило

Не останавливать разработку на `PASS` и не требовать `+` после тестов: следующий безопасный инженерный шаг выполняется в этом же активном обращении. Пользователь участвует лишь в установке/тесте на своём ПК, когда удалённого доступа нет. Не утверждать, что процесс продолжается в фоне после окончания ответа.
