# BGXAI 054-R3 — исправление неинтерактивного запуска WeiDU (SOURCE ONLY)

**Внимание: НЕ предлагать пользователю ещё один повтор пункта 54, пока нет независимого теста на настоящем Windows WeiDU и EET.**

## Проверенные симптомы

- Первая попытка: `REQUIRED_LOG_OR_TLK_MISSING` — R1 исправил определение языка.
- Вторая попытка: `Not a game directory` — R2 запускал WeiDU в каталоге игры.
- Третья попытка: `COMPILER_ERROR` со строкой `Command [...]`; это соответствует `subprocess.TimeoutExpired` (тайм-аут 90 с). На запуск был передан **`setup-enhanced-powergaming-scripts.exe`**, имя `setup-*` по спецификации WeiDU автоматически подхватывает TP2. Не было `--no-auto-tp2`, `--no-exit-pause`, закрытия stdin.

Документация WeiDU: https://weidu.org/WeiDU/README-WeiDU.html (автоматический запуск TP2 при имени setup-*); https://the-mod-elephant.github.io/weidu/ (параметры --no-auto-tp2 и --no-exit-pause).

## Исправление R3 (не установка)

- Копируем существующий доверенный WeiDU-251 exe побайтно, с SHA256, **только во временную папку** как `weidu.exe`; оригинальный setup-скрипт не запускается.
- Подавляем поиск `.tp2` параметром `--no-auto-tp2`, паузу выхода `--no-exit-pause`, самообновление `--noautoupdate`; перенаправляем `--log` во временный каталог.
- Запускаем с `cwd=game_root` для загрузки IDS, но входной `BX52CHK.baf`, выход и exe находятся *вне игры*, во временной папке.
- Закрываем stdin через `subprocess.DEVNULL`. Если WeiDU висит дольше 25 секунд, записываем **явный** `COMPILER_TIMEOUT` и последние сообщения, вместо обрезанного `Command [...]`.
- Перед попыткой работаем через контрольные суммы BCS, Lua, WeiDU.log, chitin.key, TLK, weidu.conf; после ещё раз сравниваем те же файлы. Установка TP2 и изменение установленной версии 049 запрещены.

## Проверки

`python -m pytest -q test_compile_054.py` — **27 passed**, включая запуск настоящего дочернего процесса с тестовым stand-in вместо WeiDU и имитацию зависания. Это НЕ эквивалент реального теста WeiDU 251 Windows с EET: он остаётся непроверенным.

## Решение

Код сохраняется как R3, без установки новых боевых компонентов. Не просить пользователя повторять старую команду, пока нет убедительной независимой проверки на реальном компиляторе и IDS. Ошибка не повреждала наблюдаемые файлы установленной 049 (по отчёту пользователя `live_unchanged=true`).
