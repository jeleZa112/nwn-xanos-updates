# BGXAI 082 — безопасная связка 080 + 081: происхождение команды и EPS

**SOURCE ONLY — НЕ УСТАНАВЛИВАТЬ**. В игре последняя подтверждённая версия **066S**; EPS 18.4 продолжает самостоятельно делать автобафы, лечение и тактические действия. Ни один файл активной игры не изменён.

У 066S подтверждены слушатель старта действий и наблюдение `m_actionID`, но `P.manualOriginKnown = false`, `origin_verifiable = false`, `queue_verifiable = false`. Адаптер 081 умеет лишь прочитать ID (или сообщить UNKNOWN). Он не доказывает, что очередь EPS пуста; нулевой ID не даёт такого доказательства.

`BGXAI082_QUEUE_GUARD_BRIDGE.lua` связывает 081 с координатором 080. До верифицированного EEex API он **устанавливает для любого персонажа `action_state.verified=false`, `origin_verified=false`, `queue_empty=nil`, `idle=false`**, независимо от благоприятных тестовых фактов. Координатор 080 в таком случае не отдаёт даже предполагаемых новых боевых распоряжений, а мост возвращает `HOLD_NO_ENGINE_DISPATCH`.

В комплекте нет WeiDU, хука, установки, записи LOCALS, BCS, копирования Lua в override, перехвата ручной команды или автоматического отката. Все модули являются чистыми тестируемыми функциями.

## Тесты

`texlua test_082.lua`: **765/765 утверждений PASS**, включая 49 комбинаций ID действий (0, атака, движение, неизвестные), явно ложные уверенные данные и случаи отсутствия данных. `python -m unittest -q test_082.py`: **14/14 PASS**. Контрольные суммы источников и отсутствие опасных команд проверяются отдельно в `verify_release_082.py`.

## Результат и следующая работа

Нельзя активировать 080 по одному лишь факту, что `m_curAction.m_actionID == 0`. На следующем этапе требуется достоверное реальное наблюдение очереди и источника команды **в EEex 1.1.7 на установленной EET**. Только после проверки API и согласованной защиты WeiDU/бэкапа возможен активный релиз. Вместе с 081 содержимое этого пакета даёт доказательство **отказа вмешиваться**, но не доказательство улучшения боевого ИИ в игре.
