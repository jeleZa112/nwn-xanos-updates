# BGXAI 049 — пассивные сигналы охраны (не боевой ИИ)

**Основывается на успешной игровой проверке BGXAI 048:** HITREG=true, CALLS=2, EVENTS=2, ERR=0.

Новый Lua-модуль сохраняет все функции 048 и при каждом подтверждённом EEex попадании врага по члену отряда добавляет ограниченную запись `guard_signals` в `BGX43Probe.snapshot()`.

## Что хранится

- `attacker_id` — ID нападающего из реального объекта EEex;
- `protected_id` — ID атакованного члена отряда;
- `candidate_party_ids` — ID остальных членов отряда **только в порядке портретов** (это ещё не назначенные защитники);
- `source_event_sequence` — связь с подтверждённым событием попадания;
- `guard_switch_state=UNKNOWN`, `line_of_sight=UNKNOWN`, `ability_to_intercept=UNKNOWN` — реальные режимы и доступность не выдумываются;
- `dispatch_status=DISABLED_PASSIVE_ONLY`, `action_command_sent=false` — никаких приказов персонажам.

Ограничение массива: не более 64 сигналов. Копии из `snapshot()` не изменяют внутренний буфер. Ошибка формирования совета не прерывает регистрацию попадания, а обработчик всегда возвращает `false` — урон и эффекты оружия не подавляются.

## Установка и откат

Установка исключительно по команде пользователя с явным YES, через существующий BGXAI_UPDATE.cmd после предпроверки. Меняется только `override/M_BX43.lua` через WeiDU; после 048, при закрытой игре. Резервная копия в `Documents\BGXAI49_SAFE_BACKUPS`.

## Игровая проверка

После установки и подтверждённого попадания врага по герою:

```lua
local s=BGX43Probe.snapshot(); C:DisplayText("VER="..s.version.." HITS="..s.weapon_hit_calls.." GUARD="..s.guard_signal_count.." ERR="..s.guard_signal_errors.." ORDERS="..tostring(s.guard_dispatch_enabled))
```

Ожидаем `GUARD>0`, `ERR=0`, `ORDERS=false`. Это **не доказывает**, что охрана автоматически защищает: исполнение приказов намеренно не реализовано в 049.

## Не затрагивает

042B, скрипты EPS/SCS, BCS, TLK, EEex bootstrap, игровые сохранения, систему переключения «Охрана». Во время офлайн-тестирования живую игру пользователя не трогали.
