# BGXAI 076R1 — исправленная read-only карта EPS и F-охраны

Дата: 14.11.2026. **SOURCE ONLY. НЕ УСТАНАВЛИВАТЬ В ИГРУ.**

## Причина исправления

На реальной установленной **066S** пользователь запустил исходник 076 и получил:

```json
{"status": "BLOCKED_NO_GAME_CHANGE", "reason": "USER_LIVE_075_MARKER_COUNTS_DRIFT"}
```

Это ложное блокирование из-за ошибки сравнения. Предыдущий анализатор 075 подтвердил SHA256 настоящего `BDDEFAI.BCS` (`fb435d82e6c3e0ebea1d6a9532753921bd5411d70ac0677dc1fd8ec483380476`), все 1088 блоков, исходную 064 после удаления 11 блоков, а маркеры `BDAI_ATTACK_MODE=60`, `MO_HealCast=11`, `BGX38_GUARD=37` подсчитывал **в 1077 старых блоках**. В 076 эти же цифры по ошибке сравнивались с маркерами **всех 1088 блоков**. Новые обработчики лечения 066S содержат дополнительные `BGX38_GUARD`, поэтому итог для 1088 закономерно больше старого 37.

## Исправление

- 076R1 **не ослабляет** SHA256 и структурные проверки 075. Тот же код 075 оставлен без изменений, ожидаемый SHA исходника `f1f46df61a168e489746c9bab369c46bb72b9bad40c635b5d6d355c66e22677a`.
- Одна и та же группа из **1077 старых блоков** используется для сверки 60/11/37; отдельные поля отчёта показывают количество маркеров в **11 новых** блоках и во **всём BCS**.
- Позиции BGX61 1032–1051, BGX66S очистка 1052–1055, лечение 1056–1061, щит 1062 проверяются независимо.
- Нет сетевых обращений из исполняемого скрипта, нет записи в игру, `BCS`, `WeiDU.log`, EPS, Lua, настроек F. При несовпадении настоящего SHA выводит `BLOCKED_NO_GAME_CHANGE`.

## Проверки

`python -m unittest -v test_076r1.py`: **24/24 PASS**. Включены 19 исходных тестов 076, 5 новых; новый регрессионный тест собирает синтетические 1088 блоков (1077 старых, 11 новых), включает старые 37 + девять дополнительных F-маркеров, воспроизводит неверный подсчёт 076 и доказывает, что исправленная проверка принимает структуру при подставленных **только в тесте** синтетических SHA. В командном запуске пользовательские SHA не подменяются.

`python verify_release_076r1.py`: проверяет SHA256 всех исходников, что 075 копия неизменна, и отсутствие функций записи в модуле анализа. Ни эти тесты, ни запуск прежней 075 не доказывают динамическое поведение движка при лечении/охране.

## Запуск на пользовательском Windows

Положить **оба файла** `audit_priority_076r1.py` и `verify_066s_live_075.py` в одну директорию (например, `%TEMP%`) и выполнить:

```powershell
py -3 "$env:TEMP\audit_priority_076r1.py" --bcs "C:\Games\BG_EET_FOXX_NEW\override\BDDEFAI.BCS"
```

Прежний 075 уже был проверен пользователем и лежал в `%TEMP%`; при запуске из GitHub закреплённых источников обязательно сверить SHA новых файлов. При статусе `READ_ONLY_066S_PRIORITY_POSITION_MAP_R1` прислать только JSON. Не загружать целиком большой BCS и не проводить повторный бой для этой диагностики.

**Не устанавливать 067–076R1 как активные моды. Живая установленная версия остаётся 066S.**
