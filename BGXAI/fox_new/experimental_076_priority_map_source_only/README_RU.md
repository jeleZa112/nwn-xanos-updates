Маркеры EPS attack=60, EPS heal=11, BGX38 F=37. **Это подтверждённая структура установленного BCS, не игровой успех лечения или перехвата.**

## Зачем 076

Раньше ошибки анализа BCS создавали неверные выводы о порядке EPS и BGXAI. Эта версия **ничего не устанавливает**, не пишет в игру и не импортирует Lua. Она читает *только* SHA-pinned `override/BDDEFAI.BCS` и печатает в консоли JSON с точными **1-based** номерами правил, содержащих известные имена маркеров.

Имеющиеся исходники 066S обосновывают диапазоны:

- 061 охрана: блоки **1032–1051**;
- 066S очистка запросов: **1052–1055**;
- 066S реактивное лечение: **1056–1061**;
- 066S щит мага: **1062**.

Упоминания `BDAI_ATTACK_MODE`, `MO_HealCast`, `BGX38_GUARD` — это лишь **маркеры**, а не доказанные факты выполнения атак/лечения/охраны. Относительный порядок правил в BCS не определяет заранее, выполнено ли условие и пуста ли очередь. В исходном BAF 066S семь блоков лечения/щита требуют `ActionListEmpty`; при занятой очереди это может задерживать дополнительную команду.

## Как использовать при необходимости

В распакованном каталоге пакета:

```powershell
py -3 .\audit_priority_076.py --bcs "C:\Games\BG_EET_FOXX_NEW\override\BDDEFAI.BCS"
```

`audit_priority_076.py` — **read-only**, без настройки «игнорировать SHA» в командной строке. На любом несовпадении останавливается с `BLOCKED_NO_GAME_CHANGE`. Результат можно отправить в ChatGPT, для анализа без новой установки. Ранее проверенную 075 повторно запускать не надо.

- `python -m unittest -q test_076.py`: **19/19 тестов PASS**, включая исторический настоящий 041 BCS, который правильно отклоняется как не 066S.
