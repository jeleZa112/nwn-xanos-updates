# BGXAI 047 — корректное разрешение цели AttackReevaluate через EEex

09.11.2026 в реальном EET на Шанке: `ATTACK IDS: 134:141756530>-1`.
В `BGXAI 046` обработчик получил 47 действий, 3 атакующих действия, но не записал событие — он читает только `m_acteeID.m_Instance`, хотя `AttackReevaluate` декодирует цель в `m_acteeID2`. Это подтверждено разбором движка автором EEex и исходником `EEex_Action_LuaHook_OnAfterSpriteStartedAction` (после начала действия).

### Исправление
- Для AttackReevaluate (134) и AttackOneRound (105) **предпочтение разрешённой** цели `action.m_acteeID2.m_Instance`, затем допустимому первому полю.
- Для остальных атак (3, 94, 98) сначала используется `m_acteeID`, затем `m_acteeID2`.
- ТОЛЬКО числовая, неотрицательная цель, совпадающая с актуальным ID портрета, попадает в `events`. Атакующий должен быть вне отряда. Никаких атак из неопределённого `-1`.
- `sprite.m_targetId` фиксируется **только как диагностическое поле**, не служит основанием для создания атаки: он может быть устаревшим.
- `snapshot()` показывает поле `target_source`, `target1`, `target2`, `sprite_target`, `reason`. Буфер ограничен 64 событиями, команды игровым персонажам не выдаются.

### Безопасность
- Существующие BGXAI 042B/043P/044/045/046, боевые BCS, EEex boot, TLK, UI и сохранения не затрагиваются. WeiDU-операция — замена только `override/M_BX43.lua`.
- Установка только при BGX46 последним в WeiDU, прежнем проверенном SHA256 `1c1e314e1f14a693fa0b10d7450e737447a992e9d7900fb7112437f75c26a6a3`; по явному `YES`, с резервной копией и проверкой хешей.
- Откат возможен только если BGX47 последний и целостность оригинальной резервной копии подтверждена. Никаких ручных операций с override.

### Как применять
В существующем `BGXAI_UPDATE.cmd`: пункты **38 — precheck**, **39 — source sync**, **40 — install YES**, **41 — status**, **42 — guarded rollback**. Сначала полностью закрыть игру и InfinityLoader. При BLOCKED/REVIEW — остановиться и прислать вывод.

После успешной установки — загрузить игру через InfinityLoader, короткая проверка в консоли: `local s=BGX43Probe.snapshot(); C:DisplayText("V="..s.version.." E="..#s.events.." LAST="..(s.last_attack and s.last_attack.reason or "none").." SRC="..(s.last_attack and s.last_attack.target_source or "none"))`.

Ограничение: целостность и Lua-логика проверяются на офлайн имитации EEex; в реальной игре наличие разрешённой цели зависит от конкретного объекта и момента вызова listener. Отчёт `EVENTS>0` заранее не гарантируем.
