Дата: 2026-11-12. Целевая игра: `C:\Games\BG_EET_FOXX_NEW` (EET 2.6.6.0, EEex 1.1.7, SCS 35.21, EPS 18.4, Insane).

**Статус:** в комплекте реализован активный механизм, готовый для *отдельно разрешённой* защищённой установки, однако **на ПК пользователя он НЕ установлен и не протестирован в реальном бою**. Последняя проверенная в живой игре — BGXAI 064. Существующий `BGXAI_UPDATE.cmd` пока не меняли; дополнительная запись в его меню — отдельный этап после native PowerShell parser precheck.

## Что реально изменилось в Lua-коде

* Точная исходная `M_BX43_064_BASELINE_READONLY.lua` SHA256 `bfee5278b5b69b1fb4a02e3fea321082b0238407789df83ec6bd2f78d7e19f4b` сохранена. Генератор `build_066.py` называет ошибкой любое отклонение от этой базы.
* Вставлен `BGX66_TEAM_BRIDGE.lua` перед единственным вызовом `P.init()`. **Не зарегистрированы новые EEex listeners**. Существующий hit-listener вызывает заменённую `BGX52Bridge.prepare`.
* После подтверждённого попадания по союзнику выбирается один подходящий свободный F-охранник. При одновременном попадании по другому союзнику второй свободный F-охранник получает отдельный запрос. Каждая цель и каждый защитник резервируются на 45 игровых тиков, чтобы не засыпать движок дублирующими приказами. Это событийное распределение по факту появления ударов, **без гарантии глобальной приоритизации уже запущенных действий**.
* Игра не получает прямых `Attack`, `Spell`, `ProtectObject` от Lua: ровно пять записей `BGX52_*` в одного защитника, финальный `BGX52_REQ_SLOT` — commit. Установленный `BDDEFAI.BCS` выполняет `ProtectObject` при собственных условиях: текущий F, `ActionListEmpty()`, modal NONE, расстояние, видимость и TTL.
* Защитники допускаются к ближней охране только при проверенном `CLASS.IDS` `2 Fighter`, `6 Paladin`, `12 Ranger`, HP > 50%, `BGX38_GUARD=1`, `m_nModalState=0`, **той же ARE**. Дублирующие назначения или незаконченная прошлая заявка исключаются. Неизвестные киты/мульти/дуалы и классы 1/3/5 маг/жрец/бард остаются **пассивными кандидатами поддержки**: никаких автоматических заклинаний/рукопашных приказов. Подтверждённые игровые поля класса/HP/F/координат/AREA получены из живого EET скриншота пользователя.
* Упавшая Lua-проверка не подавляет урон: исходный listener возвращает `false`. Ошибка записи сбрасывает запрос.

## Установка и откат — шлюзы

`BGXAI66_INSTALL.py status` — только чтение установленной 064 или новой 066. `preflight` — точная SHA256 и WeiDU проверка живой 064 без изменения игры. `install --yes --confirm INSTALL_BGXAI_066` — только Windows и только фиксированный корень, предварительно закрытые Baldur/InfinityLoader/WeiDU, отсутствие чужого последнего WeiDU, проверенный внешний бэкап, затем строго Lua-only WeiDU `BGX66`.

`rollback --yes --confirm ROLLBACK_BGXAI_066` — только когда BGX66 последний компонент WeiDU, сверяет Lua/BCS/стадию, делает новый внешний бэкап и удаляет BGX66 через WeiDU. После отката проверяет SHA256 восстановленной 064. При неуспехе **не повторять установку/откат вслепую**.

**Важно:** прямой запуск `install/rollback` НЕ разрешён просто по прочтению этого файла. Через исходный проверенный однофайловый обновлятор эти команды будут доступны только после native Windows проверки его нового draft и отдельного ввода разрешающей фразы. Не копируйте вручную Lua в `override`.
