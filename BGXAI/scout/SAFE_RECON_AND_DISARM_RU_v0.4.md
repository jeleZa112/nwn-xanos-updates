# BGXAI 0.4 — осторожная разведка, обнаружение и обезвреживание ловушек
**03.11.2026.** Условия: EET 2.6.6.0 / SCS 35.21 / Insane / EEex 1.1.7.
**СТАТУС: исходники и тесты в GitHub, SHADOW-only. НЕ подключено к игре/EEex, не заменяет текущий 0.6.27 pilot.**

## Требование пользователя
Если вора отправили вперед на разведку и поиск ловушек, он должен увидеть ловушку, **остановить подход группы**, оценить шанс, **проверить окрестности на врагов**, и только затем безопасно обезвредить. Нельзя отправлять вора под удар, пытаться обезвреживать в бою или пересекать другую ловушку по кратчайшему пути. Это универсальный режим для любого вора/мультикласса/кита, не привязанный к Имоен/Монтарону/месту портрета.

## Реализация и реальные проверки
- `BGXAI/scout/BGX_SCOUT_SAFETY_V01.js`: чистый JS автомат состояний; `BGX_SCOUT_SAFETY_V01.test.js` — **51/51 повторяемая проверка**.
- `BGXAI/menu/BGX_UNIVERSAL_ARBITER_V04.js`: адаптер поверх самостоятельных независимых переключателей `BGX_UNIVERSAL_ARBITER_V03.js`; `BGX_UNIVERSAL_ARBITER_V04.test.js` — **17/17** интеграционных проверок. Также раньше **26/26** тестов базового арбитра.
- Оба набора проверены в JS на опубликованных исходниках. НЕТ игрового smoke-test, нет команды `RemoveTraps` в актуальном BAF.

### Шаги в режиме SCOUT
1. Идти только по уже подтвержденному безопасному маршруту; алгоритм **не рассчитывает путь** сам. Сведения о маршруте/видимости должны приходить из проверенного EEex адаптера.
2. `DETECT_TRAPS` только в безопасном простое: требуется свежий обзор угроз, отсутствуют известные враги/бой/повреждение/неизвестная телеметрия.
3. При обнаружении `TRAP_ALERT` — **предложение** заблокировать маршрут группе и остановиться. Исполнитель в игре пока НЕ подключён, поэтому текущая версия не останавливает персонажей фактически.
4. `ABORT_DISARM`: если есть видимый враг в области, предполагаемое вражеское присутствие, звук угрозы, недавний удар/полученный урон либо партия в бою. Если разведчик может вернуться по **подтверждённому свободному от ловушек пути** к безопасной точке отряда, выдать `SCOUT_RETREAT_PROPOSAL`; при неизвестном пути **не заставлять бежать вслепую**.
5. В мирной зоне подождать **минимум 10 секунд** и **полный раунд обнаружения (порядка 6.67 с)**, получить повторные независимые снимки угроз. После появления врага таймер обнуляется и снова ждёт.
6. Перед действием проверить: правильный живой персонаж с активным `canDisarm`, HP >=70%, не скрыт, нужный конкретный trap уже действительно обнаружен, виден, находится в безопасной досягаемости, нет рискованного перехода через другую ловушку/сюжетной цели. Все эти значения должны быть доказаны адаптером, а не вычисляться по умолчанию.
7. Оценить вероятность. Из механик BGEE: `FindTraps + (1d10 - 1) > RemovalDifficulty`. При достоверно известной сложности (не 100): `p = clamp(skill - difficulty + 9, 0, 10) / 10` без учёта Luck; сложность ровно 100 — непреодолима. Автоматическое разрешение только если p >=90% и есть обе опции `Обезвреживать` + `Автоматически обезвреживать безопасные`.
8. **Критично: RemovalDifficulty обычно скрыта от игрока.** В честном режиме нельзя говорить, что бот узнал шанс по внешнему файлу монстра/ARE. Если сложность неизвестна — **ASK PLAYER**, без попытки. Необязательная явная опция `one_cautious_try` при навыке >=100 позволяет одну пробу только после всех проверок безопасности, но шанс при этом остаётся неизвестным и не гарантирует успех.
9. Однократная попытка по одному ID; до фактического подтверждения успеха не повторять. Новый сейв/F9/смена действительного уникального NPC сбрасывает состояние безопасного сканирования. Приказ игрока обнуляет ожидание, затем требует повторного обзора.

## Галочки будущего универсального меню
Для любого персонажа, у которого фактически есть соответствующие способности: `Поиск ловушек`, `Разведка осторожно`, `Обезвреживание`, `Автообезвреживание безопасных` (по умолчанию **ВЫКЛ.**), `Порог шанса` (по умолчанию 90%), `Попытка при неизвестной сложности` (по умолчанию **ВЫКЛ.**), `Не идти при видимых/подозреваемых врагах` (обязательная защита), `Вернуться к группе по безопасному пути` (только при проверенном маршруте).
Независимые галочки позволяют одновременно активировать скрытность, ближний/дальний бой, магию и предметы; несовместимые активные модальные действия выполняются по очереди и никогда не сбрасывают собственные задания вручную.

## Ограничения и приёмка
Текущая модель может выдать **только предложение**; не видит реальных врагов/путей в игре, не может проверить врага за закрытой дверью или за пределами обзора и не имеет права обещать 100% безопасность. EEex мост должен гарантировать свежесть и полноту доступной информации **с точки зрения игрового персонажа**; при неизвестности модель отказывается выполнять рискованные действия. Далее нужен исполнитель, который прямо перед `RemoveTraps(trap)` повторно проверяет опасность, досягаемость, команду игрока и подпись текущего сейва. Реальная дистанция, маршруты и EEex API ещё не проверены, данный алгоритм к 0.6.27 `latest.json` не подключён. Оригинальный `BDDEFAI.BCS` не изменён.
