# BGXAI — универсальный арбитр независимых функций v0.3
Дата: 2026-11-03. **SHADOW ONLY**: это исполняемый JavaScript для автономных тестов, а не игровой EEex/MENU/WeiDU бот. `BGXAI/latest.json` и действующие BAF не изменены.

## Почему сделано
У пользователя в SCS Improved AI для КАЖДОГО персонажа можно независимо разрешить магию, ближний/дальний бой, навыки, предметы и скрытность. Новый BGXAI должен принимать одновременно любые из этих разрешений (в пределах реально доступных у текущего мультикласса/кита способностей). Никаких жёстких уникальных ролей и имён NPC.

**Код**: `BGXAI/menu/BGX_UNIVERSAL_ARBITER_V03.js`. Тесты: `BGXAI/menu/BGX_UNIVERSAL_ARBITER_V03.test.js`. **26/26** сценариев прошли в чистом JS во время публикации, см. тесты. Ранее 44 внутренние проверки во время разработки, итоговый опубликованный регресс — 26.

## Основная архитектура
- Любое число профилей `config(campaignKey).actors[actorKey]` за кампанию, без имён, слотов, расы и кита в коде. Личное `p.allow` — **19 независимых флагов**, включая ближний/дальний бой, Sneak, Hide, Detect, Disarm, Unlock, контроль, боевую/защитную/лечебную магию, баф, призыв, предметы/жезлы, песню и отступление.
- `preset(p,name)` единожды применяет стартовые флажки; затем `toggle(p,task,on)` **НЕ блокируется пресетом**. Не подменять `preset` взаимоисключающей ролью.
- Мультикласс/дуал/кит/последствия прокачки не угадываются по имени. Адаптер должен по фактическим доступным возможностям подать `capabilities`, `ready spells`, `legalTarget`, `slots remaining`, `equipped weapons`, `visibility`, `manual order`. Unknown => false. Пока нет подтверждённого адаптера, игра НЕ исполняет решение.
- `select(config,actorKey,snapshot)`: выбирает **одно** наиболее полезное безопасное действие из доступных: аварийное отступление; лечение себя/союзника; контроль и защитная магия; призывы/бафы; заклинания урона; предметы/жезлы; melee/ranged/sneak; вне боя — обнаружение/скрытность и **только с согласия** взаимодействие с конкретным замком или ловушкой.
- Приоритет player manual + уже выполняемое действие абсолютен. `world.cooldowns` и escapeBudget пришли от адаптера. Без `safeRetreat===true` отход не выдаётся.
- Скрытность сохраняется: каст/предмет/обычная атака не сбивает её (кроме ситуации угрозы жизни с доказанной необходимостью). 3E Sneak требует **melee**, текущего melee weapon, безопасного пути, уязвимой цели, не использованной на ней атаки.
- Ресурсные ограничения: фактически заученная/доступная способность, legal target, слот после каста >= `spellReserve`; запас зарядов после предмета >= `itemReserve`; редкие средства вне boss/high threat не тратить. AoE без проверки friendlyFireSafe запрещён.
- Взлом/обезвреживание: `target.visible`, `reachable`, `safeAccess`, `playerApproved`, не questSensitive; для замка ещё `trapsChecked`, для ловушки `discovered`. Никаких краж из NPC/открывания сюжетных ящиков вслепую.

## Что пока НЕ сделано
1. EEex читатель фактических возможностей и устойчивых личных идентификаторов между слотами, переименованием, сохранениями/F9 и EET сменой главы. **Текущий actorKey — внешний маркер, НЕ доказанный стабильный game ID**.
2. Интерфейс .MENU и Lua-связь с настройками; lefreut UI не трогать до теста на копии.
3. Совместный командный scheduler для 6 активных персонажей; согласованное целеуказание/лечение без дублирования; реальная оценка damage/TTL/TTK по журналам, не по догадке.
4. Действия song, предметы привязанные к нестандартным kit-способностям и весь набор заклинаний ещё **не поддержаны исполнительным адаптером** — тумблеры есть, не все имеют готовые кандидатные правила.
5. Безопасный исполнитель, обнаружение manual-order origin, реальная WeiDU/EEex компиляция/установка и игровой тест.
6. Инвентарь/двери/ловушки без явного подтверждения игрока не автоматизировать.
