# BGXAI — импорт реально работающих настроек Advanced AI
Дата: 2026-11-03. Статус: **проверенный JS-прототип преобразования, не установленный игровой адаптер**.

## Источник
Реальный `BDDEFAI.BCS` из пользовательского архива `BG_EET_AUDIT_02_QUESTS_AI.zip`, SHA256 `2d98605d2ee5a1d8abb17961f03f2ca9c9d48ea24a1007860e938f49c650165a`.
Полный структурный разбор подтвердил **322 блока, 5577 TR, 322 RE, 1022 AC**. Сведения о 644 блоках ранее были ошибкой двойного подсчёта открывающих/закрывающих CR.

## Реализовано
- `BGXAI/menu/BDDEFAI_CONFIG_BRIDGE_V01.js` — чистый JS-преобразователь локальных переменных `BDAI_DISABLE_ATTACK`, `BDAI_ATTACK_MODE`, `BDAI_DISABLE_ITEMS`, `BDAI_DISABLE_DEFENSIVE`, `BDAI_DISABLE_OFFENSIVE`, `BDAI_DISABLE_SPECIAL`, `BDAI_SKILL_MODE`, `BDAI_NO_ARCANE` в начальные *рекомендации и независимые галочки* BGXAI. Это не автоматическая подмена настроек.
- `BDDEFAI_CONFIG_BRIDGE_V01.test.js` — **29/29 повторяемых тестов** (выполнены в V8 на содержимом опубликованных GitHub файлов): боевой режим, блокировка предметов и арканы, классовая доступность, режим поиска/скрытности/песни/изгнания, абсолютный приоритет ручного управления, сохранение скрытого состояния, ручные переопределения.
- В текущем BDDEFAI режимы `BDAI_SKILL_MODE=1/2/3/4` соответствуют `FindTraps/Hide/BattleSong/Turn` в блоках 297–301. При переносе это **не взаимоисключающие разрешения**, а один исходный *выбранный* режим. Наш арбитр может оставить все 4 разрешения и переключать их по контексту только при действительно доступном умении.
- `selectModal()` отдельно проверяет наличие нежити, полезность песни, риск ловушки и ручной приказ, чтобы одновременно не пытаться петь и искать ловушки.
- В исходном скрипте `BDAI_DISABLE_ITEMS=1` выставлен при инициализации, следовательно импорт не включает расходники без пользователя; `specialItem` сохраняется выключенным даже при общем разрешении предметов.

## Границы
- **Реальная EEex-передача локальных переменных** и подтверждение, что значения отражают UI конкретного персонажа, ещё не сделаны. Не утверждать, что игра уже синхронизирована.
- Флаг `BDAI_DISABLE_DEFENSIVE` применяем как *предложение* для `defenseSpell/healSpell/buff`, `BDAI_DISABLE_OFFENSIVE` как предложение для `control/damageSpell`. Это удобная группировка; **не доказательство**, что все соответствующие BCS-ветви совпадают со всеми категориями нового интеллектуального ИИ.
- Для подтверждения действия class/kit/dual и настоящего наличия spells/items нельзя доверять самому флагу: `capabilities[task]` обязателен и должен поступить от проверенного игрового EEex адаптера.
- `BDAI_NO_ARCANE=1` возвращается как `noArcaneContext`, но **не отключает** автоматически жреческую магию. Для арканы проверять конкретный контекст игры и законность.
- Ни один файл игры, обновлятор, `latest.json`, `BDDEFAI.BCS`, `BGXGRP`, `BGXTANK`, NWN/main не изменён.

## Следующий технический контракт
1. Read-only EEex: selected actor -> stable ID; read BDAI LOCALS flags; detect current usable skills/spells/items and manual action queue. Никаких хитростей при пустом ответе API.
2. `BDDEFAI_CONFIG_BRIDGE_V01.importBDAI(...)` выдаёт стартовую конфигурацию текущему NPC.
3. EEex `.MENU` показывает **все независимые** разрешения (не один роль-переключатель), неактивные недоступному киту; пользователь меняет отдельно.
4. Арбитр выбирает действие; до приёмочных игровых тестов работает только в SHADOW, без приказов.
