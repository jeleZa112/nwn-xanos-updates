# BGXAI 0.7.3 — EEex: первый реальный наблюдатель для меню и безопасной разведки

**03.11.2026. Статус: код готов, проверен на эмуляции EEex; на компьютере игрока и в EET ещё НЕ запускался.** Это промежуточный диагностический модуль без боевых команд и без установщика. `BGXAI_UPDATE.cmd` и `BGXAI_LIVE.cmd` неизменны. Копировать `M_BGX73.lua` в `override` пока не требуется.

## Что делает файл M_BGX73.lua

* Использует уже подтверждённый в проекте метод регистрации `EEex_Action_AddSpriteStartedActionListener` и вызовы `EEex_Sprite_GetInPortrait(0..5)`.
* При начале действия члена партии считывает его текущий слот, **числовой код класса, кита, уровни и текущие HP**, по возможности `getLocalInt` для восьми настроек штатного `BDDEFAI` (атаки, предметы, защита, наступательная магия, особые навыки, режим навыков, режим атаки, запрет магии в контексте).
* Через задокументированный `sprite:countAllOfTypeStringInRange('[EVILCUTOFF]', 448, true, false)` пытается считать врагов **в пределах видимости**; при ошибке API возвращает `?`, а не ложное «безопасно».
* Печатает строки `[BGX73] OBS actor=A1 slot=... class=... enemyLOS=... BDAI=... manual=? trap=? path=? identity=SESSION_ONLY` в игровой консольный лог (если игра выводит эти строки). Псевдоним `A1` живёт только в текущей Lua-сессии, не содержит имя, raw ID, координаты, пути или идентификатор учётной записи.
* Наблюдает не чаще 1 из каждых 20 стартов действий на персонажа; максимум **250** строк OBS на сессию; проверяет наличие API, ловит исключения и не регистрирует один и тот же слушатель дважды.
* **Не выполняет ни одного действия персонажа**, не изменяет никаких игровых флагов, AI-скриптов и файлов, не использует сетевые запросы, не трогает модовое меню lefreut и штатный `BDDEFAI`.

## Почему пока нельзя автоматически снять ловушку

Найденные API подтверждают чтение персонажа и существ в его LOS, но **не доказывают обнаружение конкретной ловушки, отсутствие невидимых врагов, безопасную геометрию маршрута и происхождение ручной команды игрока**. Поэтому метки `trap=? path=? manual=?` остаются неопределёнными. Даже `enemyLOS=0` — не доказательство безопасности. Пока нет полной диагностики и проверенного исполнителя `RemoveTraps` на конкретном обнаруженном объекте, бот отказывает в автоматическом обезвреживании.

`BGX73_READONLY_ADAPTER.js` извлекает этот формат и строит **строго неполный** снимок. Он сознательно выставляет `surroundingsChecked=false`, `visibilitySnapshotFresh=false`, `canDisarm=false`, `trap=null`, `safeRetreatToParty=false` и никогда не возвращает разрешение на обезвреживание или бегство. При этом видимые враги сохраняются как сигнал опасности. Новая версия должна подтвердить остальные условия *из игры*, а не угадывать по классам.

## Проверки

* Lua 5.4: **синтаксис PASS**; mock EEex через liblua5.4: **17 групп PASS** (регистрация слушателя, состав, класс/кит, HP, BDAI, число LOS, отсутствие raw ID, отсутствующий API, ошибки считывания).
* Node.js: **33 теста адаптера PASS**; ещё **2 теста** с `BGX_SCOUT_SAFETY_V01.js`: неполный снимок даже при `enemyLOS=0` не позволяет `DISARM_TRAP`.
* Это не тест внутри `InfinityLoader.exe`/EEex 1.1.7. В тестах Lua 5.4; движок EEex использует LuaJIT, совместимость чтения конкретных полей в данной сборке требует реального smoke-test. При отсутствии поля выводится `?` и алгоритм безопасно отказывается от недоказанного решения.
