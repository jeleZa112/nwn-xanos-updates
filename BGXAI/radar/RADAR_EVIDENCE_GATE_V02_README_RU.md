# BGXAI — Radar × EEex Evidence Gate v0.2 (SHADOW, 03.11.2026)

**Статус:** офлайн-прототип без связи с игрой. `BGXAI/latest.json=0.6.27-role-profile-install-pilot`, LIVE 0.4.4 и BGXAI_UPDATE.cmd **не менялись**. Это не установленный Radar exporter, не включённый EEex runtime и не автоматическое обезвреживание.

## Что добавлено
- `BGXAI/radar/BGXRADAR_EVIDENCE_GATE_V02.js`: принимает только синхронизированные проверенные снимки Radar+EEex с явным `identityEpoch`, подтверждением **каждого** соответствия entity ID, стороны (enemy/party), области и видимости EEex.
- Отсекает устаревшие снимки (750 мс), рассинхронизацию (350 мс), дубликаты Radar ID / EEex actor ID, невалидные HP/эффекты/сопротивления, скрытых и непроверенных существ.
- Возвращает данные HP, эффектов и сопротивлений **только как тактическую подсказку**; `canIssueGameAction=false`, `canDisarm=false`, `canRetreat=false`; отсутствие видимых врагов не означает безопасность.
- `scoutEvidence` стыкует допустимые сведения с `BGX73_READONLY_ADAPTER.js`, но **не** подтверждает отсутствие врагов, ловушки, безопасный маршрут, ручные приказы и право автообезвреживания. После загрузки сохранения старый fused snapshot не переносится.
- `BGXRADAR_EVIDENCE_GATE_V02.test.js`: **45/45 офлайн-тестов** пройдены в Node.js 22; импорт использует существующий в GitHub `../eeex/BGX73_READONLY_ADAPTER.js`. В локальном тестовом каталоге использована функциональная копия адаптера; фактическое GitHub-исполнение тестов отдельно нужно подтвердить.

## Контракт источников (ЕЩЁ НЕ РЕАЛИЗОВАН В РАДАРЕ)
```js
radar={schema:2,source:'BG2RadarOverlay-local-export',session:'s',area:'AR1000',identityEpoch:'load1',timeMs:4850,entities:[{id:'r1',side:'enemy',hp:25,effects:[],resist:{}}]};
eeex={source:'EEex',session:'s',area:'AR1000',identityEpoch:'load1',timeMs:4920,confirmedMatches:[{radarId:'r1',actorId:'A1',side:'enemy',sameCreatureVerified:true,inGameVisible:true,sameArea:true,alive:true}]};
```
Временные значения — общие монотонные миллисекунды одной локальной системы, а не несогласованные часы разных процессов. `identityEpoch` **обязан** измениться после F9/load или потери идентичности; способ достоверного получения пока не подтверждён. Реальный stock BG Radar подобный JSON не отдаёт.

## Безопасность и ближайший шаг
1. Не изменять рабочий exe Radar и не передавать данные через Twitch relay; отдельный opt-in локальный read-only NDJSON/IPC exporter только после проверки установленной версии/Options.
2. Подтвердить в настоящем EEex 1.1.7 происхождение и стабильность идентификаторов, «виден персонажу», source ручного приказа, конкретную обнаруженную ловушку и маршрут. Не читать скрытую вражескую информацию как всезнание.
3. Только после source verification включать data bridge, затем меню независимых переключателей, затем отдельно тестировать gated executor на резервном сохранении.

Пользователю **не нужно ничего распаковывать в игру**. Архив предназначен для исходников и продолжения разработки. Публичный GitHub не содержит логов, имён персонажей из приватных данных, игрового пути, PAT/DPAPI. Не трогать NWN/main.
