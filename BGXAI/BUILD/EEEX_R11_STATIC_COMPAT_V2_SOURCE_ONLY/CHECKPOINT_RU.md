# BGXAI — EEex R11 статический предконтроль V2 (SOURCE ONLY)

Дата: 22.11.2026. Статус: `CODE_READY / OFFLINE_TEST_PASS / NOT_DEPLOYED / NOT_LIVE`.

## Зачем

R12 Target-Bound V2 и R11 успешно проверены локально, однако установленный EEex игры ещё не проверен. Предыдущая статическая проверка V1 находила названия API регулярными выражениями после удаления комментариев; это было уязвимо к ложным совпадениям в Lua-строках. Создан V2, в котором строки Lua (`'...'`, `"..."`, `[=[...]=]`) и комментарии (`--`, `--[=[...]=]`) скрываются до поиска вызовов. Наличие вызова остаётся только **статическим свидетельством**.

## Что делает

`BGXAI_EEEX_R11_STATIC_COMPAT_RO_V2.py` на Windows принимает только `C:\Games\BG_EET_FOXX_NEW`; читает `chitin.key`, `override/M___EEex.lua`, `EEex_scripts/B3AttackInfo.lua`, `EEex_scripts/EEex_Action.lua`, `override/M_BGXWP.lua`, `override/M_BGXW2.lua`, `override/M_BGXW4.lua`.

Считывает SHA256 и байтовую длину исходников, ищет официально известные имена `EEex.GetWeaponHitChance`, `EEex.IsImmuneToWeapon`, `EEex_Action_AddSpriteStartedActionListener`, `EEex_Action_LuaHook_OnAfterSpriteStartedAction`, не считает комментарии/строки активным кодом. Не следует символическим ссылкам / Python-распознаваемым junction, не работает с пустыми/очень большими/повреждёнными скриптами, не пишет файлы и не запускает WeiDU или игру. Если всё найдено: `STATIC_CALLSITES_FOUND_RUNTIME_NOT_PROVEN`, но `runtimeApiAuthenticated=false`, `weaponSwitchAuthorized=false`, `installAuthorized=false`. При несовпадении: `HOLD`.

**Ни один статус не доказывает runtime-доступности функций, актуальный APR альтернативных слотов, происхождение EPS/manual, право переключать оружие или эффективность против защищённой цели.** Никакого игрового hook и никаких боевых команд.

При этом содержимое текущей рабочей ветки может изменяться независимо от PIN.
