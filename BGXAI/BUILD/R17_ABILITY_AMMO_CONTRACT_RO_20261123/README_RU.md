# BGXAI R17: связка способности/боеприпаса, только чтение

**Статус:** SOURCE ONLY. Не устанавливается, не содержит команд управления персонажами, не меняет BG_EET_RU, BG Voice RU, EPS, SCS или игру. Вызов существующего `BGXAI_UPDATE.cmd` **не требуется**.

Переиспользованы исходные данные:
- Аудит R3 (ITM/BIFF) от 22.11.2026: `BGXAI_WEAPON_NATIVE_ITM_R3.json`, SHA256 `7ae7555f81b14a784e7866472f14483b02c2d6b707ab6169225e8fec32507304`. **Это другой персонаж/другая сессия**.
- Отчёт R16 `REAL_LOG_ALTERNATE_SLOTS_RO_V1.json`, без подтверждения APR альтернативных слотов.
- Живой журнал TD15 `BGXAI_R13_2_CONSOLE_20261123T064924087770Z.log`, SHA256 `cebfa573df8fc9e5180ec8cbcfc8b67a865a12c6381394d5dcd511cdf7500945`.

Реальный результат на предоставленном журнале:
- Статический предыдущий ITM: слот 36 — лук `BOW05` (тип способности 4, дальность 75); слот 12 — `AROW01` (тип способности 2, `launcherRequiredRaw=1`, дальность 100). **Совместимость именно как игровая действующая пара не аутентифицирована**.
- После трёх событий `R13 DEFENSE` / атака 3 в ограниченном окне наблюдается снижение числа стрел: `20→19`, `20→18`, `18→17`. Это **изменение содержимого слота в окне**, не доказательство числа выстрелов или точной связи с одним боевым действием. Между боями количество 19→20; ранее R16 классифицировал это как «перезагрузка/пополнение, причина не подтверждена».
- В прежнем ITM лука opcode 1, mode 1, key 2 — кандидат на **плоскую установку APR**, а не +2 атаки. Не применять повторно к наблюдаемому эффективному APR.
- У меча `SW1H04` имеется способность с opcode 146, потенциально связанная с поломкой оружия; не учитывать как бесплатный бонус к урону. Двуручный лук/посох вместе со щитом требуют отдельного подтверждения активной защиты.
- Сохраняются неопределённости: текущие хэши ITM, проверка ограничений использования, ID выбранной способности, нативная пара лук-стрелы, временные эффекты, эффективность APR остальных слотов, полная защита/иммунитеты врага, очередь EPS/ручные действия.
- `weaponSwitchAuthorized=false`, `dispatchAuthorized=false`, `weaponPriorityAuthorized=false`.

Для локальной диагностики с этими **ранее полученными** файлами:

```sh
python BGXAI_ABILITY_AMMO_CONTRACT_R17_RO.py --r3 <previous_R3.json> --r16 <R16_report.json> --log <TD15_console.log>
```

Реальный журнал и старый R3 **не вложены в публичный исходный пакет**: в архиве только код, синтетические тесты и обезличенный производный отчёт.

`python -m unittest -v test_r17_ability_ammo_contract_ro.py`

Никакие тесты на синтетическом наборе не доказывают игровую функциональность нового кода. Следующее действие по проекту — отдельный **пассивный/native authenticated** сбор выбранной способности, ID launcher/ammo и snapshot активных эффектов во время действия; только после этого возможен честный рейтинг всех доступных слотов. Не устанавливать до отдельного разрешения.
