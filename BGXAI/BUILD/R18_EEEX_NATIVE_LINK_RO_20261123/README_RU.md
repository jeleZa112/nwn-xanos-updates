# BGXAI R18 — пассивный контракт EEex: способность, launcher и состояние

**Тип:** SOURCE ONLY / READ ONLY. Это не мод, не установщик, не Lua-наблюдатель с автозагрузкой. Игру, `WeiDU.log`, `BGXAI_UPDATE.cmd`, TD15, EPS, сохранения, BG_EET_RU и BG Voice RU не изменяет.

## Зачем R18

После R17 известны реальные события атаки со стрелами и мечом; в старом R3 есть структура ITM для `BOW05`, `AROW01`, `SW1H04` и `STAF01`. Но не подтверждены **фактически выбранная способность ITM**, **настоящая связь стрелы→лук в движке**, **полные активные эффекты**, **эффективные APR остальных слотов** и **происхождение команды (ручная/EPS)**.

Функции из upstream **EEex v1.1.7** (проверен именно исходный код тега, а не установленная сборка):

- `CItem:getAbility(abilityIndex)` — возвращает структуру способности выбранного ITM (`EEex_Resource_GetCItemAbility`).
- `sprite:getLauncher(Item_ability_st)` — возвращает объект launcher и его слот (`EEex_Sprite_GetLauncher`).
- `EEex_Sprite_GetActiveStats(sprite)` — активные производные характеристики; это **не полный список действующих эффектов**.
- `EEex_Action_AddSpriteStartedActionListener` существует upstream, однако **R18 не регистрирует никакой обработчик**.

См. `R18_UPSTREAM_API_CONTRACT_V1.json`: указаны точные upstream Git blob SHA и флаги *не подтверждено в игре*.

## Состав

- `BGXAI_R18_NATIVE_LINK_PROBE_RO.lua` — детерминированный on-demand, дважды сверяющий ID цели/атаки, слот, способность, launcher и 8 производных характеристик. При любом расхождении — `HOLD`. Не принимает внешний `verified=true` как доказательство.
- `BGXAI_R18_EEEX_ADAPTER_CANDIDATE.lua` — пример **отдельно НЕ устанавливаемого** адаптера известных upstream API. Не содержит `EEex_*Listener` вызовов и не перечисляет эффекты или неизвестные смещения памяти.
- `test_r18_native_link_probe.lua` — 28 тестов поддельного интерфейса (атака, дальний/ближний/кулаки, разрывы данных, смена цели, слота, способности, оружия и статов).
- `test_r18_eeex_adapter_candidate.lua` — 12 тестов макета CItem/CGameSprite.
- `test_r18_source_contract.py` — 18 тестов исходников, безопасности и происхождения upstream API.
- `R18_UPSTREAM_API_CONTRACT_V1.json` — сведения об официальных исходниках EEex и **запрет всех действий**.
- `SHA256_MANIFEST.json` — хеши файлов для точного воспроизведения.

## Текущее поведение

Для валидной выбранной стрелы возвращается `CURRENT_ATTACK_NATIVE_READ_CANDIDATE_RO`, кандидат `launcherResrefCandidate`, слот launcher, индексы выбранных способности/боеприпаса, базовые скалярные stats. **Слово CANDIDATE означает, что реальный вызов ещё не проверен в EET**. Результат не подтверждает доступность других слотов, бонусы силы, эффект яда, критические повреждения, иммунитеты, очередь EPS или право сменить оружие.

Строка `derivedStatSnapshotKey` — простое сравнение 8 чисел. Это **не полный `activeEffectsFingerprint`**, и скрытый баф может измениться без изменения этих чисел. В любом случае `fullActiveEffectsFingerprintVerified=false`.

При недостатке данных или гонке между двумя чтениями — `HOLD`, без команд, без ожидания, без отмены действия.
