# BGXAI R13.2 — корректировка пассивного наблюдателя по реальному бою

Исходное свидетельство: `BGXAI_R13_CONSOLE_20261123T061617028509Z.log` (3 события DEFENSE со статусом HOLD, два участника группы). Доказана загрузка Lua и вызов слушателя. Прочитать реальную защиту врага пока не удалось.

Обнаруженные проблемы:
- `m_selectedWeapon=10` — **кулаки, SLOT_FIST**, а не слот обычного оружия; прежняя проверка отклоняла его.
- `m_selectedWeapon=12` — SLOT_AMMO1, боеприпасы; оставлен отдельный класс `AMMO`.
- Наблюдатель исключал `q.reason` из журнала и для HOLD сериализовал поля только из q (там они пустые), скрывая исходные ID цели/слот/тип действия.
- EEex может возвращать новые userdata-обёртки одного ID; `rawequal` слишком строг для пассивного чтения. Теперь сравниваем стабильные числовые ID, класс Sprite, действие и выбранный слот до/после двух последовательных чтений. Это НЕ подтверждение указателя/вероятности попадания.

Изменено только содержимое **пассивного** Lua `M_BGXD13.lua`. Добавлены `reason`, `sourceActor`, `targetActor`, `selectedSlot`, `slotClass` в JSON при HOLD. Сохранены все 9 исходных защитных полей. Игровые команды, смена оружия, очередь, EPS, сохранения, BG Voice RU и BG EET RU не меняются.

Установка только через **существующий `BGXAI_UPDATE.cmd` → 163**. По умолчанию 163→2 READ ONLY. 163→3 (Install) требует точной фразы `INSTALL_BGXAI_R13_HOLD_DIAGNOSTIC`; предварительно выполняется новая SHA-проверка, внешний backup и проверка TD14 как последнего компонента WeiDU. WeiDU TD15 перекрывает только `override/M_BGXD13.lua`; после установки TD14 остаётся в истории, а TD15 становится последним. Откат — 163→4, только при TD15-last и точной фразе `ROLLBACK_BGXAI_R13_HOLD_DIAGNOSTIC`; возвращает байты TD14. Никакой автоматической установки.

После установки захват для R13.2: **163→5**. Старый 162→5 требует TD14-last и после установки TD15 откажет, это предусмотрено.

Критическая граница: никаких доказательств реальной вероятности попадания/иммунитетов/полной APR альтернативы/диспетчеризации. `weaponSwitchAuthorized=false` независимо от статуса. Source-only тесты НЕ заменяют live-тест.
