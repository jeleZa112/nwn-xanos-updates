# BGXAI — первая проверка личности Джагана для XEquipItem V3 (SOURCE ONLY)

**2026-11-27. Не устанавливать. Не включать.** Это чистый Lua-модуль, предназначенный для возможного вызова из **уже существующего** R37/EEex callback. Он не регистрирует слушателей, не вызывает XEquipItem и не меняет ни одной переменной LOCALS.

## Конкретный сценарий

По реальному BALDUR(1).gam (SHA256 `7e926634c0972e90e25c975a18c9bf34b96f4d85184195c630555fdd43f7e19c`) целевой персонаж — Джаган, индекс портрета 1, saved class 3, один `STAF01` в слоте 20, пустой оружейный слот 35, flags=1, charges=[0,0,0]. Сам файл сохранения в GitHub не публикуется. Исходник также не использует имя `*GCLERIC` или `CRE scriptName=None` как подтверждение личности.

## Что проверяет модуль

Только при доступности `sprite` + доверенных EEex reader-функций, переданных существующим R37, дважды считываются: `sprite.m_id`, `sprite.m_typeAI.m_Class`, идентификатор портрета через `EEex_Sprite_GetInPortraitID` и все 38 наблюдаемых верхнеуровневых слотов 0..38, **кроме** неявного SLOT_FIST=10. Наличие `STAF01` допускается лишь в слоте 20 ровно один раз в этих 38 ячейках; слот 35 должен быть пуст, характеристики предмета должны совпасть. До/после проверяется согласованность actor id, party index, текущего action, selectedWeapon, ability, queue count, currentScriptNumber по существующему R37 контексту. Любая неполнота/изменение => `HOLD`.

`actorIdInMemory` остаётся только в возвращённой структуре; **не логировать его без отдельного решения**. Никакого сохранения id между игровыми сессиями. `saved GAM` не содержит доверенного runtime actor id.

## Что принципиально НЕ подтверждено

- Просмотр `ActionStarted` (R37) **не доказывает**, что персонаж простаивает. `ActionListEmpty()` не является полной гарантией текущей команды или ручного приказа; при занятости возвращается advisory, но **armAuthorized=false**.
- Совпадение игрока и предмета в callback не доказывает, что в эту минуту загружен именно сохранённый GAM, что классовые/ITM ограничения пройдены, что предмет не зачарован или не нужен по квесту, что `XEquipItem` не прервёт действия или сохранит заряды. Нет измерений после реального переноса.
- Этот код не добавлен в R37 и не передаёт флаг готовности в V3. Нет активного BAF native EET compile и нет last-only WeiDU installer.
