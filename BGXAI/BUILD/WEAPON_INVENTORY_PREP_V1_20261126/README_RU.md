# BGXAI: подбор и будущая экипировка оружия ИЗ РЮКЗАКА — новый приоритет пользователя 26.11.2026

## Что запросил пользователь

Умный автономный ИИ должен при атаке конкретного противника рассматривать **всё пригодное оружие персонажа, включая рюкзак**, а не только уже занятые быстрые оружейные слоты. Если оружие из рюкзака действительно лучше в данной ситуации, ИИ должен **надеть** его и использовать, не теряя предметов и не сбивая текущую атаку, ручную команду, лечение/каст EPS.

**Уточнение предыдущей задачи, которое НЕЛЬЗЯ игнорировать:** BGXRANGED V5 LIVE давал до 3 дополнительных выстрелов в упор; установленный V6 сократил это до **одного** в LIVE 21.11.2026. Реальный R37 26.11 подтвердил автоматический переход Халида на меч при свободном от ручных команд бое. При 6-секундном боевом раунде отдельная стрела после контакта могла быть завершением уже ранее запущенной атаки; **НЕ вводить Stop/ClearActions, НЕ менять V6/R29, не пытаться добиться механически невозможного нуля таких стрел, не доказав источник нового приказа**. Приоритет — новая функциональность рюкзака.

## Проверенная игровая основа

- EE/BG2EE поддерживает `XEquipItem("HAMM01",Protagonist,SLOT_WEAPON1,EQUIP)` по IESDP [BG(2)EE Actions #385](https://gibberlings3.github.io/iesdp/scripting/actions/bgeeactions.htm). Это означает, что сценарный путь **адресного** назначения предмета в оружейный слот существует. Но безопасное поведение на занятом слоте, сохранение предметов/зарядов, источник уникального item-instance и совместимость с текущими игровыми скриптами **не доказаны живым тестом**. Нельзя переходить от справочника к автоустановке без этого.
- `EquipItemEx` **не перемещает предмет** в инвентаре; `FillSlot` может **уничтожить предмет, уже находящийся в слоте** (IESDP). Для этой функциональности `FillSlot` запрещён полностью.
- Слоты рюкзака из [SLOTS.IDS BGEE](https://gibberlings3.github.io/iesdp/files/ids/bgee/slots.htm): **15–34**, быстрые слоты оружия **35–38**, боеприпасы **11–14**, щит **9**. Фактически разрешённых быстрых оружейных слотов **2/3/4**, зависит от класса: использовать только runtime verified capacity, не считать все четыре всегда доступными.
- Существующий `BGXAI_WEAPON_SLOTS_R2_READONLY.lua` уже читает `sprite.m_equipment.m_items:get(slot)` для quick weapons/quiver. Для рюкзака повторно используется **та же проверенная структура доступа** без создания нового слушателя.
- Существующий V3/V4/V5/NONINTERRUPT оценивает текущие quickslots; для оружия в рюкзаке ещё отсутствует настоящий runtime-adapter с доказанной доступностью, итоговым APR/THAC0, влиянием эффектов, классов, бафов, снарядов, щита и переносом предмета. Никакой флаг `verified`, переданный офлайн-планировщику, не является доказательством полного EEex runtime.

## Как довести до реальной функции без пустых наблюдателей и опасности удаления предмета

1. **Inventory-native adapter для EET/EEex:** присоединить чтение 15–34 к уже установленному R37 callback (НЕ второй listener); реальный resref + слот + заряд/стек + флаги, usability (класс, STR, alignment), cursed/quest/identified, двухручное оружие/щит, дополнительные эффекты оружия. Из уже имеющихся R34 ITM/ R32 2DA / V3-V5 строить модель полезности против конкретного врага. Отдельно вывести `MODEL_SCORE` и `ENGINE_VERIFIED`, не лгать про итоговые APR невыбранного предмета.
2. **Safe equipment transaction:** ограниченный исходный пилот **только на пустой доступный quickslot**, при валидном рюкзаке, отсутствии ручного приказа и занятых EPS/атаки/каста, с проверкой `XEquipItem` при живом сценарии на неуникальном заменяемом предмете и с внешней резервной копией игры. Проверка **до/после** по item instance/count/slot/flags, без уничтожения и с `HOLD` при изменении. Никакой `FillSlot`; не редактировать напрямую сохранение.
3. **Полные quickslots:** отдельный, более сложный протокол `occupied→backpack / backpack→quickswap`. НЕ запускать, пока не проверена атомарность/свободное место/уникальность/rollback; не затирать последний рабочий меч, лук или щит. Защищать ручные loadout locks игрока.
4. **Небоевая фаза и боевая фаза:** если нет безопасной границы текущего attack round/animation — **отложить** переэкипировку; нельзя обходить safety через `ActionListEmpty()==true` в одиночку. После экипировки перепроверить фактическое значение выбранного оружия и только потом применить существующую механику выбора quickslot. Cooldown / hysteresis, чтобы не перетасовывать оружие несколько раз в одном бою.
5. **Release:** всё в существующем `C:\Games\BG_EET_FOXX_NEW\BGXAI_UPDATE.cmd`, без новых обновляторов; source CI/native WeiDU parse, точная отдельная typed установка, SHA, внешний бэкап и WeiDU last-only rollback; live A/B подтвердить реальные улучшения. Не дублировать R29/V6/EPS.

**Приоритет:** не затягивать из-за багов одного оставшегося выстрела; двигаться к правильному изъятию подходящего оружия из рюкзака, начиная с гарантированно свободного слота, затем полноценно решать занятые слоты.
