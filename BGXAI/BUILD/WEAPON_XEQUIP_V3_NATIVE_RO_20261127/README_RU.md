# BGXAI — точный V3 BAF: подготовка нативной проверки без установки

**Дата:** 2026-11-27. **CODE+OFFLINE_TEST; real EET native V3 compile NOT VERIFIED; DEPLOY/LIVE NO.**

## Почему это нужно

Старый пункт `175` уже успешно проверил *инертный* BAF (`False()`) настоящим WeiDU 25100 в игре пользователя. Он **не проверял** активируемый V3 BAF для настоящего Джагана. Повторять `175` нельзя считать прогрессом.

В исходном пакете V3 после реального `BALDUR(1).gam` уже есть файл `BGXAI_REAL_JAGAN_BUILD_AUDIT_AND_BAF_V3.json`. Из него берутся строго **762 байта** BAF SHA-256 `996fd8896225ddbcd1ba2e260ca866acb70de09a6f91c9eb4338063fb7ae23e1`, а JSON SHA-256 `83a6865028336b9a2ebec5645ae34670832f1b07f372620f9c3961968a378b28`. BAF код: `STAF01` из `SLOT_MISC5` (slot 20) в `SLOT_WEAPON0` (slot 35), `BGXW3ARM/TAG/TRY` только `LOCALS`; сначала дезактивация, затем одна попытка `XEquipItem`. **Никакого кода включения `ARM=1`.**

## Что реализовано

`BGXAI_XEQUIP_V3_NATIVE_COMPILE_RO.py`:

- По умолчанию выполняет **только анализ точных байтов** BAF и аудита, без запуска WeiDU или обращения к игре; положительный статус `EXACT_V3_BAF_PIN_VERIFIED_NO_NATIVE_COMPILE`.
- Имеет отдельный отключённый по умолчанию инженерный режим `--native-readonly`, который **не должен вызываться пользователем отдельным CMD/PowerShell**. Предназначен только для будущего защищённого пункта **того же** `BGXAI_UPDATE.cmd`.
- Для нативного запуска на Windows требует закрытую игру, SHA256-pinned WeiDU `0d17e26e...`, Git-blob SHA1-pinned общий native compiler backend `0bd66e6f...`, внешний временный каталог, точное имя `BGXW3NAT.baf`, полный контроль входных байтов, неизменность watched-файлов и удаление временного BCS.
- Повторно использует **существующий** `BGXAI_WEAPON_NATIVE_COMPILE_PREFLIGHT_RO.py`; не вызывает WeiDU install, не пишет BCS в `override`, не пишет actor `LOCALS`, не меняет EPS/скрипты.
- Отчёт `V3_NATIVE_BAF_COMPILED_TEMP_ONLY` может быть выдан **только при настоящей проверенной WeiDU компиляции**. Он не означает безопасное исполнение, уникальность предмета в работающей игре, класс/кит, атомарность, владение действием или успешный перенос. Мониторинг смотрит только заданные файлы, не весь каталог игры.

## Проверки и остаточные ограничения

Локально проверено **14/14 Python тестов**: хеш, входной аудит, подмена файла, пустые/ложные пути, недоверенный backend, отклонение запуска native без разрешённой среды, имитация успеха/ошибки/изменения watched-файлов, восстановление временно заменённых callbacks, исходник без установочных команд. Эти тесты **не заменяют** настоящую компиляцию на пользовательской Windows EET.

CI `.github/workflows/bgxai_xequip_v3_exact_native_ro_ci.yml` — source-only Windows/Linux, без частного `BALDUR.GAM` и без запуска настоящего WeiDU. Отдельно проверять фактический GitHub run до объявления CI PASS.
