# BGXAI — локальная телеметрия и приватная онлайн-синхронизация
Дата: 2026-11-03. Статус: **архитектурное предложение, НЕ реализованный и НЕ подключённый сетевой канал**.

## Цель пользователя
Пользователь хочет играть в EET/LoB, а BGXAI должен в ходе боя фиксировать события, учиться по реальным сбоям и получать краткие корректировки без ручной загрузки каждого лога. Пользователь использует ChatGPT Plus, дополнительных платных API не оплачивает; Ollama уже установлена (`qwen3:4b-instruct`). Для пользователя должен оставаться один `BGXAI_LIVE.cmd` в корне рядом с `chitin.key`.

## Фактическое состояние
- Windows: подтверждён успешный старт `BGXAI_LIVE.cmd` 1.1 и локального монитора 0.3.1, валидная SHA256; монитор распознал Ollama и открыл лог.
- Фактический `BGXAI_COMBAT.log` содержит 221 EEex ACTION, сложность LoB (`GameDifficulty=6`), подтверждена загрузка Lua probe.
- Пользователь сообщает, что **не видит** `STATUS.txt` и `ALERTS.txt`. Источник `BGXAI/live/BGXAI_LIVE_MONITOR.ps1` пишет `STATUS.txt` при первом вызове `Log`, а `ALERTS.txt` только при инциденте, в `$GameRoot\BGXAI_LIVE_REPORTS`. Наличие/отсутствие файлов на ПК после боя не подтверждено проверкой точного пути. Проверить конкретно `C:\Games\Baldur's Gate Trilogy (EE)\BGXAI_LIVE_REPORTS`, не путать с `%LOCALAPPDATA%\BGXAI_LIVE\versions`.
- Чат ChatGPT **не** подписан на локальный сокет/логи и не может постоянно читать новые события или сам отвечать в момент возникновения проблемы. Обновления GitHub сами по себе не запускают модель в чате. Не обещать обратное.

## Предлагаемая архитектура без платного API
1. EEex / InfinityLoader только читает наблюдаемые события (сейчас 3 имени, расширение на всех членов партии — отдельный этап и требует теста).
2. Локальный `BGXAI_LIVE_MONITOR.ps1` в ходе боя добавляет таймстамп, версию, GameDifficulty, счетчики/обнаруженные паттерны: повторная смена действий, уход и ранний возврат, повтор MoveToObject с тем же target/pos, гибель и отсутствие подтверждённого реагирования, вмешательство игрока. **Факты и гипотезы разделять.**
3. Локальная Ollama может разбирать небольшие события автономно и показывать тихие предупреждения; нет требования постоянной связи и платы за API.
4. Отдельный управляемый модуль после явной настройки **приватного** GitHub-репозитория загружает только компактный `latest_status.json`, одну краткую сводку за интервал, `incident_*.json`; не грузить полный `BGXAI_COMBAT.log`, системные данные, пути пользователя или сохранения. Ротация, дедупликация, ограничение по размеру и частоте; отсутствие сети не должно задерживать игру.
5. Сетевой секрет: только отдельный минимально-правовой GitHub токен с доступом к единственному приватному repo, хранить защищённо локально (не в CMD, не в открытом файле игры, не в чате и не в публичном GitHub). Можно рассмотреть альтернативный защищённый relay. Нужны явное согласие пользователя и настройка доступа.
6. Ассистент через подключённый GitHub может читать приватные отчёты **когда ему поступает пользовательский запрос**; для автоматических проверок отдельная задача с ненулевой периодичностью, но это не потоковый live-ChatGPT. Без отдельно настроенного и оплаченного API не будет непрерывных ответов именно модели ChatGPT в бою. Команды в игру из удалённого канала не отдавать; EEex исполнитель обсуждать отдельно с ограничениями и ручным приоритетом.
7. Один пользовательский `BGXAI_LIVE.cmd` остаётся точкой входа, монитор и сетевой модуль загружаются в версионированный кеш по SHA256 с откатом, игровой `BGXAI_UPDATE.cmd` и ветка NWN/main не затрагиваются.

## Проверки перед реализацией
- **Сначала подтвердить файл статуса по точному пути**. Если `STATUS.txt` действительно отсутствует — выяснить, тот ли процесс работает, в какой папке и права записи; получить текущий скрин, не выпускать слепые hotfix.
- Добавить локальный heartbeat (отдельный файл с меткой времени и счетчиками) только после проверки причины отсутствия `STATUS`. Убедиться, что существующие монитор/лог не перезапускаются без необходимости.
- Тест: один бой -> появились новые события с локальными метками и локальная сводка -> приватная передача только сводки -> GitHub connector прочитал ее по пользовательскому запросу. Затем оценить интервал и качество, без автоматического управления боем.
- Запретить публиковать инциденты/логи в публичный `jeleZa112/nwn-xanos-updates`.

## Примечание
Это не готовый live-канал GPT и не свидетельство, что интернет-синхронизация уже работает. Не обещать фоновую работу данного чата без соответствующего инструмента.
