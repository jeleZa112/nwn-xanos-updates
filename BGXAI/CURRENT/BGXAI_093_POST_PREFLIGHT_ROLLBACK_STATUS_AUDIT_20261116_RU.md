## Установленный статический дефект
В BGXAI_IDLE_GUARD_INSTALL_SOURCE_ONLY.py:
1. rollback(): после WeiDU uninstall вызывает `verify_baseline(root, stage_allowed=True)`, поэтому оставленная папка `BGXIDLE/` и `setup-BGXIDLE.exe` не мешают успешно завершить rollback.
2. source_status(): после последнего компонента 066S вызывает `verify_baseline(root)` с `stage_allowed=False`.
3. verify_baseline(): при `stage_allowed=False` выдаёт `PILOT_STAGE_ALREADY_PRESENT`, если существует папка `BGXIDLE/` **или** `setup-BGXIDLE.exe`.
4. rollback() не удаляет эти два staging-пути. Значит после успешного отката `status` может давать STOP вместо подтверждения восстановленной 066S.

Это аналитический вывод из исходного кода, не результат Windows runtime теста. Дополнительная особенность: `install` после успешного rollback также блокируется оставшимся staging.

## Безопасное исправление — ТОЛЬКО отдельный SOURCE ONLY кандидат
- Не трогать закреплённый commit 9ad7249c768bc4770e5adb5b8582d8c0184e32b7 и активный BOOTSTRAP_PIN до полного повторного тестирования.
- Уточнить семантику status: наличие неактивной staged папки не должно считаться установленным компонентом; проверять last WeiDU+live SHA, а артефакты помечать `stale_stage_detected`. 
- Повторная установка должна безопасно проверять и контролируемо устранять старый stage только после отдельного согласия, либо не разрешать повторную установку с понятной диагностикой; не удалять данные произвольно.
- Новый тест: synthetic baseline -> install -> status -> rollback -> status, плюс отдельные негативные тесты чужой модификации stage, отсутствующего backup, mismatched SHA и не-last WeiDU.
- Сверить Windows PowerShell 5.1 AST, исходники, manifest и все старые пункты меню.
- Переключать однофайловый pin только после доказанного regression PASS. Устанавливать мод исключительно после отдельного разрешения пользователя.
