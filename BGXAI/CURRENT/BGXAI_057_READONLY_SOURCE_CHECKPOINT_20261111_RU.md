## Исправление неверного следующего шага
- Предыдущая инструкция с `C:DisplayText` предполагала подтверждённую Lua-консоль, которой в проверенной конфигурации нет: Ctrl+Space у пользователя вызывает паузу. Не предлагать повторно вводить команды в несуществующую консоль.
- По исходнику установленной диагностики 044 (`BGXAI/fox_new/release_044/BGX44/M_BGX44Diag.lua`) уже предусмотрен Ctrl+Alt+F11 без Lua-консоли; он показывает загруженность `BGX43Probe` и старые counters, но **не** полные bridge counters 056.
- **Первое действие пользователя:** в игре, запущенной через InfinityLoader, нажать Ctrl+Alt+F11, прислать снимок строки `BGX44:` либо сообщить, что строки нет. Никакого повторного боя не требуется. Старые runtime-счётчики после выхода из игры не сохраняются.

## Новая реализация 057 (пока только исходный код)
- Создан отдельный Lua-ресурс `M_BX57.lua` (6-символьный basename, подходит под EEex M_* загрузку). Ctrl+Alt+F10 без консоли показывает через `Infinity_DisplayString`: `weapon_hit_calls`, `weapon_hit_errors`, `bridge_attempts`, `bridge_prepared_count`, `guard_signal_errors`, `bridge_last`, две основные причины отказов и F/Q/MOD/EX/CD у спутников.
- 057 только читает `BGX43Probe.snapshot()` и EEex объекты/LOCALS. Не пишет переменные игры, не посылает команду атаки/охраны, не меняет файлы, не читает диск, возвращает false из клавиатурного обработчика (не забирает нажатие у игры).
- Созданы Lua, README, mock-test Python, манифест SHA256, ZIP `BGXAI_057_READONLY_SOURCE_ONLY.zip`.
- Проверки: **PASS** реальный Lua 5.4 parser и mock runtime (F10+Ctrl+Alt, защитник F=1 Q=3, PREP/ATT/ошибки, отсутствие перехвата клавиш, корректный отказ при отсутствии 056 или API вывода). ZIP CRC PASS, побайтовые хеши участников совпали с манифестом.
- ZIP: 5225 bytes, SHA256 `acc42dcf17bb95d511b263e9bbec08a75014fa3cd390c06311de30b205c98a49`.
- **Не подтверждены** EEex 1.2.0 LuaJIT, автозагрузка M_ в реальной EET, Windows WeiDU-инсталляция 057, live hotkey и поведение охраны 056 после интеграции. **НЕ КОПИРОВАТЬ M_BX57.lua В override ВРУЧНУЮ.** Нужен отдельный безопасный WeiDU опциональный install + backup/rollback, SHA проверки и реальный Windows preflight после базового hotkey 044.

## Правило продолжения
- Не считать архив выполнением цели. При наличии результата Ctrl+Alt+F11 уточнить runtime 056. Если hotkey 044 работает, подготовить защищённый выпуск 057 с единственным опциональным диагностическим Lua-файлом и проверяемым откатом; не менять исходные 056 BCS/Lua. Если 044 не показывает строку, сначала диагностировать автозагрузку/ключ EEex 1.2.0 без ещё одного боя. Не просить WeiDU.log, scripts.zip или три ZIP пользовательских ресурсов заново.
