# BGXAI — источник реальных событий 066S для многоцелевой охраны — 16.11.2026

## Почему исправляем

Последняя многоцелевая логика BGXAI 080 по-прежнему опиралась на искусственные `{verified=true,active_now=true}`. В прежних модулях 081–084 подтвердили отсутствие доказательства происхождения ручных команд и мгновенной безопасности EPS, но **уже существовал реальный вход подтверждённых попаданий** в установленной 066S: `BGX43Probe.snapshot()`. Поэтому не создаём второй обработчик EEex и не трогаем лечение/зелья/свитки EPS.

## Сделано фактически

- Разработан `BGXAI066S_080_CONFIRMED_HIT_BRIDGE_SOURCE_ONLY.lua` — read-only преобразователь пары **существующих** массивов `events` и `guard_signals`, связывая по `source_event_sequence`, с точными attacker/victim/party и проверкой источника `ENGINE_WEAPON_HIT_CONTEXT`.
- Дедупликация по последнему подтверждённому событию одного нападающего; до 6 записей; сбой при конфликтующих или подменённых совпадениях; пропуск отдельных осиротевших записей после естественного вытеснения из кольцевого буфера 066S. Никаких записей LOCALS, хуков, игровых вызовов или изменений FPS/EPS.
- Формат вывода специально **не** выдаёт `active_now_verified`, `origin_verified`, `queue_empty_verified` или время события: исторический подтверждённый удар — не доказательство продолжающейся атаки. `readiness()` возвращает `HOLD_NO_ENGINE_DISPATCH`. Это полезный подтверждённый источник входных данных, не новый действующий боевой алгоритм.
- На точной Lua-версии установленной 066S SHA256 `50640902ec4c25a2c85e5088d7231678b54445a847b41743c476974236d1d70f`, под макетом EEex, выполнены **настоящие методы этого исходника** `P.onWeaponHit` и `P.snapshot`; проверены один и два разных противника, совпадение ID и отсутствие добавочных игровых записей или приказов.
- `test_066s_snapshot_bridge.lua`: **261/261** assertions PASS; 066S native snapshot integration PASS; прежние BGXAI 080 **82/82** PASS, multi-threat **143/143** PASS; exact pin source replay PASS. Воспроизведение: `python run_bridge_tests.py` из клона репозитория `bg-eet-ai` (нужен `texlua`), с проверкой точных Git blob SHA ранее существовавших 066S/072/080/082.
- Новый исходник SHA256: `3a6ddc5c2fa5f90a53e9b5a0321e1d99cdc62e6e566344ea28a1831f86927078`.

## Статус

**SOURCE ONLY, НЕ УСТАНОВЛЕНО.** Пользовательская EET: установленная BGXAI 066S + EPS18.4. Старый one-file updater и PIN **не менять**. Новый адаптер — вспомогательная часть, которая устраняет недоказанный источник событий предыдущего 080, но не обходит 082/084. Для активного применения необходима надёжная информация о свежести текущей атаки и ручных/EPS действиях и отдельно санкционированная установка с бэкапом и сравнением поведения. Лечение/предметы остаются у EPS.

## Главное правило проекта

Уже выполненные модули не писать повторно; доказывать реальные источники данных прежде, чем применять их. Тестовые мок-данные не равны работе в игре. В рамках активного обращения продолжать безопасную работу без требования `+`; обещания фоновой работы запрещены.
