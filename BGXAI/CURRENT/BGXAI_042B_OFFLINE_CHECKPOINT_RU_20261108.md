# BGXAI 042B — более сильный офлайн-кандидат для охраны с EPS

Дата 08.11.2026, EET Foxx / EPS 18.4 / BGXAI 041. **В играемой установке никаких изменений**, релиза/нового пункта меню пока нет.

## Обнаруженная причина

Две обычные ветки EPS используют `Attack(3)`: в действующем `BDDEFAI.BCS` позиции №1032 и №1045. По IESDP `Attack` непрерывен до смерти цели; `ActionListEmpty()` остается ложным. Из-за этого 11 `ProtectObject` охраны в конце сценария не исполняются. В отличие от Attack, `AttackOneRound(105)` заканчивается после одного раунда, очередь может освободиться.

## Создан 042B source-only

1. Строго проверяется SHA256 исходного реального BCS `86d80953be464a3f10da8e1dc031b907801860b7f1f15b3ea6fb9d25e485f3f5` (2 229 760 bytes).
2. Байт-в-байт неизменённые 11 защитных блоков BGXAI 038/039 перемещаются с позиций 1047–1057 на **1032–1042**.
3. Только две обычные автоатаки после смещения (№1043, №1056) изменяют compiled action ID `3` → `105` (`AttackOneRound`). Другие 1055 блоков **не изменяются по содержимому** (но 11 защитных изменяют позицию).
4. Весь preview BCS имеет 1057 блоков, 2 229 764 байта, SHA256 `8602e8853a9c0e8b1bd5733021e6dd9c9ac73e03beb6c9900ef6ebd09dacb9a0`.
5. Реальные F/иконка 041, команды магии, условия EPS, `BDAI_ATTACK_MODE`, текущие заклинания и правила не переписаны. Без `ClearActions`, без `ActionOverride`, без подмены ручных приказов. Бардовская песня в игре НЕ тестировалась.

**50/50 локальных тестов PASS** включая сохранность всех байтов, кроме двух action ID, модель приоритета на свободной очереди и запрет работы на ином SHA. ZIP `BGXAI_042B_BOUNDED_PRIORITY_SOURCE_ONLY.zip`: 10 049 bytes, CRC PASS, SHA256 `c6aa9070320c5e2262e7d25816ce55fe1d1bb9a4813c8448ab4c29de0e43ed26`.

## Ограничения и следующий этап

НЕТ проверки компиляции/декомпиляции этого BCS под пользовательский WeiDU 25100, нет Windows/install/test и обратного восстановления в WeiDU. Программное преобразование работает только вне игры и не является установщиком. Нельзя советовать ручную замену БЦС. Отложенная ручная команда `Attack` после загрузки сохранения может продолжиться до смерти цели. Другая AI-логика/скрипты иных слотов могут выдавать отдельные долговременные действия. `AttackOneRound` изменяет частоту переоценки цели EPS и может отразиться на уроне/погоне: необходимо одно контролируемое испытание, когда будет безопасный установщик.

**Следующий шаг разработчика**: подготовить guarded WeiDU инсталляцию для ЕДИНОГО существующего `BGXAI_UPDATE.cmd`, с проверкой `041` последним модом, внешними бэкапами `BDDEFAI.BCS`, `WeiDU.log`, TLK; pin исходного SHA и preview хеша, не устанавливать если что-то отличается. Единственный отказоустойчивый rollback строго через WeiDU, без самовольного возврата BCS после неясного WeiDU. Затем один короткий игровой тест Attack ON/F guard ON, проверка песен барда. Источник подтверждения механики: https://gibberlings3.github.io/iesdp/scripting/actions/bgeeactions.htm (§3, §105).
