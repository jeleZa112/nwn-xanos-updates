# BGXAI R29 — первый устанавливаемый экспериментальный прототип, 24.11.2026

**CODE / офлайн-тесты ≠ DEPLOY / игровой PASS.** Этот R29 ещё не запущен в реальной EET. Установка НЕ произведена. Создан прототип, который изменит только `override/BDDEFAI.BCS` посредством WeiDU и только после отдельного буквального согласия игрока.

## Что реально реализовано

Один высокоприоритетный native BCS блок, вставляемый перед существующими **1162** блоками `BDDEFAI.BCS` с побайтовым сохранением прежних блоков. Проверяет, что управляемый **чистый воин-спутник** (не ГГ) с включённой `BGX38_GUARD` использует дистанционное оружие, в quickslot 0 лежит точно `SW1H04`, в quickslot 1 — `BOW05`, а текущий боеприпас — `AROW01`. Если видимый неприятель рядом (<=6), не союзник, очередь действий пуста, нет модального состояния, паники/беспомощности, слота лечения и активного таймера EPS `MO_SpellCast`, выполняется ровно одна команда `SelectWeaponAbility(SLOT_WEAPON0,0)`. Никакого `Attack`, `Stop`, `ClearActions`, смены цели, двигания предметов, вызовов Lua или заклинаний.

Это **привязка к паре предметов, а НЕ проверка уникального ID Халида**. Другой воин с теми же предметами в тех же слотах тоже может переключиться. Если оружие другое или стрелы не `AROW01`, правило не сработает. Обратного автоматического переключения «меч → лук», оценки APR других слотов, отравленных стрел, иммунитетов, дуалов/мультиклассов, дальнего маршрута здесь пока нет. Это не полноценная V3.

### Ограничения безопасности

`ActionListEmpty()` + `MO_SpellCast` и лечебный guard — это *предохранители, а не доказательство* отсутствия ручного приказа, текущего заклинания, атаки/восстановления и всех внутренних действий EPS. Эффект переключения надо проверить игровым A/B, возможно, оно будет запаздывать или не происходить из-за приоритетов скрипта. Новых разрешённых универсальных действий V3 нет.

**Исправление после реального R29 SAFE STOP (24.11.2026):** `RANGED7_MUST_BE_LAST_WEIDU_COMPONENT` больше не блокирует preflight только из-за того, что после RANGED7 стоит другой мод. Вместо этого программа требует ровно одну действующую запись RANGED7 в WeiDU.log, точные SHA исходников и DPLAYER.BCS, `BGXRANGED7/PROOF.json`, SHA staged DPLAYER и целую внешнюю резервную копию. Если запись или доказательства отсутствуют — HOLD без установки. Теперь отчёт при остановке дополнительно сообщает сокращённое имя последнего компонента, число записей RANGED7 и наличие proof. **Новая версия проверена в CI на Windows+Ubuntu:** https://github.com/jeleZa112/nwn-xanos-updates/actions/runs/45423753552 (35 R29 tests, old updater, native/mock, 439 Lua x3). Установка и gameplay всё ещё не выполнялись. Следующий запуск: единственный CMD, пункт **169**, режим **1 READ ONLY**. Не выбирай 2 до отдельного рассмотрения PASS.

## Как запускать через существующий один CMD после публикации release

Используется только `C:\Games\BG_EET_FOXX_NEW\BGXAI_UPDATE.cmd`, новый пункт **169**. Он сам проверяет SHA256 источников через прежнюю систему pinned manifest, открывает меню в Python:
- **1 — native preflight (READ ONLY).** Проверяет реальные хэши BCS DPLAYER/BDDEFAI/WTASIGHT/PRIEST1, EEex R27, EPS, историю компонентов WeiDU и подтверждение RANGED7, компилятор, компилирует собственный BAF во временной папке с `--no-auto-tp2 --noautoupdate --no-exit-pause`, проверяет сохранение 1162 старых блоков и декомпиляцию кандидатного BCS. После PASS игра не изменена.
- **2 — guarded install (typed)**. Только после ввода **`INSTALL_BGXR29_KHALID_BOW_TO_SWORD_PILOT`** и только при пройденном повторном preflight выполняет проверенный внешний backup и WeiDU COPY подготовленного BCS. Проводит сверку хэшей после установки. Поскольку игровой результат не проверен, успешная установка сообщает `R29_INSTALLED_AWAITING_LIVE_AB`.
- **3 — status (READ ONLY)**; **4 — rollback (typed, только если R29 последний в WeiDU.log)**, фраза `ROLLBACK_BGXR29_KHALID_BOW_TO_SWORD_PILOT`; **0 — выход**.

В каждом выполненном режиме (включая безопасную остановку) программа автоматически сохраняет ровно один JSON-отчёт за пределами игры: `%USERPROFILE%\Documents\BGXAI_LIVE_REPORTS\BGXAI_R29_<MODE>_*.json` и печатает `REPORT_FILE=...`. Не требуется копировать длинный текст консоли.

Не вводить install token до успешного пункта 1 и согласованного игрового теста. Ввод неверной фразы ничего не устанавливает. Внешний бэкап находится в `Documents\BGXAI_R29_SAFE_BACKUPS`. Сейвы, BG Voice RU, BG_EET_RU, EPS .tph/.baf, `WTASIGHT.BCS`, `DPLAYER.BCS` и `PRIEST1.BCS` не изменяются скриптом установки.

### Условия реального теста, только после отдельно подтверждённой установки

В тестовом сейве Халид — чистый воин с `SW1H04` в первом слоте и `BOW05` во втором, используемые стрелы `AROW01`, общая ИИ ВКЛ, BGX38 охрана ВКЛ. Выполнить повторную загрузку, сблизить противника при включённом луке, проверить отсутствие лишнего выстрела, переключение на меч, отсутствие дружественных атак, сохранение приоритетов лечения и ручных команд, затем отключить F-охрану и подтвердить отключение пилота. Другие источники оружия должны быть NO-OP. При нарушении поведения остановить и выполнить rollback (если последний WeiDU), не удалять вручную.
