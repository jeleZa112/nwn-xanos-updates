# BGXAI 060 — первый отдельный BCS-исполнитель, 11.11.2026

## Причина смены подхода

Цель — командный ИИ EET+SCS 35.21+EEex+EPS 18.4. Неделя на проверку F-охраны была неэффективной. EPS 18.4 уже предоставляет автоматическую магию, способности и режимы; нельзя заменять весь EPS ради одного режима охраны. 056 Lua+EEex поставил реальный запрос `BGX52_REQ_SLOT=3` после попадания Шанка по Jade (`H=1 HE=0 A=1 P=1 Q=3 TTL=82`), поэтому новая линия — BCS-исполнитель.

Последняя проверка пользователя: у P2 и P4 относительно Jade `ARE=true`, `LOS=true`, `OK=true`; поэтому дополнительный area/LOS-фильтр 059 **не признан исправлением**. Оставить 059 отдельным source-only, не ставить его на ПК ради этой проблемы.

## Создан новый компонент

GitHub branch `bg-eet-ai`: `BGXAI/fox_new/experimental_060_direct_response_source_only/`, 8 текстовых файлов (генератор, BAF, builder, установщик, два набора тестов, README, манифест).

Базовая 056: ожидается 1065 CR-блоков, SHA256 установленного `override/BDDEFAI.BCS` `054c1c8e99b4d8ef8fb541287844d46cb81faa4c320f59c3f39f82f8bf0ab87c`; установленного Lua `override/M_BX43.lua` `35e450b6600f0fc65d47e535126a52e0303c360033307fa920776faec3f581ab`. Никакие исходники/файлы 056 не переписаны.

`BGX60_RECEIVER.baf` заменяет 8 только собственных BCS-приёмников 056 на 14 новых (2 cleanup + 6 direct + 6 fallback), вставка на том же 1-based слоте 1032, сохраняя 1057 остальных EPS/старых блоков побайтно:
- direct: подтверждённый EEex hit через Q/TTL + F=1 + idle + видимость защищаемого + видимость `LastAttackerOf(PlayerN)` → `AttackReevaluate(...,30)`;
- fallback: тот же подтверждённый hit, F=1, idle + видимость/близость защищаемого → `ProtectObject(PlayerN,6)` без прежнего `See(NearestEnemyOf(PlayerN))`;
- `BGX60_LAST_BRANCH=1/2`, `BGX60_LAST_VICTIM=N` выставляются при выборе BCS-ветки. Это НЕ доказательство совершенной атаки/боевого результата.

На каждом шаге `ActionListEmpty`, `ModalState(NONE)` и F=1 сохраняют приоритет имеющегося действия. Нет `ClearActions`, Lua атак, принудительных заклинаний, перезаписи авто-кастов. Риск: `AttackReevaluate(…,30)` не гарантирует завершение спустя 30 AI ticks, что отмечено IESDP; возможно он задержит EPS касты. Перенос на игру только после проверки.

`BGXAI60_BUILDER.py`: strict SHA pinned 056, compile BAF во временном каталоге штатным WeiDU/IDS/TLK игры, verify 14 блоков (action ID 30/36/115/134/87), patch BCS, гарантии 1057 прежних блоков. `BGXAI60_INSTALL.py`: read-only status / preflight по умолчанию, opt-in install/rollback с двойным подтверждением, проверкой последних записей WeiDU, резервной копией и проверкой после установки. Источник остаётся в отдельной папке; существующий однофайловый BGXAI_UPDATE.cmd не подменять без проверки pin.

## Непроверено / следующий пункт

**Не было реальной компиляции WeiDU с установкой пользователя и игрового исполнения.** Следующее действие — реальный, строго read-only preflight 060 при закрытой игре, который проверяет точную 056 и компилирует 14 BAF блоков в temp без изменения EET. Если compile FAIL — исправить не трогая установленную 056. Если PASS — отдельно подтверждённая установка с WeiDU backup и **один** игровой тест с близким охранником. Запрещено повторять циклы десятков одинаковых боёв, собирать 45 тыс. ресурсов или заново требовать скрипты/логи.

Нет фоновой работы; реальный Windows-компилятор/игра недоступны в текущем контейнере. Версия 060 source-only, в игре по-прежнему 056.
