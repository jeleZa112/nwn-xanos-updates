# BGXAI — реальное продолжение 066S: устранён конфликт запросов охраны и лечения
Дата: 2026-11-14. Состояние: **исходники и тесты, НЕ установлено**. Остаются live 066S + EPS 18.4; 067 HOLD; предыдущие прототипы source-only.

## Что нашлось при сверке исходников

Последний готовый source-only патч `M_BX43_066S_CAPABILITY_CANDIDATE.lua` (SHA256 `954bb400ccc7e39aa0040460d167b51584892d7bd58237bf78ed05781eb7da70`) мог в опциональном capability-mode создать одновременно `BGX52_REQ_SLOT` (охрана) и `BGX66_S_HEAL_SLOT` (лечение) одному актёру, особенно мультиклассу воин/жрец. Порядок был «охрана -> лечение», хотя по контракту срочное лечение важнее. Кроме того, после истечения краткого Lua-резерва 45 тиков всё ещё мог сохраняться BCS-запрос на 300 тиков, который другой канал не проверял. Это реальная ошибка в исходном коде подготовленного патча, **а не утверждение о воспроизведённой проблеме в игре**.

Пять новых Lua/EEex-mock тестов добавлены. **До исправления 3 из них падали**, в том числе двойной запрос одному актёру и обе несовместимые pending BCS-переменные. Ошибка устранена:

1. При подтверждённой, явно включённой capability-mode ветви сначала `S.onHit` резервирует лечение, затем `T.prepare` резервирует защиту **только свободному другому актёру**.
2. Охрана не назначается, когда у него есть активное лечение/Shield: читаются реальные канальные LOCALS и Lua-резерв.
3. Лечение не назначается, когда у него есть активная заявка охраны: проверяются настоящие LOCALS и Lua-резерв.
4. При отсутствии или ошибке чтения запрет; никакого предположения, что разрешение существует.
5. При `T.capabilitySourceVerified=false` выполняется точный старый порядок 066S; его нельзя менять без доказательств.

Изменены ровно **5 локализованных участков** предыдущего Lua-кандидата; `arbiter_exact_diff.py` точно возвращает исходник прежнего V2. Ни одного `ClearActions`, нового заклинания, ручного игрового действия, изменения BCS/BAF или нового хука EEex.

## Что не решено и что делать дальше

НЕТ достоверной **игровой** информации через EEex 1.1.7 о наличии свободного действия/очереди EPS, происхождении ручной команды, текущем доступном вооружении, dual/kit/shapechange и точном ID нападающего у BCS-получателя. Их **запрещено** заменять ложными boolean-свидетельствами или обходить `ActionListEmpty()`. Поэтому capability gate остаётся **OFF по умолчанию**, никаких изменений игры/установщика не производилось. Следующий полезный этап — минимальная демонстрация реальной координации на штатной 066S без перехвата ручных приказов, а НЕ публикация ещё одного неработающего номерного мода. Установку только после доказательства сравнительного преимущества, точных хешей, проверенного резервирования и отдельного разрешения пользователя.

Сохранение: `CURRENT/` checkpoint, `BUILD/BGXAI_066S_GUARD_HEAL_SHARED_PRIORITY_SOURCE_ONLY/`, GitHub `bg-eet-ai` branch, журналы проекта. У пользователя сейчас НЕ надо спрашивать новую команду PowerShell и не надо устанавливать ZIP.
