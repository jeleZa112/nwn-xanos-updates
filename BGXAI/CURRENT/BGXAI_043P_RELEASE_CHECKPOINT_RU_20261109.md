# BGXAI 043-P — отдельный EEex-наблюдатель / релиз-кандидат (09.11.2026)

## Что действительно сделано

Создан пакет исходников BGXAI 043-P `0.3.14-043-PROBE`, позволяющий отдельно поставить через WeiDU наблюдатель начала атаки по союзнику в `override/M_BGX43Probe.lua`. EEex v1.1.7 API проверен по официальному тегу. Наблюдатель только собирает в Lua последние 64 события атаки и может один раз вывести уведомление `BGXAI 043 observer: party attack seen (NO AI COMMANDS)`. Ни один боевой приказ не создаёт; не делает дисковых логов или сетевых запросов.

Отдельный `BGXAI43_PROBE_INSTALL.py` проверяет SHA256 установленного исходного боевого BCS 042B `8602e8853a9c0e8b1bd5733021e6dd9c9ac73e03beb6c9900ef6ebd09dacb9a0`, наличие EEex `override/M___EEex.lua` и InfinityLoader, 042B последним WeiDU-компонентом; требует остановить игровые процессы. До установки создаёт и проверяет внешние копии ресурсов; производит запись через `setup-BGX43.exe` с TP2. Обратный ход — только WeiDU после сверки резервных копий, установленного Lua и последнего мод-компонента. Инсталляция строго после явного `YES`, модификация `BDDEFAI.BCS`/TLK/UI.MENU не предусмотрена.

## Автообновлятор

Ранее 042B установлен у пользователя в игре и работает. В том же публичном скрипте `BGXAI/BGXAI_SYNC.ps1` добавлены пункты:

- **18:** READ-ONLY предпросмотр условий установки 043-P, не скачивает исходники и не записывает игровые файлы;
- **19:** загрузка и проверка 043-P source-only по SHA256;
- **20:** экспериментальная WeiDU-установка с отдельным `YES`;
- **21:** статус 043-P READ-ONLY;
- **22:** штатный откат с `YES` и проверкой резервных копий.

Пункты **1–17 сохранены**, работающие BGXAI 041+042B не переустановлены; NWN/main не менялся.

Запись `BOOTSTRAP_PIN.json` указывает на неизменяемый диспетчер GitHub **`96e3e797ecedb1c49f67b76494ca8827ca6ec012`**, 24 864 байт, SHA256 **`6e95696df1a32e8be94c5d573449a22e647772e2ae53bf6d30bb286b2f566b54`**.

**Предыдущая проблема**: у пользователя старый локальный `BGXAI_UPDATE.cmd` получал по постоянному URL закешированный pin, поэтому запускал `9e7a6f...`, несмотря на обновлённый GitHub. Отдельно исправлена версия bootstrap в публичном `BGXAI_UPDATE.cmd` (commit `d270a2814ca62aa8b8784e35374039a16687195c`) с уникальным `bgxnonce` для скачивания указателя версии. **Локальный CMD пользователя ещё не заменён**, это отдельное действие пользователя, иначе новые пункты могут не появиться.

## Границы достоверности

**НЕ запускался** у пользователя на Windows WeiDU и реальной EEex LuaJIT, никаких игровых файлов не менял. В качестве проверки надо сначала скачать исправленный однофайловый `BGXAI_UPDATE.cmd`, сохранив оригинал как резервную копию, затем запускать только **18 — READ-ONLY** и предоставить вывод. Пункт 20 **НЕ запускать**, пока не подтверждены EEex prerequisites и исходный BCS. Далее одна контролируемая установка и естественная игровая проверка, без повторения боя с Шанком.

Python-модель «перехватчик/прикрытие» и модельная проверка 043 не управляют игрой: для фактической выдачи приказов нужно доказать происхождение ручного приказа и безопасную очередь. Не обещать это как готовый AI 043.
