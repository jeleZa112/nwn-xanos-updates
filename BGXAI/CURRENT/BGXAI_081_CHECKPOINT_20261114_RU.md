# BGXAI 081 — подтверждение границ EEex и очередь EPS (14.11.2026)

**Состояние:** только офлайн, **не установлено**. В игре последняя реально подтверждённая BGXAI 066S; F-охрана и EPS 18.4 не изменены. Пользователь просит продолжать безопасные этапы самостоятельно, без согласований, но не вводить неподтверждённый активный боевой код.

## Достоверные исходные данные

- В библиотеке проекта сохранён кандидат работающей `M_BX43.lua` 066S, exact SHA256 `50640902ec4c25a2c85e5088d7231678b54445a847b41743c476974236d1d70f`. Его источник был прочитан и проверен байт-в-байт в текущем сеансе.
- В `P.init()` он регистрирует `EEex_Action_AddSpriteStartedActionListener` и `EEex_Sprite_AddBlockWeaponHitListener` (второй при наличии). В `P.onStarted` доступно `action.m_actionID`, а в обработчике попадания читается `attacker.m_curAction.m_actionID`. Эти наблюдения НЕ подтверждают отсутствие очереди EPS и автора приказа.
- Сам исходник имеет `P.manualOriginKnown = false`; в `P.snapshot()` `origin_verifiable = false`, `queue_verifiable = false`.
- Существующий 066S сам записывает LOCALS для BCS (`BGX52_*`, `BGX66_S_*`): его нельзя целиком называть «пассивным».
- В документации EEex `EEex_Action_AddSpriteStartedActionListener` помечен как **недокументированный**; предоставлен API добавления действий в очередь, но не проверено независимое чтение этой очереди в текущей v1.1.7. Документация: https://eeex-docs.readthedocs.io/en/latest/EEex%20Functions/Action/ и https://github.com/Bubb13/EEex/releases .

## Реализовано в 081

1. `BGXAI081_ACTION_PROVENANCE_READONLY.lua`: получает (при наличии) числовой ID текущего действия, всегда возвращает `action_origin='UNKNOWN'`, `queue_empty=nil`, `manual_command=nil`, `safe_to_dispatch=false`; `arbitrate()` всегда HOLD даже для входных «идеальных» внешних параметров. Нет игровых команд/хук-регистраций/LOCALS.
2. `audit_live_081.py`: чтение `override/M_BX43.lua` с **точным SHA 066S**, опционально проверка BCS по SHA `fb435d82e6c3e0ebea1d6a9532753921bd5411d70ac0677dc1fd8ec483380476`; только JSON в консоль, любое несовпадение BLOCKED. Цель — проверка совпадения действующего исходника с сохранённым, **не** проверка динамики EEex.
3. `test_081.lua`: **289/289 assertions PASS** (включая отсутствие возможности установить разрешение из ID=0); `python -m unittest test_081.py`: **13/13 PASS**, включая SHA исходника и отказ на настоящем BCS версии 041.
4. `verify_release_081.py`: **7/7 SHA256 PASS**, проверка отсутствия игровых команд/записей PASS. ZIP SHA256 `3fb555fe491de87b8f15295cf036548f9a47b156171beeb492a639477c4d9ecc`, размер 9623 байта.

Оригинальный активный `M_BX43.lua` не включён в публичный пакет. Никаких игровых файлов/WeiDU/SCS/EPS/обновлятора и резервных копий не изменено.

**Результат:** источник наблюдателя в 066S подтверждён; свободная очередь и автор действия **не подтверждены**, поэтому немедленное включение 080 недопустимо. Следующий безопасный этап: тестировать совместимость 080+081 при неопределённом действии/очереди и подготовить **отдельный диагностический EEex runtime-пробник без боевых приказов**, только после оценки рисков установки.
