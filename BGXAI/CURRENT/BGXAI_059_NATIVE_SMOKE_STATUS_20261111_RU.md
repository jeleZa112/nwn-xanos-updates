# BGXAI 059 — проверка наличия EEex API и подготовка нативного smoke test

Дата: 11.11.2026.

## Подтверждено пользователем

В текущей EET v2.6.6.0 через Lua-консоль получено: `AREAAPI=function SIGHTAPI=function`. Следовательно, обе требуемые функции `EEex_UDEqual` и `EEex_Sprite_ForAllOfTypeStringInRange` присутствуют. Это проверка наличия функций, **не** проверка рабочего результата native LOS и **не** доказательство безопасности синхронного вызова внутри hit listener.

## Реально выполненная разработка

Создана отдельная однострочная, read-only команда `BGX59_NATIVE_SMOKE_READONLY.lua`. Она дважды проверяет видимость Jade (P3, zero-based slot 2) из позиций защитников P2 (slot 1) и P4 (slot 3). Для каждого отображает `ARE`, `LOS`, `OK`; отдельно проверка `pcall` защищает от Lua-ошибки. Параметры API: `[ANYONE]`, 128px, `true` (LOS), `false` (non-sprite). Нет изменений LOCALS, боевых команд, манипуляций файловой системой или установки в игру. Не путать этот консольный smoke с полноценным on-hit нагрузочным тестом.

Настоящий Lua 5.4 через системную `liblua5.4`: **10/10** mock tests PASS (положительный LOS, разные области, препятствие, отсутствие API, исключение из API, отсутствие объектов, ошибки сравнения и отсутствие команд-мутаторов).

Код и тесты в GitHub `BGXAI/fox_new/experimental_059_guard_visibility_source_only/native_smoke/`, ветка `bg-eet-ai` (четыре файла, все сверены по точным Git blob SHA). Archive в Library `/BALDURS_GATE_EET_AI/BUILD/BGXAI_059_NATIVE_SMOKE_READONLY/BGXAI_059_NATIVE_SMOKE_READONLY.zip`, SHA256 `b24dcdde629815458881280bc2b2826338b4e16ae365091ed901c9b078c49094`. В ZIP манифест и три файла, CRC и SHA сверены.

## Следующее действие для пользователя

Не скачивать архив. При открытой EET на спокойной карте (желательно после обычного сохранения) скопировать содержимое `BGX59_NATIVE_SMOKE_READONLY.lua` в ту же доступную Lua-консоль, куда ранее вводились `BGX43Probe.snapshot()` и `AREAAPI`. Не нужно атаковать Шанка. Прислать две строки, начинающиеся `BGX59 G=P2...` и `BGX59 G=P4...`.

`ARE=false` → разные/непрочитанные ARE, LOS не вызывается, OK=false ожидаем.
`ARE=true LOS=false OK=true` → запрос видимости выполнен, цели в радиусе/LOS не найдено.
`ARE=true LOS=true OK=true` → выборка видит цель и расстояние до неё не более 128px.
`ARE=true LOS=false OK=false` → native EEex вызов не завершился успешно или функция потеряна.

## Ограничения и версия

Установлена только BGXAI 056. Выпуск 059 — source-only, WeiDU installation candidate **НЕ запущен**. До отдельного разрешения пользователя не изменять игровые override/WeiDU. Прежние 35 офлайн-тестов 059 и новые 10 smoke-тестов — разные наборы (**45/45** совокупно в моделях); успех native EEex по ним не гарантирован.
