# BGXAI — 16.11.2026, EPS-first multi-threat guard

## Что именно реализовано

**SOURCE ONLY, НЕ УСТАНОВЛЕНО.** Расширена прежняя архитектура BGXAI 080 (одна угроза) методом `reviewMultipleThreats()` для двух/нескольких **подтверждённых** угроз. При двух разных атакующих и двух свободных F-защитниках вычисляет глобальное распределение: не занимает единственного пригодного для второй цели защитника первым боем. Проверенная цель — точный ID нападавшего, не `NearestEnemyOf`. Приоритет у уязвимого тыла и более раненного (при HP <25% новое назначение охраны не создаётся: приоритет EPS лечению). Запрещены вмешательства в ручные приказы, магию, бафы, песни, ловушки, предметы и лечение EPS. Только advisory, 0 LOCALS / 0 действий / 0 игровых модификаций.

Старые 062 — одна угроза, 072 — точный нападавший и EPS guard gate, 078 — healer, 080 — один hit, 081–083 — отсутствие подтверждённого EEex provenance/queue. Всё повторно использовано и **не переписано**. Недавние SOURCE-only лечебные кандидаты 16.11 остаются HOLD за дублирование EPS.

## Неразрешённая граница

Событие action-started и `m_actionID==0` **не доказывают** пустую очередь EPS и источник ручного приказа в EEex 1.1.7. Поэтому из реальных 083 наблюдений модуль возвращает HOLD. Нельзя утверждать, что охранник уже самостоятельно изменил поведение в игре: установленной остаётся 066S + EPS18.4. Разрешение на изменение override/WeiDU/update menu отсутствует. Пользовательский пункт 93 ранее READ_ONLY_PREFLIGHT_PASS; не повторять. Пункт 94 относится к старому пилоту и не устанавливает новый многозадачный алгоритм.
