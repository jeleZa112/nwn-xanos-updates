## Реальный исходный сбой

Живой удар Шанка по Jade: `H=1 HE=0 A=1 P=1 HIT=recorded BR=PREPARED_BCS_ONLY`. В тот же paused runtime: `G=P4 V=P3 F=1 Q=3 MOD=0 TTL=82`. Пользователь уточнил, что P4 оставался на улице, пока Jade и Шанк были внутри помещения. EEex событие, Lua-выбор, запись LOCALS подтверждены; BCS-исполнение не подтверждено. Разные ARE в конкретном эпизоде не измерены и не предполагаются автоматически.

## Наследование релизов

- **056 (0.3.22)** — последняя подтверждённая установка. Активный BCS содержит 1065 блоков, SHA256 ранее сверен. В проекте не менять без безопасного релиза с WeiDU backup/rollback.
- **057** — диагностика, SOURCE ONLY, НЕ УСТАНОВЛЕНА.
- **058** — уже опубликованный экспериментальный SOURCE-ONLY фильтр `EEex_UDEqual(guardian.m_pArea,victim.m_pArea)`. Полный `M_BX43.lua` доступен в GitHub по `BGXAI/fox_new/experimental_058_same_area_source_only/`, blob SHA `ea410a7d1c0babde9b8aa6df5a2e55164bd55f56`; не дублировать как новый релиз.

## Что реально добавлено в 059

1. `BGX59_ELIGIBILITY.lua` (встроен в интегрированный `M_BX43.lua`). Для всех F=ON и `MOD=0` кандидатов, уже отфильтрованных 058 по ARE, проверяет ненулевой `m_pArea`, `EEex_UDEqual`, затем `EEex_Sprite_ForAllOfTypeStringInRange(guardian,"[ANYONE]",128,callback,true,false)` с жертвой среди видимых результатов. Все ошибки API дают отказ, а не приказ.
2. Если несколько подтверждённо доступных защитников, выбирает ближайшего с устойчивым tie-break по портретному слоту. При отсутствии — не пишет новый Q.
3. Исходный обработчик попадания, Lua LOCALS writer, таймеры BCS и `ProtectObject` в 059 не менялись по структуре. Источник **не** вызывает новых действий игрока.
4. Пространственный фильтр НЕ доказывает маршрут; BCS по-прежнему отдельно проверяет `ActionListEmpty()`, врага, TTL и `Range(PlayerN,10)`. Живой результат 059 не подтверждён.
