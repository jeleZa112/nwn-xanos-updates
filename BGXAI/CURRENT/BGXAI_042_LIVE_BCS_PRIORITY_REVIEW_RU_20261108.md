# BGXAI 042 — разбор реального BDDEFAI.BCS после 041
**Дата:** 08.11.2026. **Ветка:** `bg-eet-ai`. **Игровая версия:** EPS 18.4 + BGXAI 0381/039/040/041; Insane, SCS 35.21, EEex. **Статус:** офлайн-анализ + беззаписная симуляция, НЕ установленный патч.

## Входные данные
Игрок предоставил только **текущий** `C:\Games\BG_EET_FOXX_NEW\override\BDDEFAI.BCS` (не исторический архив). Размер **2 229 760** байт; SHA256 **`86d80953be464a3f10da8e1dc031b907801860b7f1f15b3ea6fb9d25e485f3f5`**, совпал с реальным Windows read-only аудитом пункта 12. Содержимое BCS и полный мод EPS не публиковать в открытом GitHub из-за прав автора; опубликовать только созданные нами инструменты анализа и технический отчёт.

## Обнаружена ошибка инструментального счётчика 042 v1
Исходный regex v1 искал только `AC\nID...` и **не замечал первого действия** внутри каждого `RE\n100AC\nID...`. Поэтому строка `Actions:` из первой проверки неполная. Исправленный анализатор учитывает обе формы, а исходное количество 1057 BCS-блоков достоверно. Обнаружено **2262 действия**.

## Точный результат разбора
- **2 блока с длительной `Attack()` (action ID 3): №1032 и №1045.** Оба проверяют `ActionListEmpty()` (trigger 16427), `BDAI_DISABLE_ATTACK` и условия навыков/доступности цели; **НЕ** проверяют `BDAI_ATTACK_MODE` и `BGX38_GUARD`.
- **11 блоков с `ProtectObject()` (action ID 87): №1047–1057.** Все требуют `ActionListEmpty()`, включённый `BGX38_GUARD`, а также собственные ограничения по расстоянию/состояниям/таймеру. Они расположены ниже обоих блоков `Attack()`.
- Всего **18 блоков** с условием `BGX38_GUARD`: №1–7 обслуживают переключение F/значок/сообщения и №1047–1057 — защитные действия.
- Всего **59 блоков** с `BDAI_ATTACK_MODE`: 39 с `NoAction()` (0), 18 с `Spell()` (31), 2 с `SetGlobal()` (30), из двух последних один дополнительно содержит действие 269. **Это не 59 команд атаки.** Массовая блокировка по `BDAI_ATTACK_MODE` повредила бы функциональность EPS.
- В файле нет действий `AttackOneRound()` (105) или `AttackReevaluate()` (134), зато есть две длительные `Attack()` (3). Согласно IESDP, `Attack()` может сохраняться до гибели цели и не обеспечивает постоянной свободной очереди.

## Механизм и ограничения уверенности
Когда и автоатака, и охрана могут сработать на свободной очереди, более раннее правило №1032/1045 с `Attack()` потенциально занимает её надолго; тогда `ActionListEmpty()` в защитных правилах №1047–1057 не выполняется. Этот механизм согласуется с фактическим успешным защитным действием при личной настройке EPS `Атаковать врагов=ВЫКЛ`. Это сильная **проверенная структурная причина**, а не прямое доказательство каждого игрового поведения. Касты/предметы в EPS идут раньше защиты и могут законно задержать её; не применяем общие сбросы очереди или принудительное прерывание.

## Минимальный вариант 042A — только офлайн-дизайн
Условие `Global("BGX38_GUARD","LOCALS",0)` добавляется **только** к двум веткам обычной автоатаки; при F OFF EPS действует по-старому, при F ON автоматическая `Attack()` не занимает очередь до команд охраны. В симуляции поверх точной пользовательской копии изменились **только блоки 1032 и 1045**; условные действия всех 1057 блоков, 11 защитных веток, 59 блоков настройки, 2262 команд и остальной исходный текст сохранены. In-memory SHA256 условного результата: `adb3b888123278810ade0f3cffdcc2c102558ae16871ddcb4ecc044641377149`, +150 байт. **Никакой файл патча в игру не записан.**

Этот вариант является **приоритетным режимом охраны**, а не гарантией одновременной независимой автоатаки при отсутствии угрозы: при F ON защитник ориентируется на `ProtectObject()` и может не нападать на врагов, не угрожающих союзникам. Он не снимает уже запущенную `Attack()` при включении F на ходу; не должен отменять ручной удар, спелл или бардовскую песню. Требуется проверить поведение выключения F во время текущего `ProtectObject()`.

## Следующие действия
1. Подготовить source-only 042A как **точечный WeiDU-патч** `BDDEFAI.BCS` с проверкой исходного SHA256; не распространять чужой скомпилированный BCS, не изменять NPC/вражеские BCS.
