# BGXAI — обязательное правило: только штатный автообновлятор

Дата: 11.11.2026. Решение пользователя: «возьми за правило работаем с автообновлятором».

## Обязательный порядок

1. Все новые версии, статусы, проверки, установка и откат BGXAI идут через **существующий** `BGXAI_UPDATE.cmd` в `C:\Games\BG_EET_FOXX_NEW`. Пользователь не должен скачивать отдельные ZIP, вручную копировать BAF/BCS/Lua, запускать отдельные CMD/Python/PowerShell ради штатного пути.
2. Стандартная архитектура: `BGXAI_UPDATE.cmd` читает `BGXAI/fox_new/BOOTSTRAP_PIN.json`, скачивает только скрипт `BGXAI/BGXAI_SYNC.ps1` из проверенного неизменяемого коммита, сверяет точные длину и SHA256, затем запускает меню; источники релизов имеют отдельный SHA256-манифест.
3. Для нового действия сначала готовятся исходники, тесты, версии/манифест и безопасный пункт меню. Затем обновляются script pin/commit, без замены CMD. Установка — исключительно после прохода read-only preflight, резервной копии WeiDU и отдельного подтверждения рискованной операции.
4. Нельзя выдавать офлайн mock-тесты за результат реального EEex/WeiDU или уверять, что версия установлена, пока не проверено. После сбоев не повторять установку автоматически.
5. Не просить повторно большие игровые архивы и не отправлять пользователя в бесконечные проверки одной охраны; придерживаться долгосрочной цели полноценного автономного ИИ при сохранении функций EPS.

## Следующий шаг пользователя

Закрыть игру/InfinityLoader, **запустить тот же существующий `BGXAI_UPDATE.cmd`** из корня EET и выбрать **61**. Передать точный текст/скриншот preflight. Не скачивать ZIP 060 и не запускать `BGXAI60_PRECHECK_READONLY.cmd` отдельно. Если 61 сообщает STOP — остановиться и разбирать его вывод; не переустанавливать 056.
