# BGXAI 045B — исправлена ошибочная проверка последнего WeiDU-мода

Дата: 2026-11-09 (пользователь в +07:00). Ветка GitHub: `jeleZa112/nwn-xanos-updates`, `bg-eet-ai`.

## Наблюдаемый сбой (045)

Пользователь последовательно показал, что официальный read-only preflight пункта 28 подтверждает:

```
042B/043P/044 installed: True/True/True
044 last: True; 045 installed: False; 045 last: False
Original 042B/043P/044 SHA256 match: True/True/True
Short Lua files exist: False/False
BGXAI 045 PRECHECK: BASELINE OK. NOT INSTALLED.
```

Затем вариант 045 пункта 30 завершился до запуска WeiDU:

```
BGXAI 045 BLOCKED: Expected BGX44 as LAST WeiDU component
BGXAI STOP: BGXAI 045 installer returned code 1
```

Это означает, что установка 045 НЕ ПРОВЕДЕНА. В реальном игровом окружении подтверждены работающие 042B, установленный 043P/044 и отсутствие обоих коротких Lua 045. Причина расхождения с высокой вероятностью в прежней Python-проверке: `BGX44[^~]*\.TP2~\s+#\d+\s+#0(?:\s|$)` требовала конкретный числовой суффикс `WeiDU.log`; в независимом preflight PowerShell поиск базировался на собственно имени TP2. **Реальная строка WeiDU.log от пользователя пока неизвестна; конкретный суффикс не выдумывать.**

## Исправление: 045B

Выпущена отдельная immutable директория `BGXAI/fox_new/release_045b/`, версия `0.3.16b-045-RESREF-FIX`. Точное имя `BGX44/SETUP-BGX44.TP2`, включая допустимые различия регистра, разделителя пути и формата суффикса, проверяется в последней активной строке. Строгая проверка имени мода и позиции сохранена; чужой TP2 и имитации имени отклоняются. Если шаблон всё равно не совпадает, ошибка теперь выводит краткое фактически полученное значение последней строки WeiDU для диагностики без новых установок.
