# BGXAI — приоритетный выбор оружия V2 (21.11.2026)

## Текущий фокус
**Только завершение интеллектуального выбора оружия.** Не начинать следующую тактическую ветку, пока не получена игровая проверка приоритетного оружия.

## CODE — реализовано в исходниках
- Старые модули сохранены: `BGXAI_WEAPON_CHOICE_ADVISORY_V1.js` и `BGXAI_WEAPON_TRAITS_ADVISORY_V1.js` (их не переписывали, используют те же расчёты эффективных THAC0/APR/урона, сопротивлений, стоимости переключения, бонусов класса/кита/расы и dual/multi).
- Новый `BGXAI_WEAPON_PRIORITY_ENGINE_V2.js`: read-only интеграционный слой поверх этих двух модулей. Проверяет ВСЕ четыре оружейных быстрых слота, наличие боеприпасов для каждого дальнего оружия/метательного, совпадение статусов оружия и цели с одним снимком, класс/кит/дуал, полный учёт двух рук, стоимость смены, принадлежность одной ARE, явную враждебность (через старый V1), незанятость EPS, отсутствие приказа игрока/каста/лечения.
- Исправлена логическая ошибка V1: `KEEP_CURRENT` не является доказательством наилучшего оружия, если другой занятый слот не оценён. При таком случае V2 выдаёт HOLD, не ложное «лучшее».
- Подавляет переключение на каждом тике: нужны 2 последовательных наблюдения одной цели/снаряжения, затем задержка после совета. ID текущего снимка может законно меняться: устойчивость определяется отдельными отпечатками экипировки, защиты цели и итоговой боевой статистики. Не подменять уникальный ID кадра постоянным.
- Результат `ADVISE_PRIORITY_QUICKSLOT_ONLY` **никогда не исполняемый**: `executable=false`, `dispatchAuthorized=false`. Нет вызова экшнов EEex/BCS/WeiDU, нет редактора игровых файлов. Булево `verified` во входе не является доказательством наличия достоверного EEex runtime-адаптера.
