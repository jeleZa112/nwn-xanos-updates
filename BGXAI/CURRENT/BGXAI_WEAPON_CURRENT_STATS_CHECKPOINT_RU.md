# BGXAI — 21.11.2026: оружие по текущим характеристикам + временные бафы

## Архитектура: решение пользователя принято

**Основной источник для сравнения:** текущие эффективные характеристики персонажа, полученные через EEex 1.1.7 `sprite:getActiveStats()` / `EEex_Sprite_GetActiveStats(sprite)`; не собирать APR заново по `WSPATCK.2DA` и уровням, если достоверный финальный APR уже известен.

**Принципиальная оговорка:** эти характеристики описывают текущий контекст, а не автоматически вычисленные THAC0/APR/урон для всех остальных quickslot. Для каждого невыбранного оружия всё ещё требуется проверенный пересчёт по тому же активному снимку с его специальной способностью, боеприпасами, владением, текущими эффектами, стрельбой вблизи и второй рукой. Если данных нет — `HOLD`, а не подстановка APR текущего оружия.

**Временные бафы:** fingerprint активных параметров + fingerprint активных бафов; появление/истечение Haste, Improved Haste, изменения Силы, боевых штрафов и других эффектов сбрасывает двухкадровую стабилизацию V3. Бафы/профильные бонусы нельзя добавить дважды. Чужие действия и EPS не перебивать. В боевом движке ещё не подтверждён способ полного перечисления и аттестации эффектов.

## Реально изменено — CODE

- Создан **чистый Lua слой** `BGXAI_WEAPON_CURRENT_STATS_BRIDGE.lua` с `audit()` / `choose()`: принимает активный снимок, удостоверяет общий buff/stat fingerprint всех кандидатов, различает наблюдённый выбранный слот и отдельно рассчитанные альтернативы, не зависит от 2DA. Делегирует действующим V4/V3. Никакого игрового dispatch.
- **Дополнен ранее существующий** `BGXAI_EEEX117_WEAPON_READONLY_PROBE_V1.lua`: пытается безопасно прочесть объект `getActiveStats()`, но не называет его доказательством полного APR, полной очереди ручных/EPS приказов или характеристик альтернативных слотов. При ошибке возвращает неполное наблюдение и HOLD.
- Прежний V5 WSPATCK-аудит не переписан, доступен как диагностическая проверка на случай недостоверности финальных значений.
