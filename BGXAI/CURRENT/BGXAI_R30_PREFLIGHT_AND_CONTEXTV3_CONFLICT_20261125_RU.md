## Фактически выполнено

Создан **read-only** SHA-pinned Python preflight `BGXAI_R30_QUEUE_DEPLOY_PREFLIGHT_RO.py` и десять отдельных регрессионных тестов. Скрипт принимает игровой корень EET и файл **неустановленного source-only кандидата**; до запуска установки он только читает:

- полный `WeiDU.log` с реальным порядком компонент; фиксирует номер R27 и настоящий последний компонент, не требует, чтобы R27 был последним;
- установленный `override/M_BGXR27.lua`, проверяет исторический SHA256 и bootstrap;
- реальные установленные `EEex_Action.lua`, `EEex_Sprite.lua`, EPS `core_base.tph` по SHA256, полученным из прежних пользовательских отчётов;
- ровно переданный SHA-pinned source-only Lua-кандидат и запретные конструкции для игровой команды/второго hook;
- повторно сравнивает SHA `WeiDU.log` и `M_BGXR27.lua` в конце чтения.

Отсутствие файла, reparse/symlink, неизвестный компонент, второй экземпляр R27, наличие R30, изменённый Lua, другое содержание EPS/EEex → `HOLD_NOT_READY_FOR_INSTALL`. Даже полностью совпавшая метаинформация возвращает `SOURCE_AND_HISTORY_READ_ONLY_PASS_INSTALL_STILL_UNAUTHORIZED`, **не** выдаёт права устанавливать. Нет записи даже в локальный JSON: вывод только в stdout и никакой модификации игры.

Локально `10/10` Python tests PASS; GitHub Actions [45453114204](https://github.com/jeleZa112/nwn-xanos-updates/actions/runs/45453114204): шаг R30 **PASS** в Linux, Windows static PASS. **Общий workflow в целом FAILURE**, поскольку одновременно были изменены исходники R27 другим обновлением (`ACTION_CONTEXT_V3`), и зафиксированный SHA исходного `R27_EVENT_JOIN_TAIL.lua` больше не совпал с SHA в сборщике R27.
