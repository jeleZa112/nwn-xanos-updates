# BGXAI 042B — устаревший указатель в загрузчике и безопасная проверка статуса

Дата фиксации: 2026-11-09.

## Факты

- Пользователь после подтверждённой установки 042B и неудачного запуска пункта 16 показал новое меню `BGXAI_UPDATE.cmd`. В начале указано `verified pinned script 9e7a6f9af0d6 (SHA256 OK)` — этот хеш соответствует исходному диспетчеру с ошибочным вызовом `--status`, а не исправлению.
- Актуальный GitHub branch `bg-eet-ai` уже содержит `BGXAI/fox_new/BOOTSTRAP_PIN.json` с `commit=a4566faa59d726f6fb59b035f139e5867f917a56`, `script_sha256=c25eb4610d02f133f28cbd8e023b547b4092e293e938dfbb02103117748c4c7b` и `script_size=21636`. Прямая проверка GitHub raw показывает актуальный pin.
- Локальный `BGXAI_UPDATE.cmd` не использует сохранённый head.txt как первичный источник. Он скачивает `BOOTSTRAP_PIN.json` по фиксированным адресам `raw.githubusercontent.com` и `cdn.jsdelivr.net`; если приходит старый валидный pin из сетевого кеша, затем корректно проверяет и запускает старую неизменяемую версию. Это вероятная причина наблюдаемого; точное место кеширования неизвестно.
- Данный вывод меню не свидетельствует о переустановке или повреждении 042B. Повторять установку через 15 нельзя.

## Немедленный workaround без изменения файлов

Использовать ранее загруженный проверенный Python-установщик напрямую **БЕЗ аргументов**. При отсутствии `--install` и `--uninstall` его `main()` вызывает только read-only `status(...)`:

```
cmd /k py -3 "C:\Games\BG_EET_FOXX_NEW\BGXAI_DEV\experimental_042b\BGXAI42_INSTALL.py"
```

Ожидается `SOURCE SHA256: ALL VERIFIED`, `BGX42 installed: True`, `Last BGXAI 042: True`, `STATUS: 042B INSTALLED; verified rollback backup: ...`. Важен именно `verified rollback backup`, поскольку неподтверждённая внешняя резервная копия блокирует безопасный откат. Команда не меняет игровой BCS и не запускает WeiDU. Если ошибка, сохранить вывод, не повторять установку или откат.
