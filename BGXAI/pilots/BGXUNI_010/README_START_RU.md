# BGXUN1 v0.1.0 — ПЕРВЫЙ ОТДЕЛЬНЫЙ ИГРОВОЙ ПИЛОТ

Дата: 2026-11-03. Для EET + SCS 35.21 + EEex + Insane. Статус: реальный BAF + отдельный TP2/CMD, **34 автономные группы проверок и 2000 повторяемых случайных сцен прошли на пользовательских IDS/snapshot**, но **реальная компиляция в Windows WeiDU и запуск внутри игры ещё НЕ подтверждены**. Это не полное воплощение всех 19 галочек и не готовое универсальное меню.

## Назначение

`BGXUN1` — новый сценарий `scripts/BGXUN1.BS`, выбираемый *вместо* старого сценария только на одном тестовом персонаже. Ни `BDDEFAI`, ни старые `BGXGRP`, `BGXTANK`, `BGXAI_UPDATE.cmd` и `BGXAI_LIVE.cmd` не изменяются. Остальные 5 персонажей могут оставаться на Advanced AI.

### Что уже совмещено в ОДНОМ BAF

1. Отдельная приоритетная очередь (сначала лечение/защита, затем опциональная магия, потом навыки, затем доступная оружейная атака).
2. Проверка текущей способности **по фактической заученной магии** `HaveSpell`, вооружению `IsWeaponRanged`, навыкам `STEALTH` / `TRAPS`, а не по имени Имоен/Ксара/киту до SCS-переобучения.
3. Отказ перебивать ручные приказы при занятой очереди (`ActionListEmpty`).
4. Лечение себя до 40% HP, только если враг не ближе 8 и есть реальный подготовленный жреческий слот; перезадержка 12 c.
5. Mirror Image при ранении ниже 70% HP и видимой угрозе на расстоянии 6–12; реальный слот, задержка 120 c; не кастует в мирной обстановке.
6. ОПЦИОНАЛЬНЫЕ Blindness и Magic Missile при ранении и видимой угрозе: только при отдельно включённых флагах BGXUCTRL=1 / BGXUDMG=1 и отсутствии стандартного отключения offensive. **По умолчанию выключено**.
7. Поиск ловушек/скрытность/песня по текущему BDAI_SKILL_MODE, с проверкой доступности. **Эти умения пока используют один выбранный классическим Advanced AI модальный режим**: независимое in-game меню всех 19 опций ещё впереди.
8. Дальний/ближний бой только уже выбранным оружием, только по видимому врагу в пределах 18/4 условных единиц; не выполняет автосмену оружия/автопогоню. Можно отдельно запретить дальний `BGXUNR=1` и ближний `BGXUNM=1` на LOCALS; в обычной игре эти служебные флаги ещё не имеют нового интерфейса.
9. Все логические действия кроме первого маркера требуют пустой очереди. Первый маркер однократный: `BGXUN1 V010 READY` над головой NPC при первом тике после назначения.

### Чего намеренно НЕТ в этом тесте

- Нет автореакции на ловушки с `RemoveTraps`, взломов, карманных краж, автоматического обхода пути и отступлений. Пока безопасность геометрии EEex не доказана, вор не должен лезть под агро.
- Нет сложного перехвата танками, смены оружия, расчёта иммунитетов, массовой магии и координации нескольких кастеров. Не обещаем работоспособности сложной тактики раньше полевого теста.
- Нет использования расходных предметов/жезлов, нет Нахала, ForceSpell, ReallyForceSpell, обхода подготовленных ячеек.
- Меню штатного Advanced AI **может не показывать те же опции**, когда выбран собственный BCS; тестом пока не подтверждено. Флаги BDAI используются только для чтения существующих локальных настроек; этот мод их не перезаписывает.

## Установка: первый раз

1. В игре сделай **отдельное сохранение**. Полностью закрой EET и InfinityLoader. Никаких WeiDU-операций при открытой игре.
2. Распакуй этот архив в **корень игры**, рядом с `chitin.key` (например `C:\Games\Baldur's Gate Trilogy (EE)\`). Должны появиться только `BGXUNI_SETUP.cmd`, папка `BGXUNI` и README. Не распаковывай Lua/JS из старых пакетов в override.
3. Запусти `BGXUNI_SETUP.cmd` (один новый CMD для этого отдельного пилота). Он создаёт лишь собственную копию WeiDU `setup-BGXUNI.exe` из имеющегося `setup-stratagems.exe` либо `setup-BGXAI.exe`. Не удаляет и не заменяет эти EXE.
4. Появится WeiDU. Если успешно: `scripts\BGXUN1.BS` и `override\BGXUN1.BCS`. Если ERROR/не появился BS — **не назначай** сценарий; приложи `setup-BGXUNI.DEBUG` и новый кусок `WeiDU.log`, без повторной установки вслепую.
5. Запусти игру через штатный InfinityLoader; открой *Персонаж → Сценарий* и выбери **BGXUN1** только одному спутнику (первый безопасный кандидат — Имоен с дальнобойным оружием, если её нынешний класс действительно это допускает). Остальные остаются на прежних скриптах.

## Три короткие проверки (на отдельном сохранении)

**A. Назначение.** Включи общий AI. Должна один раз появиться надпись `BGXUN1 V010 READY` у тестового персонажа. Если нет — проверить, что скрипт действительно выбран и AI включён; без иных предположений.

**B. Ручной приоритет.** В безопасном месте отдай персонажу движение в точку; скрипт не должен менять приказ. В небольшом бою на Insane с уже выбранным дальним оружием персонаж атакует ближайшего видимого врага на расстоянии до 18, не меняя оружие. Выключение Party AI должно прекращать инициативные действия. Этот тест не подтверждает отсутствие всех engine edge-cases.

**C. Возврат.** В карточке персонажа снова выбери старый Advanced AI. Игра должна снова работать как прежде. Если желаешь удалить только наш новый мод, закрой игру и выполни из корня `BGXUNI_SETUP.cmd /remove`; WeiDU должен удалить свои BGXUN1.BCS и BGXUN1.BS. Проверить `WeiDU.log`.

НЕ требуется новая отправка WeiDU.log или трёх старых игровых архивов: всё, что нужно для статического анализа, уже есть в Library. Новые DEBUG/LOG нужны только если текущая новая установка упадёт.

## Offline checks / Ограничения доказательств

Файл `tests/test_bgxuni.py` — отдельный облегчённый проверяющий парсер и эмуляция сценариев, не компилятор WeiDU. Исходные `ACTION.IDS`, `TRIGGER.IDS`, `SPELL.IDS`, `stats.ids`, `CLASS.IDS` проверены из сохранённого `BG_EET_AUDIT_01_MAGIC.zip`; их неизменяемые SHA256 и symbol snapshot включены в `tests/ids_snapshot.json` для повторного автономного прогона без 45k ресурсов. Запуск: Python 3 `python tests/test_bgxuni.py`. Итог текущего прогона: 34/34 PASS + 2000 seeded scenes.

Открытый риск: не подтверждены компиляция BAF с пользовательским WeiDU, нахождение BS в меню, режим BDAI UI при нестандартном сценарии и runtime-ошибки конкретных spell actions. При ошибке не лезть в старые сценарии, прислать только `setup-BGXUNI.DEBUG` или скрин ошибки.

Следующий релиз после приёмки: независимое игровое MENU на базе EEex, меню разрешений без зависимости от исходного класса и имени, отдельное включение функций и SHADOW-планировщик; безопасные действия вводить ступенчато с проверкой реальной игры.

## Исправление установщика v0.1.1 от 03.11.2026

РЕАЛЬНЫЙ Windows-тест пользователя нашёл баг установщика v0.1.0: WeiDU 25100 отвечает `unknown option '--tp2'`. При таком исходе мод **не установлен**, боевые BAF не изменены. Причина в параметре командной строки нашего CMD, а не в игре.

**Пользователю, у которого уже распакован первый ZIP:** полностью закрыть Baldur's Gate и InfinityLoader, прервать старый CMD через Ctrl+C, скачать **ТОЛЬКО новый `BGXUNI_SETUP.cmd` v0.1.1**, заменить файл с таким же именем в корне EET рядом с `chitin.key`, запустить новый CMD и нажать любую клавишу при подтверждении. Папку `BGXUNI` и боевые сценарии копировать снова **не требуется**.

Исправленный CMD автоматически и безопасно копирует `BGXUNI\setup-BGXUNI.tp2` в корень игры под именем `setup-BGXUNI.tp2` (стандарт WeiDU setup-name detection) и вызывает `setup-BGXUNI.exe --yes`, без `--tp2`. Если одноимённый TP2 в корне уже существует и не совпадает побайтно, установка останавливается, не перезаписывая чужой файл. После выполнения обязательно проверяет появление `scripts\BGXUN1.BS`. Команды удаления и переустановки используют поддерживаемые WeiDU 251 `--uninstall` и `--reinstall` без `--tp2`.

**Граница проверки:** синтаксис команд `--yes` / `--uninstall` / `--reinstall` подтверждён исходниками WeiDU, 7 новых статических проверок установщика пройдены, BAF тесты повторены. Настоящий повторный запуск WeiDU 25100 на Windows **пока не подтверждён**. Если следующая стадия выдаст COMPILE/ERROR, не повторять установку, прислать `setup-BGXUNI.DEBUG` или финальный экран.
