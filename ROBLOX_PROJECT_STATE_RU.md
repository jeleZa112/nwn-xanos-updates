# ROBLOX_BG_AI — текущее состояние
Обновлено: 2026-11-05. Источник истины: ветка `roblox-bg-monitor` репозитория `jeleZa112/nwn-xanos-updates`.

## Цель
Автоматическая игра и прокачка в Roblox Zombie Rush Survival на Windows, пока пользователь работает в других программах. Бот должен создавать одиночное лобби, самостоятельно добираться до основной позиции, устанавливать пушки, оборону и продолжать волны. Ни одна из этих автономных функций пока не подтверждена полностью.

## Среда
- Windows; Roblox в оконном режиме; Python 3.13.17 x64 установлен.
- Ollama установлена локально, пока не интегрирована и не требуется для текущего захвата.
- Python-библиотеки `windows-capture==2.0.1`, NumPy, OpenCV были установлены и применялись.
- Постоянный файл запуска на ПК: `ROBLOX_UPDATE.cmd`, который подтягивает `roblox_monitor.py` из отдельной ветки GitHub. Сохранять эту однофайловую схему; новые ZIP и патчи для пользователя нежелательны.
- NWN и BGXAI не изменять. Ветка Roblox отдельная.

## Реализовано и проверено
1. Windows Graphics Capture получает меняющиеся изображения Roblox, находящегося за браузером, пока игра НЕ свёрнута. Для полностью свёрнутого окна этот способ не подтверждён.
2. Режим мониторинга обрабатывает кадры в оперативной памяти без сохранения скриншотов. В версии 0.6.1: 120,1 с, 17 158 полученных, 240 обработанных кадров, 93 изменения сцены, 0 ошибок, 0 изображений на диске.
3. One-file updater успешно скачивал версии 0.6.1 и 0.8.0 с GitHub (подтверждено пользовательскими скриншотами).
4. В режиме LEARN записано 80 JPEG за прохождение до 16-й волны, архив TRAIN_001.zip (~10 МБ). Исходная демонстрация и разбор — `TRAINING_REVIEW_2026-11-05_RU.md`.
5. Версия `roblox_monitor.py` на момент данного сохранения — 0.9.2; она содержит меню мониторинга, LEARN и lobby helper.

## Не реализовано / не доказано
- Автономное управление Roblox в фоне без мыши и клавиатуры пользователя.
- Самостоятельное движение к площадке лобби.
- Надёжное распознавание всех кнопок, состояний, валюты, количества пушек, волн.
- Автоматическое создание лобби, подтверждённое успешным полным тестом.
- Автономное размещение пушек, обороны, отходы, прохождение 50 или 100 волн.

## Актуальный блокер: лобби
Пользователь ожидает, что **бот сам создаст лобби**, а не пользователь. По записи известна последовательность: площадка создания → карта «Пейзаж города» → 1 игрок → «Сложно» → «Создать» → ожидание обратного отсчёта.
В тесте `lobby.log` за 16:39 обнаружение меню мелькнуло один раз, но режим `armed=False`, поэтому действий не было.
В тесте за 16:44 консоль показывала `armed=False`, поскольку был введён `yes` в нижнем регистре. Позднее проверка входа исправлена на `.upper() == "YES"`, но **повторная проверка с `armed=True` не предъявлена**. Не выдавать это за успешное создание.
На последнем скриншоте меню уже открыто, выделено **4 игрока**, а требуется 1; бот не нажимал, поскольку был выключен. Координаты распознавания взяты из другой пропорции кадра; они могут быть неверными. Включённые нажатия пока только foreground-only и могут перемещать мышь — это не решение задачи работы в фоне.
