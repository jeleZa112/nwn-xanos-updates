## Что делает автоисправление в один запуск
- Встроено в тот же CMD и нормальную последовательность V101/V102→V120→V121; отдельный пользовательский CMD/PowerShell не нужен.
- Безопасно сохраняет один *неизменяемый* исторический снимок точного исходного V120 ZIP (129 записей, SHA256 `08a9d5da367404b33bc982871627e8c3e1179c7a8ec8808bab0a75bea5755015`) в папку кеша **вне игры**, не выгружая личные EXE-фрагменты в GitHub.
- Через GitHub RAW на точном commit `bf7a30b651d427e38af850d7dc6c06ade7a625ec` скачивает/кеширует исходник бота (SHA256 `4dfb5d57f3bfddaca5a31884c5a91ea2a8380aa78ace28047409ebe9dfb531b3`) и 14 эталонных модулей в ZIP (SHA256 `7622bfdec1f77e44a307c0cda3e73c86d143a024b87d4ad0f359897c89a74124`); **запуск только после SHA-контроля**.
- Если известный исходник повреждён или пропал — восстанавливает точную эталонную копию, сохраняет изменённую в карантине, автоматически повторяет исследовательский комплекс один раз.
- При подмене V120 источника, несовпадении SHA, неизвестной ошибке, конфликте путей/ссылок — **HOLD**, не выдумывает исправление и не меняет игру. При отсутствии сети допускается только целый закреплённый кеш.
- Один результат `60_V121_AUTOFIX_SOURCE_ONLY.json` в существующем `SEND_TO_CHATGPT_BG_EET_RU.zip`; всё находится вне корня игры.
- **Проверки 735/735** относятся к SOURCE/MODEL/STATIC и старому точно закреплённому архиву, не являются доказательством работы хуков в игре или свежего состояния Windows.

## Главный незавершённый игровой результат
**Идентификатор выбранного оружия при каждом конкретном промахе и его точная связь с отображаемой строкой боевого журнала не подтверждены.** Native same-Hit наблюдатель не установлен, GAMEPLAY PASS=0. Дальнейший шаг — native runtime пилот только при exact ABI, SHA текущего EEex, безопасных enter/annotate/exit, внешнем backup и отдельном явном разрешении пользователя. Нельзя подбирать оружие по времени, последнему атакующему или глобальной переменной.

## Правило автономной работы
Для каждого нового направления сначала проектировать полный пакет проверок и зависимостей, выполнять безопасные шаги подряд в одном цикле, автоматически восстанавливать только известные точные исходники и повторять максимум один раз. Не требовать от пользователя многократных запусков, «+» или дополнительных скриптов ради одной функции. Отделять CODE/SOURCE PASS, CI PASS, WINDOWS PASS и GAMEPLAY PASS.
