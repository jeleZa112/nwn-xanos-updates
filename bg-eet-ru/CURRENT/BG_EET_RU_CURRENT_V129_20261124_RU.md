# BG_EET_RU — актуальная точка V129 (SOURCE, не игровой релиз)

Дата: 24 ноября 2026. **Содержательный результат:** пересмотрена неверная предпосылка native-перехвата из-за точного анализа оригинального `CGameSprite::Hit()` в пользовательской игре.

## Что подтверждено в игре
- Единственный живой V126 UI-захват `SEND_TO_CHATGPT_BG_EET_RU(20261124-164826).zip` = 72 отображённые строки, 11 результатов d20 (5 попаданий, 6 промахов). `capture_exit_code=0`, новых игровых записей при захвате 0.
- `UI.MENU` с пассивным наблюдателем V126 **установлен** и сохранил текст без изменения; текущий пользовательский CMD обновлятор — **V128**. Не выпускать V129 CMD ради версии, не повторять бой/14 аудитов.
- V108 ранее выводил RESREF AROW01/BOW05, но без attacker/target/sequence/UI-row event key. Не смешивать события разных сессий.

## Новое статическое открытие по реальному двоичному коду
- `19_V68_COMBAT_CODE/functions/0039DA50_0039E9DC.bin`, SHA256 `19c1d11b7ac41d261d22b19506b3570427e356544e48f2e2c622c1efdb74cc79`.
- Две ветви `je` в `0x39E699` и `0x39E6A4` ведут в `0x39E7A0`, где выставляется `ESI=1, EAX=1`. Далее `0x39E7B3 jne 0x39E855` **перескакивает** вызов `CMessageHandler::AddMessage()` в `0x39E84B`.
- Точные байты, адреса целей пяти переходов и SHA проверены независимо по загруженному ZIP. Это доказывает, что **тот конкретный callsite не универсальный источник каждого прохода `Hit()`**. Что означают значения `0x182` и `0x502` и насколько часто их ветви выполняются в игре, ещё не определено; не выдавать их за конкретные игровые состояния.
- Доклад в `bg-eet-ru/native-correlation/V129_NATIVE_DISPATCH_FINDING_RU.md`.
- Python SHA-pinned verifier: `conditional_hit_message_v129.py`. Pure Lua модель: `BG_EET_RU_V129_ATTEMPT_LEDGER.lua` — **учитывает попытку даже без сообщения; отсутствие сообщения НЕ равно промах**. Требует доказанных native thread/frame/item/actor/target. Не имеет JIT/EEex install.
- PR #99 merged `7504bb5dac9d751785930d284b9c9b83b5c6b655`; GitHub Actions `45443496782` Windows PASS, Ubuntu PASS, включая реальный Lua 5.4 и негативные тесты 16 байтовых якорей/5 переходов, прежний V128 onefile regression. **CI не означает игру**.

## Строго следующий этап, без переключений
Построить защищённый native **per-Hit entry + exit** observer, который регистрирует каждую попытку, и отдельно optional `CMessage`. Исходы HIT/MISS из одного лишь отсутствия сообщения не выводить. Перед игрой требуется проверить Win64 ABI/сохранение регистров/XMM, точность `CItem` на входе, owner существующего EEex JIT и rollback, SEH/unwind, уникальный ключ до UI `combatLog`. Любая новая игра-изменяющая установка — **новое дословное разрешение и внешний backup**. Работающие BGXAI, BG Voice RU, сейвы, V108 и UI.MENU V126 не менять.

Текущий игровой результат: **UI_CAPTURE_PASS / NATIVE_MESSAGE_COVERAGE_BUG_IDENTIFIED / NATIVE_RUNTIME_INSTALL_HOLD / WEAPON_ON_MISS_NOT_ENABLED**.
