# BG_EET_RU V131 — один обновлятор, новый read-only PE unwind gate

**Цель:** проверить на исходном установленном `Baldur.exe` реальные Windows `.pdata/.xdata` таблицы раскрутки стека для потенциального native-перехвата `CGameSprite::Hit()`, без повторного боя и без нового игрового мода.

## Основание

В пользовательской сборке исходная функция `Hit()` SHA256 `19c1d11b7ac41d261d22b19506b3570427e356544e48f2e2c622c1efdb74cc79` начинается с пролога с `sub rsp,0x80` в `0x39DA68`. Предлагаемая новая точка `0x39DA6F`: две MOV (6 байт), после выделения стека, перед RIP-LEA `0x39DA75` и EEex FirstCall `0x39DA86`. **Пока это лишь кандидат, не установленный перехват.**

## Что сделано
- В единственном `BG_EET_RU_UPDATE.cmd` добавлен пункт меню **6 — unwind**. Не запускает предыдущие 14 проверок и не требует запуска Baldur.
- Сам обновлятор по неизменяемому commit `ea012654ce6323b265ba1a91c1b71d9e0a866ad8` и SHA256 `683243951008f19495a978134d8f44732aa4d132472d08ead2c480e9c86c2f70` скачивает проверенный `pe_unwind_entry_gate_v130.py` в внешний кеш `Documents\BG_EET_RU\.BG_EET_RU_AUTOFIX_CACHE\V130_RO.py`.
- Для настоящей `dataclass` внутри PE-парсера модуль регистрируется в `sys.modules` перед выполнением; частичной загрузки кода/изменённого SHA нет.
- Проверяет только `C:\Games\BG_EET_FOXX_NEW\Baldur.exe`, без записи в него, без обращения к запущенному процессу, без JIT/EEex хуков. Точная SHA исходного EXE `fc821a4806a0305b84fd85f1aad2bd472c8db642ed34b4494ae62351cae1c580` обязательна.
- Результат сохраняется в **существующий один** `SEND_TO_CHATGPT_BG_EET_RU.zip`: запись `64_V130_PE_UNWIND.json`. Если таблица повреждена/неточная, `HOLD` с причиной, игра не затронута.
- Никакие `UI.MENU`, `V108`, `BGXAI`, `BG Voice RU`, TLK, сейвы не изменяются.
- Даже `POST_PROLOGUE_CANDIDATE_STATIC_PASS_RUNTIME_HOLD` не означает разрешение к установке native hook: остаются Win64 ABI/XMM, EEex JIT owner, SEH/unwind при исключениях, безопасный rollback и связь с реальной строкой `combatLog`.
