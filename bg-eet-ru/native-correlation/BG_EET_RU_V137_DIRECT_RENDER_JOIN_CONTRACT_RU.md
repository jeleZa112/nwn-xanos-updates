# BG_EET_RU V137 — прямое сопряжение атаки с видимой строкой (SOURCE ONLY)

## Реальная база (проверена по архиву пользователя от 25.11.2026)

- Запущен один `BG_EET_RU_UPDATE.cmd` **v136**, пункт `9=JIT-RO`; файл `67_V136_LIVE_JIT_TARGET_RO.json` подтверждает исполняемый `FirstCall` переход и оригинальные 4 точки `Hit()`, **но не владельца EEex, callback ABI или результат атаки**. Никаких игровых изменений V136 не делает.
- Наблюдатель V126 сохранил **72 отображённые строки**, в том числе `ПОПАДАНИЕ` и `ПРОМАХ`, но без внутреннего токена попытки. V108 дал **2** независимых события с полями `weapon_resref=AROW01` и `launcher_resref=BOW05`, `ammo=UNVERIFIED`. **Их нельзя склеивать по персонажу или близости во времени**.
- Оригинальные байты `Hit()` подтверждают `JNE` в `0x39E7B3`, прыгающий на `0x39E855` мимо вызова сообщения `0x39E84B`; этот вызов **не является универсальным источником всех атак**. Логика V137 не требует его даже для промаха.
- Установленный в EEex `Hit()-FirstCall` уже обрабатывается upstream и сохраняет `r15` (CItem) и `rsi` (ability) в **общую** память. Повторно патчить эту точку или считать глобальные переменные ключом конкретной атаки нельзя.

## Что уже реализовано в V137

`v137_direct_render_join_ro.py` — действующий **локальный чистый валидатор**, принимающий события с ожидаемым строгим происхождением. Он позволяет явно доказать логическую однозначность `one Hit invocation → one visible ATTACK_ROLL row` **в синтетической модели**, без условного `AddMessage`:

1. Идентичность атаки: `(session, thread_id, frame_id, attack_seq, attacker_id, target_id)`; вход `0x39DA6F`, выход `0x39E99B`, исходный `raw_return` без догадок о значении 0/1.
2. Снимок оружия: `weapon_resref`, `launcher_resref`, `ammo_resref` с фактическими значениями и `item_snapshot_id`, созданный **внутри той же нативной попытки**. Пустые необязательные поля не превращаются в выдуманные значения.
3. Прямой `direct_render_token`, порождённый будущим безопасным мостом и дошедший до рендеринга **именно данной строки**, а не сгенерированный парсером по соседним строкам, actor name, timestamp, указателю на CMessage или условному callsite.
4. Доказательные поля захвата должны быть строго `True`; подмена `1`, строки `'true'`, неполные записи, повторные токены и неоднозначные ряды → `HOLD`.
5. Соответствие результата `HIT/MISS` отдельно калибруется **в реально наблюдаемом бою**. `raw_return=0/1` не классифицирует его автоматически.
6. Даже при положительном мок-тесте вердикт **`SOURCE_ONLY_CANDIDATE`** с `gameplay_verified=false`, `live_identity_verified=false`, `native_abi_verified=false` — чистый валидатор не может заверить источник входных флагов.

Реальный исходный архив возвращает `REAL_USER_CAPTURE_DIRECT_JOIN_HOLD` — подтверждённых per-attempt токенов в нём пока нет. Код не устанавливает хуков, не обращается к процессу, не меняет игру, BGXAI или BG Voice RU. Результат записывается **только в отдельный файл исследования** на стороне разработчика, а не в игровой архив.

## Без чего нельзя установить native мост

- Проверить владельца существующего `FirstCall` JIT и отсутствие коллизий с другими хуками для запланированных новых точек. `MEM_PRIVATE + PAGE_EXECUTE_READWRITE` не равняется доказательству EEex-ownership.
- Получить реальный callback Win64 ABI-контракт: сохранность GPR, XMM, RFLAGS, shadow space, 16-байтное выравнивание, stack unwind и SEH; доказать `RtlAddFunctionTable` **для конкретного адреса**, а не наличие API в исходниках.
- До очистки стека синхронно скопировать **значения RESREF**, а не хранить CItem/userdata-указатели. Хранить стек вложенных попыток по native thread + frame + monotonic seq и инвалидировать его при исключениях/разрывах.
- Найти стабильный, действительно вызываемый для ПОПАДАНИЯ и ПРОМАХА рендеринг `ATTACK_ROLL` в актуальном UI, безопасно доставить до него уникальный токен. Проверить сценарии без текстовой строки, несколько сообщений, автоочистку журнала, порядок отображения и игру на паузе. UI-текст нельзя менять до полной корреляции.
- Раздельно калибровать `raw_return`, hit/miss, тип атаки/оружие/снаряд, показать точную одну строку для конкретного события в живой игре.
- При любой недостоверности `HOLD` и отсутствие изменений; перед установкой — SHA-проверка живой сборки, внешняя резервная копия, отдельное **типизированное** подтверждение пользователя и откат только последнего компонента; один привычный обновлятор и один ZIP.
