# BG_EET_RU — единый исследовательский комплекс native Hit, V2

**SOURCE/MODEL PASS; LIVE EEex/JIT HOLD; GAMEPLAY NOT TESTED.** Пакет не является установщиком и **не содержит исполняемых игровых хуков**. Единственный пользовательский обновлятор по-прежнему `BG_EET_RU_UPDATE.cmd` (рабочий релиз V121).

## Цель

Получить RESREF фактически использованного оружия и номер способности **в том же вызове `CGameSprite::Hit()`**, где формируется сообщение о броске, включая промахи. Не связывать события по времени, последнему атакующему, первому видимому предмету или позиции в очереди.

## Выявленные и исправленные ошибки

1. **RIP-relative LEA — запрещена.** На `0x39DA75` исполняется `lea rdx,[rip+0x24c9a1]`. EEex `EEex_HookBeforeRestoreInternal()` вставляет исходные байты в новый JIT-трамплин без пересчёта RIP. Поэтому исходный вариант мог адресовать неправильную память. Исправленная входная точка `0x39DA68` — `sub rsp,0x80` (7 байт); до перезаписи RCX/RDX/R8/R9.
2. **Три точки — два различных API EEex.** Для `0x39DA68` допустим кандидат `EEex_HookBeforeRestoreWithLabels` (перенос обычной инструкции). Для исходного `CALL rel32` в `0x39E84B` и `0x39E996` нужен `EEex_HookBeforeCallWithLabels`, который вычисляет реальный адрес callee. Raw-copy здесь столь же опасен, как и для LEA. Это только проверенная **стратегия**, не JIT-код.
3. **Не трогать upstream-хук.** `0x39DA86` принадлежит уже установленному EEex `FirstCall`; повторная установка или подмена не разрешена. Одного opcode `E9` недостаточно, чтобы удостоверить владельца текущего JIT-трамплина.
4. **Непроверенный выход больше не вызывает Lua error.** `Exit(nil)`, NaN, строка, неправильная память `EEex_ReadU8` и ошибка `EEex_Label` дают безопасное отсутствие действия или `HOLD`.
5. **Конфликт одинаковых идентификаторов кадров** держит frame poisoned до завершения всех конкурирующих вызовов, не снимает блокировку после первого выхода. Защита от переполнения переводит модель в `session HOLD` и освобождает Lua-кеш.

## Воспроизводимая проверка в чистой папке

Нужен **ранее полученный пользовательский архив** `SEND_TO_CHATGPT_BG_EET_RU(20261124-031007).zip` SHA256 `08a9d5da367404b33bc982871627e8c3e1179c7a8ec8808bab0a75bea5755015`. Он не встроен в исследовательский архив и не выгружается в публичный GitHub.

Внутри пакета все исходные Python/Lua модули и `trusted_sources.zip`. Разработчик может запустить:

```bash
python one_pass_native_pilot_check.py /path/to/SEND_TO_CHATGPT_BG_EET_RU.zip --trusted trusted_sources.zip --out ONE_PASS_NATIVE_PILOT_REPORT.json
```

Комплекс делает 735 прежних SOURCE/MODEL проверок, 39 статических ворот исправленного Lua, 18 проверок маршрута машинных инструкций, 45 проверок исполнения Lua-контекста, 46 проверок Lua-мока памяти и 7+6 adversarial unittest-методов. **Это НЕ 895 игровых событий и НЕ GamePlay PASS.** Один сломанный независимый этап не скрывает результат остальных.

Для намеренно повреждённого входного ZIP / исходника / `trusted_sources.zip` должен возвращать `SOURCE_HOLD`, при этом исходная игра не меняется.

## Что пока НЕ реализовано

Нет проверенного настоящего Win64 JIT с сохранением ABI, XMM, unwind/SEH, подтверждённой идентичности патчей в живом процессе, доказанной маркировки `CMessage` и реальной строки `combatLog` при промахе. Source-only Lua `Start()` **всегда отказывает** в установке даже при принудительном выставлении разрешающих флагов. Никаких игровых модификаций до отдельного явного разрешения и guarded backup/rollback.

**Следующий осмысленный рубеж:** инженерно законченный guarded runtime observer с единым игровым тестом, а не серия индивидуальных CMD/ZIP по одной функции.
