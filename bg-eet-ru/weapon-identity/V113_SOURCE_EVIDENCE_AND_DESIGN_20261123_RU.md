# BG_EET_RU — V113: исследование безопасной связи броска, оружия и строки журнала

**Срез:** 23 ноября 2026. **Стадия:** SOURCE + OFFLINE SYNTHETIC PASS, никакой установки / Windows LIVE V113. **Игра изменена:** нет.

## Подтверждённые исходные данные из установленной EET

- Windows V112: `V112_ITEM_NAMES_AND_UI_SOURCE_CONFIRMED_JOIN_HOLD`, отчёт 127 файлов в проверенном ZIP, CRC PASS, `game_files_written=0`.
- `V108` содержит две реальные записи обработчика урона `weapon_resref=AROW01` + `launcher_resref=BOW05`; ранее отдельно подтверждён `SW1H04`.

## Выводы из источников upstream EEex

1. **Прямое объяснение автора** (Bubb13, ответ 14.06.2025 в issue #86): `EEex_Sprite_AddAlterBaseWeaponDamageListener` вызывается *после создания базового эффекта урона `op12` при попадании оружием*. Поля контекста включают `ability`, `attacker`, `effect`, `isCritical`, `isLeftHand`, `launcher`, `target`, `weapon`. Этот обработчик **не охватывает промахи** и не предоставляет документированный ID строки журнала. https://github.com/Bubb13/EEex/issues/86
2. `EEex_Action_LuaHook_OnAfterSpriteStartedAction` передаёт `(sprite, action)` при начале действия. Это **не каждый бросок атаки** при APR и не готовый ключ для точной привязки к `combatLog`. https://github.com/Bubb13/EEex/blob/a6d21abe44e20509f5d0259ccc6c7e7f9d12b285/EEex/copy/EEex_scripts/EEex_Action.lua
3. `EEex_Menu_AddBeforeListRendersItemListener` работает при отрисовке UI и самим автором помечен `DON'T USE` из-за сильных задержек при включённом FPS uncap. Использовать его как журнал событий недопустимо. https://github.com/Bubb13/EEex/blob/a6d21abe44e20509f5d0259ccc6c7e7f9d12b285/EEex/copy/EEex_scripts/EEex_Menu.lua
4. `EEex_Sprite_AddBlockWeaponHitListener` предназначен для **блокирования эффекта попадания/урона**, может менять бой; не использовать как безобидный наблюдатель. https://github.com/Bubb13/EEex/blob/a6d21abe44e20509f5d0259ccc6c7e7f9d12b285/EEex/copy/EEex_scripts/EEex_Sprite.lua
5. В `EEex_Sprite_Patch.lua` присутствует метка `Hook-CGameSprite::Hit()-FormatRollCall` и внутренний `CGameSprite_Hit_Roll`; это **потенциальная точка будущего исследования**, но не готовый Lua API с данными оружия и строки и **не разрешение патчить бинарник**. https://github.com/Bubb13/EEex/blob/a6d21abe44e20509f5d0259ccc6c7e7f9d12b285/EEex/copy/EEex_scripts/EEex_Sprite_Patch.lua
6. Старый форумный пример 2020 года о перехвате печати лога в `EEex_Init.c` носит исторический характер и требует изменения низкоуровневого вызова движка. Его нельзя копировать в x64 игру пользователя. https://forums.beamdog.com/discussion/71798/mod-eeex-v1-0-0/p29

## Проверенный алгоритм безопасности V113

Артефакт: `V113_JOIN_SAFETY_GATE_SOURCE_ONLY.py`. Проведено **16 синтетических тестов (PASS)** и проверка последнего реального отчёта V112 (**HOLD**). На момент V113 не существует доказанного `roll_instance_id` и неизменного `journal_row_id` одновременно в событии атаки и сообщении журнала.

Для добавления подписи требуются одновременно: идентификатор конкретного броска, сформированный движком в момент создания сообщения; неизменный ID строки, а **не UI `rowNumber`**; совпадение атакующего, цели и исхода; уникальность обеих сторон связи; валидный CItem RESREF и понятная политика идентификации предмета. Для промахов необходим источник, срабатывающий также при промахе — одного V108 недостаточно. При любом нарушении возвращать исходную строку журнала, не подставляя название оружия.

Тесты отбрасывают: совпадение только по атакующему; совпадение по времени/порядку; потерю или повторение токена; перемену оружия; две строки на один бросок; один ID строки на разные броски; несоответствие цели; неподтверждённое оружие; и попытку подписать промах данными hit-only callback.

## Следующее осмысленное действие

Пока **не выпускать очередной Windows-обновлятор**, который лишь снова вернёт HOLD. Сначала нужно получить документированную и безопасную точку для наблюдения за отдельным броском (включая промах) и сопутствующим текстовым событием журнала; доказать, что обе стороны связаны устойчивым ID. Только затем подготовить **SOURCE ONLY + CI**, после этого guarded install с точной проверкой SHA, внешней резервной копией, подтверждением пользователя и откатом. **V101 FULL/BRIEF, V108, V111/V112, BGXAI, BG Voice RU, сохранения и UI оставлять неизменными**.

Никакого дополнительного боя или сканирования игры от пользователя сейчас не требуется. При невозможности получить уникальную связь сохранять корректные русские подписи *в справочнике предметов*, но не добавлять ошибочные названия в строки промахов.
