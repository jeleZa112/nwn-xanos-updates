# BG_EET_RU — правило одного комплексного прогона (постоянно)

**Решение пользователя, 24.11.2026.** Вместо десятков запусков по одному символу, адресу, полю и функции: один автономный диагностический проход для всего заранее сформулированного направления, выполняемый существующим `BG_EET_RU_UPDATE.cmd`. Один архив `SEND_TO_CHATGPT_BG_EET_RU.zip`. Не просить пользователя подтверждать каждую READ-ONLY ступень или писать «+».

## Алгоритм при КАЖДОЙ смене технического направления

1. Сначала восстановить актуальную рабочую версию, исходный ZIP, проверенные исходники и блокеры. Не повторять успешные тесты.
2. До следующего обращения к пользователю сформулировать **всю цепочку зависимостей**, все доступные источники, адреса и возможные альтернативные гипотезы. Для каждой ветви заранее определить необходимые поля и объём данных, чтобы одной выборки хватало для самостоятельного последующего анализа.
3. Выполнять локальный статический анализ, верификацию контрольных сумм, тестирование кода и проверки CI самостоятельно. Новые источники искать в текущем репозитории/архиве до просьбы о файлах.
4. Если нужны данные Windows, встроить **один исчерпывающий ограниченный READ-ONLY сборщик** в канонический обновлятор, автоматически проходящий независимые стадии даже при ошибке одной из них. Не добавлять отдельные CMD/PowerShell/ZIP.
5. Коллектор выводит статусы каждого шага (`PASS`, `HOLD`, `MISSING_SOURCE`, `NOT_TESTED`), версии, SHA256, проверяемую цепочку фактов, ограниченные технические выборки и перечень **оставшихся только действительно игровых проверок**. Все исходные файлы и отчёты остаются локальными/приватными, не выгружаются в публичный GitHub.
6. При PASS безопасного этапа автоматически переходить к остальным безопасным пунктам **в том же запуске**. Не обращаться к человеку с просьбой повторить CMD при каждом новом выводе.
7. Изменения в игре: только после отдельного явного разрешения, точного SHA, внешнего backup и отката. Сохранения, BGXAI, BG Voice RU, игровую механику и утверждённые переводы не трогать.
8. Пользователя привлекать только к **одному осмысленному игровому тесту** после того, как весь технический пакет готов, либо когда без единственного комплексного локального сбора принципиально невозможно двигаться. В таком случае честно объяснить, почему нужна ровно одна проверка.

## Текущая реализация (V120)

- Опубликован один SHA-закреплённый READ-ONLY сборщик внутри уже существующего CMD.
- Собирает в один ZIP: проверку установленного PE64 и EEex loader, виртуальную таблицу сообщений, вызовы отправки, ограниченные машинные фрагменты **только в приватный ZIP**, сигналы UI/EEex/Lua и прежние отчёты.
- Не утверждать, что от этого автоматически появилась проверенная связь `атака → оружие → строка журнала`. Такое соответствие пока HOLD. Сам коллектор не устанавливает хуки и не меняет игру.
- **Метрика успеха**: рабочий русский боевой журнал без ложного сопоставления оружия, а не номер версии или количество отчётов.

При открытии новой ветки/чата начинать с этого правила и действующего handoff.

## Постоянное усиление 24.11 — массовые тесты без участия пользователя

По повторному прямому указанию пользователя **НЕ ДРОБИТЬ ПРОВЕРКИ**. Перед каждым направлением заранее составлять всю цепочку зависимости и максимальную матрицу SOURCE/LUA/Win64/EEex/fail-closed/AutoFix/rollback. За **ОДИН** автоматический проход выполнять весь доступный набор, не просить «+», отдельных CMD и файлов после каждой найденной ошибки. После PASS сразу продолжать безопасные этапы; при сбое отдельного этапа сохранять HOLD и продолжать независимые. Только **известные** ошибки проверочных модулей восстанавливать автоматически из SHA-pinned копии с карантином и одним ограниченным повтором; повреждённый V120 ZIP, EEex/EXE и неизвестную ABI не «чинить» автоматически.

Поведение проверено отдельным self-contained **исследовательским** пакетом `BG_EET_RU_ONE_BIG_BATCH_AUTONOMOUS_RO_20261124.zip` SHA256 `9a577a9890dcbd289e33107fd9d83c28d0d6d1d5fe019b78aaf3bfa13df8692b` (не игровой установщик, без приватного EXE): единственный `one_big_batch_ro.py` прошёл **9/9** автономных стадий из чистой распакованной папки с точным V120 ZIP. Включены 735 SOURCE, 33 native source, 43 Lua, 24 mock-memory, 29 AutoFix tests (в том числе 256 и 56 намеренных неисправностей), 7 adversarial, контролируемая порча ZIP и 6 site SHA-gates, сверка исходных SHA до/после. Категории тестов частично пересекаются — не суммировать как количество игровых событий. Негативный прогон с подменённым ZIP доказал **3 HOLD и 6 независимых PASS**, общий exit code 2, входные файлы не изменялись.

**Внеигровые SOURCE/MOCK PASS не подтверждают runtime GAMEPLAY PASS**; native Hit инсталляция остаётся HOLD, действующий V121 не менялся. Пользователь не обязан запускать исследовательские скрипты. Один пользовательский `BG_EET_RU_UPDATE.cmd` и один `SEND_TO_CHATGPT_BG_EET_RU.zip`; изменение игры только по отдельному явному одобрению, точному SHA, внешнему backup и rollback.
