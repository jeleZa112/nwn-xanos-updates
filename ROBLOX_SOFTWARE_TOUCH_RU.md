# ROBLOX_BG_AI V2.0.1 — программный ввод без Arduino

## Что изменено

Вместо SendInput и mouse_event, которые не меняли выбор «4 игрока» на «1 игрока», реализован другой системный механизм Windows: **InitializeTouchInjection / InjectTouchInput**. Он имитирует касание пальцем на экране. Настоящий сенсорный экран для вызова этого API не требуется; однако совместимость конкретной игры с синтетическим сенсорным вводом пока НЕ подтверждена.

**Аппаратную плату покупать не нужно.** COM-порт, Arduino и pyserial для TOUCH не используются. Не включается режим UI Navigation и не отправляется обратный слеш, поэтому старый сбой WASD не должен повторяться.

## Порядок работы

Единственный \`ROBLOX_UPDATE.cmd\` обновляет \`roblox_monitor.py\` из ветки \`roblox-bg-monitor\`. Далее в меню выбрать \`3\` (лобби), \`2\` (включить действия), \`yes\`. Когда Roblox активен и на экране открыто меню создания матча, бот:

1. Проверяет выбранную карту «Пейзаж города».
2. Отправляет сенсорное касание кнопки «1 игрок».
3. Считывает несколько новых кадров и подтверждает, изменилась ли зелёная рамка.
4. Выбирает «Сложно» только после подтверждения числа игроков.
5. «Создать» — только если одновременно подтверждены все три настройки.

На каждый параметр в TOUCH — максимум **одна** автоматическая попытка. Если игра игнорирует касание, бот не повторяет одно и то же действие бесконечно. Пишет в \`Документы\RobloxBGDiagnostics\LOBBY\lobby.log\`:

- \`INPUT_BACKEND=TOUCH\` — используется программное касание.
- \`TOUCH_API_AVAILABLE\` — Windows поддерживает необходимые функции; это НЕ означает, что Roblox обработает касание.
- \`TOUCH_SENT screen=(...) client=(...) status=UNVERIFIED\` — Windows приняла событие; ожидается игровая проверка.
- \`TOUCH_INIT_FAILED\`, \`TOUCH_DOWN_FAILED\`, \`TOUCH_UP_FAILED\` + \`WinError\` — настоящая ошибка вызова Windows.
- \`STEP_VERIFIED\` — изменение подтверждено по кадрам Roblox.
- \`INPUT_UNCONFIRMED step=one backend=TOUCH\` — игра не подтвердила выбор. Новый повторный запуск с тем же вводом без изменения кода бессмыслен.

Во время касания системная мышь не двигается. Но режим по-прежнему требует **активное окно Roblox**: одновременная независимая работа в фоне и полностью автономная игра не реализованы.

## Безопасность

Никаких HID-драйверов и программ для обхода защиты Roblox не устанавливаем. Не переключаем UI Navigation, не трогаем WASD. При ошибке API прекращаем ввод. Программное касание может быть отвергнуто Roblox; нет гарантии, что этот способ сработает.

## Что было проверено без ноутбука пользователя

- Сверены типы и порядок полей структур Windows \`POINTER_INFO\` и \`POINTER_TOUCH_INFO\` с документацией Microsoft.
- На 64-битной платформе проверены размеры ctypes-структур: 96 и 144 байта.
- Использованы официальные значения флагов \`POINTER_FLAG_DOWN/UP/INRANGE/INCONTACT\`.
- **Не проверено:** реальное исполнение кода на Windows, реакция Roblox на касание, создание матча и фоновые действия.

Если TOUCH не будет принят Roblox, не возвращаться к перебору прежних SendInput и MouseEvent. Следующий этап требует отдельного исследования интерфейса конкретной игры или управляемого альтернативного ввода, а не обещаний.
