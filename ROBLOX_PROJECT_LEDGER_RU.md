# ROBLOX_BG_AI — постоянный журнал решений
Обновлено: 2026-11-05.

## Принципы проекта
- Пользователь хочет **один постоянный обновлятор `ROBLOX_UPDATE.cmd`**, без повторных архивов с патчами.
- Все версии размещать в ветке `roblox-bg-monitor` GitHub `jeleZa112/nwn-xanos-updates`. Не вмешиваться в ветку `main` NWN и `bg-eet-ai` BGXAI.
- Требуется полная автоматизация (в том числе вход в матч), с перспективой работы в фоне на том же ПК, пока пользователь работает. Безопасность при ошибках распознавания: не нажимать вслепую, логировать решения.
- Нормальное наблюдение обрабатывает кадры в RAM без накопления картинок; обучающий режим LEARN сохраняет сжатые редкие кадры в небольшие ZIP. Стараться минимизировать нагрузку и объём.
- Не обещать способность работать с полностью свёрнутым окном или независимо управлять клавиатурой, пока это не подтверждено.

## Тактика, подтверждённая пользователем
1. Первое действие — копить на первую пушку.
2. Основная позиция — место, где пользователь стоял на поднятом углу и призывал пушки в демонстрации. Ставить там турели по мере накопления.
3. При видимом приближении зомби — возводить защиту на направлениях подхода к основной позиции.
4. Когда места в центре не остаётся — кратко выходить чуть дальше, ставить новые пушки и возвращаться.
5. Не трактовать поздний выход из позиции и гибель на 16-й волне как плохую тактику: **пользователь намеренно вышел, чтобы проиграть и завершить тест**.
6. Ускоренный режим использовался в демонстрации; пока нет данных для гарантированной стратегии до 50/100 волн.

## Риски / нерешённые задачи
- Непроверенные координаты автоматических нажатий, отсутствие достоверного распознавания выбора 1 игрока, и расхождение размера кадра/окна.
- Помощник лобби использует движения мыши и требует Roblox в фокусе: не автономное управление в фоне.
- Если Roblox выкидывает из лобби по таймеру, следующий тест должен быть коротким, с понятным журналом.
- Обработчик обучения не гарантирует фиксацию быстрых действий между снимками.
